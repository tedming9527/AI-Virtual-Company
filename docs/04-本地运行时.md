# 04 · 本地运行时（L3）

> Agent 中介层，自建直连（内部无 MCP 协议层），是「用户与大模型之间的中介」。

## 1. 职责

- **初始化**：读极简 bootstrap.json → 扫描目录规约自动发现 → 发现预置 mcp/（安装/注册另验） → 同步 presets → 定位已配置个人记忆（实际加载另验）；
- **分层注入**：把上下文按层级喂给大模型（防上下文爆炸）；
- **编排与回传**：本地演化（记忆/技能/等级），日志与晋升回传中央；
- **规约校验**：`doctor` 校验个人目录强制规约；
- **本地 git 分支自成体系**：本地可独立迭代，只有转正才走中央。

## 2. 初始化流程（定稿）

```
① 一次性引导：把仓库地址交给 Agent（只给这一次）
② Agent 读取/clone 仓库
③ 读仓库根 bootstrap.json（极简清单）
④ 扫描目录规约自动发现包（skill / knowledge / framework / role）
⑤ 按清单发现预置 MCP；客户端安装、注册、连接与加载分别验收
⑥ 同步 presets/ → 个人目录 preset/（custom/ 保留不动）
⑦ 按层级注入上下文 + 恢复个人目录记忆（iCloud）
⑧ 会话开始；后续每次启动先 check_update，版本变了才升级/重装
```

## 3. 分层注入（防上下文爆炸）

| 层 | 内容 | 注入策略 |
|---|---|---|
| **常驻** | 核心规则、身份、技能索引 | 每次都注入（保持轻量） |
| **按需** | 专业知识包全文 | resource 按需拉取，不常驻 |
| **运行** | 工具 | 注册即可调用，不进上下文正文 |

规则：**上下文只放索引和规则，正文放仓库/按需拉取。**

## 4. 三类存储（按持久度与归属分层，根治临时文件膨胀）

> 根因：把该持久的东西塞进了临时区。正解是按持久度与归属分层，而不是「勤清 tmp」。

| 存储 | 位置 | 内容 | 同步/清理 |
|---|---|---|---|
| **瞬时（可丢）** | 本地 `runtime/`（**不再写系统 tmp**） | 会话草稿、缓存、logs、lockfile、scores | TTL + 清理规则自动执行 |
| **个人持久（跨机器）** | 部署配置的 `<personal-root>/` | 记忆、学习、交付物、experience、staging、preset/custom | iCloud 同步；不入 git（见 [08](./08-个人目录规约.md)） |
| **通用持久** | 中央仓库（GitHub） | packs 四类包、presets、rules、引擎、文档 | tag 版本化；clone/upgrade 获得 |

## 5. 本地演化（技能等级）

- 本地对技能的熟练度：`等级 = f(使用频次, 成功/被采纳率, 适用范围)`；
- 等级加成作用于**本地全景图视图**（通用大类下的本地特殊技能加成），但**统计规则与中央完全一致**（见 [06](./06-全景图管线.md)）；
- 等级达标或本地产生通用候选 → 进 staging，走「自动打标 → 台账 → 人工复核 → 转正」统一升级路线；
- 失败场景 → 攒**归因数据**（哪个场景翻车、缺什么能力）——是周期改进环节的输入；
- 等级是**本地私有**，只上报「使用日志（聚合指标）」，不上报记忆本体。

## 6. 本地自定义角色

- 允许在个人目录定义本地角色（候选位置 `staging/`，复核通过后在本地视图生效）；
- 本地角色与中央 `packs/role/` 同构（非空 SKILL.md 或 PROFILE.md + meta.json，type=role）；
- 通用化达标 → 转正入中央 `packs/role/`；纯个人角色留本地，不回传。

## 7. 与中央的交互

| 方向 | 机制 | 说明 |
|---|---|---|
| **下发** | check_update → upgrade | 中央 tag 发布新版本，本地 opt-in 升级（不静默覆盖本地定制） |
| **预设** | presets/ → preset/ | 只读同步 + 哈希校验；custom/ 不被覆盖 |
| **回传** | 日志PR（免审） / 晋升PR（人审） | 见 05-治理与反馈 |
| **锁版本** | 本地 lockfile 钉版本 + override 标记 | 中央发新版只提示，不强制覆盖 |
| **迁移** | 新版本迁移脚本；旧资产标 legacy | 逐步重推导，不硬迁移 |

## 8. 版本可见性

代理流程启用后，**所有流程结束的最终汇报语句必须包含当前生效版本号**（如「初始化完成…当前版本 v1.2.0」「升级完成…当前版本 v1.3.0」）。

- 让用户随时能识别当前使用的是哪个版本；
- 与全景图版本标注保持一致（见 06-全景图管线）；
- 版本号取自本地 lockfile 钉住的生效版本，不是口头声称。
