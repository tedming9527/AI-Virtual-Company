# 04 · 本地运行时（L3）

> Agent 中介层，自建直连（内部无 MCP 协议层），是「用户与大模型之间的中介」。

## 1. 职责

- **初始化**：读极简 bootstrap.json → 扫描目录规约自动发现 → 发现预置 mcp/（安装/注册另验） → 同步 presets → 定位已配置个人记忆（实际加载另验）；
- **分层注入**：把上下文按层级喂给大模型（防上下文爆炸）；
- **编排与回传**：本地演化（记忆/技能/等级），日志与晋升回传中央；
- **规约校验**：`doctor` 校验个人目录强制规约；
- **本地 git 分支自成体系**：本地可独立迭代，只有转正才走中央。

## 2. 初始化与接入

初始化由确定性安装器 `yarn setup` / `npm run setup` 执行。先扫描保全客户端独有资料，核验后全量重建本项目受管的配置、规则、技能、MCP 和 Hook；第二步才按需导入用户资产。个人数据中心仅增量补齐，不清空用户 custom。保全失败只暂停破坏性重置，不阻断普通任务。详见 [客户端重建设计](14-客户端初始化重建设计.md)。

已启用适配器的客户端按宿主 session/turn 接入，一个逻辑任务可以涉及多个项目；聊天启动目录不是准入条件。部署配置决定根路径和状态位置。安装、宿主信任、工具连接、原生事件、正文交付与采用分别验收。

## 3. 按需交付与累计预算

| 层 | 内容 | 交付策略 |
|---|---|---|
| 启动/恢复 | 最小项目范围、真实回合绑定、必要身份段 | 回合、代理与 context epoch 逐段去重，不按每个工具事件重发 |
| 发现 | 元数据、有效中英摘要、相关性证据和加载引用 | 查询短卡分页；正文在本机用于检索，不随卡片全量注入 |
| 读取 | 来源绑定的摘录、章节索引和正文片段 | 明确选择后按 SHA/UTF-8 游标分段，不把摘录当完整规则 |
| 工具定义 | 宿主提供的可用工具和参数定义 | 属于宿主上下文，不承诺“注册工具零上下文成本” |

单次完整正文响应 8192 B、Hook 合并 12288 B、回合 65536 B、会话 262144 B。相同原生 session/turn 的父子代理共享累计额度，去重按 agent 隔离。无绑定时仅单次上限有效；JSON 转义与受控元数据计量，隐藏模型 token/费用未知。预算或采集故障保留有界控制、不否决普通任务。详细口径及旧账本迁移见 [01](01-架构总览.md)。

`ted summary` 默认 inspect 只读，显式 prepare/submit 维护来源绑定双语缓存；不重置累计账本或宣称已清空宿主上下文。

## 4. 存储与保留

| 存储 | 位置与内容 | 同步/清理 |
|---|---|---|
| 客户端运行态 | 部署解析的客户端 stateRoot：Hook、执行、预算、锁和观察记录 | 与个人资料隔离；不是所有 runtime 文件都可丢；活动任务和未知回执保留 |
| 仓库运行态 | 仓库 runtime：运行元数据、本地视图、开发验收产物 | 不强制接管宿主临时目录；中介层自建临时副本须核验不在同步目录 |
| 个人持久资料 | 部署配置的 personal-root：原文、长期课题、交付物、custom、staging | 按已配置策略同步；唯一原文不能因摘要完整、年龄或低热度自动删除 |
| 中央持久资料 | 四类 packs、presets、rules、引擎与文档 | 受审 PR、master CI、tag/Release；不含私人正文、账号或凭据 |

日志清理需具体 SHA、已核验汇总和任务终态；明确废弃资料另验版本依据与保留期。缓存、事件与唯一原文不共用一个 TTL 删除策略，见 [05](05-治理与反馈.md)。

## 5. 本地演化（技能等级）

- 本地对技能的熟练度：`等级 = f(使用频次, 成功/被采纳率, 适用范围)`；
- 等级加成作用于**本地全景图视图**（通用大类下的本地特殊技能加成），但**统计规则与中央完全一致**（见 [06](./06-全景图管线.md)）；
- 等级达标或本地产生通用候选 → 进 staging，走「自动打标 → 台账 → 人工复核 → 转正」统一升级路线；
- 失败场景 → 攒**归因数据**（哪个场景翻车、缺什么能力）——是周期改进环节的输入；
- 等级是**本地私有**，只上报「使用日志（聚合指标）」，不上报记忆本体。

## 6. 本地自定义角色

- 允许在个人目录定义本地角色（候选位置 `staging/`，复核通过后在本地视图生效）；
- 本地角色与中央 `packs/role/` 同构（非空 SKILL.md 或 PROFILE.md + meta.json，type=role）；
- 通用化达标 → 转正入中央 `packs/role/`；纯个人角色留本地，不回传。

## 7. 与中央的交互

| 方向 | 机制 | 说明 |
|---|---|---|
| **下发** | check_update → upgrade | 中央 tag 发布新版本，本地 opt-in 升级（不静默覆盖本地定制） |
| **预设** | presets/ → preset/ | 只读同步 + 哈希校验；custom/ 不被覆盖 |
| **回传** | 日志PR（免审） / 晋升PR（人审） | 见 05-治理与反馈 |
| **锁版本** | 本地 lockfile 钉版本 + override 标记 | 中央发新版只提示，不强制覆盖 |
| **迁移** | 新版本迁移脚本；旧资产标 legacy | 逐步重推导，不硬迁移 |

## 8. 版本可见性

代理流程启用后，**所有流程结束的最终汇报语句必须包含当前生效版本号**（如「初始化完成…当前版本 v1.2.0」「升级完成…当前版本 v1.3.0」）。

- 让用户随时能识别当前使用的是哪个版本；
- 与全景图版本标注保持一致（见 06-全景图管线）；
- 版本号取自本地 lockfile 钉住的生效版本，不是口头声称。

## 执行介入

本地运行时通过客户端级原生入口、项目绑定与 Hook 与 MCP 任务合同参与执行，见 [11](11-执行介入架构.md)；只覆盖实际暴露事件。技能发现与正文交付见 [12](12-资产发现与使用追踪.md)，不能从目录、等级或署名推定执行受控。
