# 18 · 本地实时监控设计

状态：2026-10-15 已实现源码首版，尚未发布或安装到本机客户端。包含真实事件发送端、本机只读服务、候选/正式资料准入、时间/会话/类型筛选、分组柱状图与增长提示动画；隔离原生适配器回归不等于已安装客户端验收。本文保留证据与治理边界，实际首版差异见第 6 节。

数据策略（按用户最新决定）：**仅在 monitor 页面存在活动连接时记录；监控副本滚动保留 24 小时，关闭最后一个页面后停止新增采集，已有副本不立即删除。** 24 小时按每条记录首次进入监控的时间计算，不按自然日或再次打开刷新。服务重启不复原过期副本，不从旧业务台账补回被清理的监控历史。

目标：用户在模型工作时，可以按时间、会话、回合和代理查看已登记候选及后续阶段资料的发现、交付、读取、采用声明及执行证据，并知道证据缺在哪里。页面反映可观察事实，不声称看见模型内部推理或证明每条规则已被遵守。

## 1. 监控范围与首版取舍

首版为**本机只读监控页**，读取部署配置指向的客户端状态，与公开全景图分开。开启后覆盖已接入且在观察期间产生事件的会话，不后台积累未开启期间的事件，不按启动项目目录准入；项目是筛选维度，一个会话可以关联多个项目。

### 资料准入：候选及以上

**只记录有可核验登记的候选，以及已复核转正或已正式发布的受管资料。** “候选”包括来源绑定的中央知识目录候选和私有候选登记，指治理生命周期中的已登记候选，不指一次检索召回的候选结果。适用于 skill / knowledge / framework / role 以及已有治理登记的其他资料类型；不靠类型名、文件位置或模型声明提升身份。

- 候选以登记 ID、版本、内容 SHA 及来源记录核验；候选试用及后续评审、转正、发布按各自台账展示，不虚构统一递增状态枚举。`candidate`、`stale`、`superseded` 是现有候选状态；失效/被替代的已登记版本仍可显示有效保留期内的历史事件并标明不可用，不代表重新启用。
- 已复核登记的正式个人资产和有版本清单的中央发布资产可直接纳入，不要求旧正式资料补造候选历史。复制、保全、统计和试用不构成转正或发布证据。
- 未登记草稿、临时提炼、原始对话、工具输出、staging 待审导入、客户端独有未升级资料以及来源/身份无法核验的内容均不进入监控副本。检索命中或返回推荐卡不会自动满足准入。
- 准入校验在**写入监控副本、索引和聚合之前**执行；不是先收集全部再由网页隐藏。事件必须唯一关联符合条件的资产身份及修订；同名、模糊相关、仅同一会话都不足以关联。无法确认则不保存该事件内容，只以不含身份/正文的有界健康计数提示未纳入。
- 多资产事件只投影符合条件的资产字段，不保存未准入资产的名称、哈希或完整工具载荷。会话只在含准入资料事件时进入列表，保留最少关联 ID；普通工具/任务日志不整批复制。资料后来登记时，从登记后的新事件开始记录，不回填登记前历史。
- 预算仅记录可归属准入资产交付的字节/去重结果；全会话共享预算若后续展示，只能作为即时只读状态并标注含其他资料，不存入资料历史或归因统计。不可分摊的总量标为未知，不推算成单资料消耗。独立采集健康只保存有界计数与原因代码，不保存被排除资料。

| 范围 | 页面呈现 | 事实边界 |
|---|---|---|
| 采集健康 | 安装/引擎/目录版本、安装代次、最近采集、解析/读取失败、索引进度 | 没有事件不等于离线；没有独立存活证据则状态未知 |
| 会话与回合 | 原生会话、回合、逻辑任务、状态、工作区关联、代理标识 | 不凭标题、内容相似或目录合并会话；岗位不是认证员工 |
| 规则与资料 | 名称/类型/版本/SHA、来源与资格、命中原因、摘要/分块、读取覆盖、采用声明 | 推荐、正文交付、工具读取与采用分列；未知不置为 0 或“未使用” |
| 关联证据 | 仅准入资料的读取完成、声明及产物摘要关联 | 不保存完整工具流水；任务完成不证明所有规则都有效 |
| 上下文 | 准入资料交付字节、去重、预算阻止原因；共享总额首版不展示 | 共享快照不入历史、不分摊给资料；UTF-8 字节不换算为精确 token/费用 |
| 治理 | 候选/试用/发布/清理的已有状态及警告 | 展示已有回执，不新增批准、试用、升级或删除操作 |
| 外部判断关联 | 仅可唯一归属于准入资料的结构化结果 | 普通 Jev 调用不保存；不为监控而增加调用 |

上表所有资料事件与关联证据均受上述准入约束；采集健康不是全局日志入口。

首版不做远程多机汇总、模型内心过程分析、后台模型归因、自动修复、发布、删除或全局 gate。页面不扫描整个 HOME、原始聊天和任意工具输出。资料正文默认不传浏览器；必要字段取自现有授权状态源，扩展读取另作范围设计。

## 2. “使用规则”的证据表示

资料详情使用并列证据徽标，不设置一个笼统的“已使用”勾选：

| 标记 | 条件 | 不能推导 |
|---|---|---|
| 已发现 | 已通过准入，且明确发现投影存在该版本 | 模型已看到或已调用 |
| 已返回推荐卡 | 对应发现响应有可关联资产卡 | 正文已交付、规则适用 |
| 摘录已交付 | 受控 summary 返回及来源摘要 | 已交付全部条件和例外 |
| 正文分段已交付 | 已记录来源绑定片段；显示覆盖字节区间 | 宿主确认接收、实际遵从 |
| 已完成可观测读取 | 支持的字面读取工具有完成事实 | 模型语义采用 |
| 模型声明采用 | report_asset_use 的同修订声明 | 独立已验证采用、因果收益 |
| 产物已核验 | 真实产物路径/摘要匹配 | 业务正确、由该规则导致成功 |
| 缺证据/不可观察 | Post 缺失、未绑定、采集错误或无适配事件 | 不补造成成功，也不当作失败或没有使用 |

示例：“账号选择规则 · vX · 摘录已交付 · 模型声明采用 · 遵守情况未知”。点开后查看来源和对应事件，而不是显示“规则执行成功”。跨来源出现相同内容也不自动合并归属；资产身份和修订分别展示。

资料搜索默认匹配安全元数据，不能为了 UI 搜索又将整库正文复制到浏览器。规则卡保留准确正文/章节引用；现有按需加载仍属于模型侧流程，监控页不伪造加载回执。

## 3. 时间、会话与代理维度

### 时间

- 默认“本次开启＋实时跟随”，可切最近 1 小时、保留中的最近 24 小时、自定义时间段；仅在实际记录区间内查询，未开启/关闭期间标为“未监控”，不回扫补录；默认显示浏览器时区，中文部署初始显示 Asia/Shanghai，并在界面标出时区。
- 保留期限使用独立 recordedAt（首次写入监控副本）计算，重复事件、页面重开和筛选不会续期。存储用 UTC 时间；查询使用半开区间 `[from, to)`，本地日期转换为明确 UTC 边界。自定义历史区间固定，实时模式使用滚动窗口。
- 区分来源提供的 occurredAt、适配器采集/观察时间 observedAt、监控投影读入时间 indexedAt。现有 native event 的 at 是采集时间，不改名成实际动作发生时间。
- 来源没有发生时间时，时间线明确按采集时间排序；开启时的必要状态快照缺少每块交付时间时标“开启时状态，分块时间未知”，不以文件 mtime 填造事实。
- 到达顺序用本监控数据代次及序号稳定排序，延迟到达显示标记；不补录未监控时段。采集延迟不当作执行耗时；Pre/Post 的观测间隔单列，不声称是纯工具运行时间。
- 暂停跟随只冻结滚动位置，顶部显示新增数量；恢复后增量补齐，不丢失游标。时间筛选同时作用于列表、统计和导出，跨边界的进行中任务显示“始于窗口之前”。

### 会话

身份层级：`客户端来源 → sessionId → turnId → taskId / agentId`。客户端来源由监控明确配置，不从机器名或个人账号推断。

- 默认列出保留窗口内有监控记录的会话，按最后观察时间排序；提供全部、最近活动、已关闭及状态未知筛选。
- 左侧会话列表显示短 ID、首/末观察时间、关联项目、活动/未知任务数；宿主有经许可的会话标题才显示，缺失使用“会话＋短 ID”。
- sessionChainId 在当前实现中等于原生 sessionId，不据此声称支持跨原生 ID 的聊天连续性。相同 ID 的重载按 generation 分段；分叉的新 ID 仅在宿主提供明确父关系时展示关联。
- 同一会话跨项目只展示一份。候选 task key 可作为弱逻辑关联线索，缺失、重用或无法验证时不强行合并；不会话间重置预算或搬用回执。
- agentId 缺失与明确的根代理分别按源协议显示；不能把 null 自动解释为“无子代理”。不同代理缺少 parentAgentId 时并列展示，父子关系保持未知。
- 预算按原生作用域显示：同 session/turn 的 v2 即时累计额只展示一次（不持久化），不把各代理读到的共享快照求和；v1 独立账本标旧口径及覆盖不足。跨原生 turn 不伪称共享同一 turn 额度。

默认不展示绝对个人路径、完整工具参数、回执 nonce、账户、密钥或聊天内容。路径优先以项目标签＋相对路径展示；详细敏感字段必须有单独明确设计，不因本地页面就全量暴露。

所有列表、API、增量流及未来导出继承同一后端准入结果，不能由筛选参数扩大范围。计数仅覆盖准入资料，明确区分事件数、工具调用数、任务数、资产修订数；同一动作的 ingress/execution/outcome 多通道记录关联为一组事实，不把它们算成多次采用。错误记录持续可查，告警展示去重不抹去证据缺口。

图表采用分组柱状图：按证据类型比较已登记候选与正式资料的事件数，使用共同零基线及相同刻度，随时间/会话/证据过滤联动，附数值表和模拟标记。不用梯形宽度暗示候选必然晋升或交付必然采用；未知采用与采集覆盖不当作零使用。准入范围、图表、时间线及计数共享同一过滤结果。

## 5. 当前数据能支持什么

依据 1.9.1 源码读取，不将源码能力说成当前 1.8.4 客户端已启用。

| 来源（相对部署 stateRoot） | 可复用内容 | 缺口与处理 |
|---|---|---|
| runtime/mediation/events/*.json | captureId、采集时间、session/turn/agent、工具/调用ID、输入/输出摘要、generation | 没有原始动作时间、规则语义或通用代理父ID |
| runtime/mediation/sessions、turns、workspaces | 已关联身份、工作区及原生回合 | 绑定回执为敏感内部字段，不返回网页；首/末观察应由事件重建，不误用附件创建时间 |
| runtime/execution/tasks/*.json、events.jsonl | 合同、加载资产、正文覆盖、documents、调用完成分类、产物与完整性 | agent 字段部分在任务而非每条审计中，需唯一匹配后关联；旧快照不能重造逐块事件时间 |
| runtime/asset-events.jsonl | manager-delivered、read-attempted/completed、model-reported | 部分事件缺统一 assetId/agent；只按唯一且版本匹配的证据连接，不能按名称猜；读取本项目配置的事实源而非任意路径 |
| runtime/context/*.json | 累计字节与作用域、代理计数及去重标记 | 聚合快照不含每次响应的准确历史字节，缺失不反推；不得为展示去重标记而暴露所有哈希 |
| runtime/hooks/outcomes 与治理台账 | 采集/交付/署名及已有治理状态 | clientStatus 当前全量读取多个目录，不适合作为每秒轮询实现 |

上述来源是关联事实的适配能力，不是全部收录清单；普通原生工具事件不直接写入监控。开启时只取必要的版本、准入资料相关会话状态和不持久化的即时预算参考，标为“开启时状态”，不复制完整历史；事件源建立起始水位，只读取开启后的新增事实。关闭后不继续补读。首版显示实际记录与覆盖状态；为了精确新增记录，拟增加安全字段白名单的 delivery/discovery 观测：来源资产 ID/修订、响应是否返回卡、summary/chunk、字节与结果、session/turn/agent、原因代码。检索原句、正文和原始输出默认不记录。补这些记录只作用于未来事件，历史缺口不能回填成实证；补记失败继续业务。

实际采用和规则遵守缺少宿主独立信号，不作为必须实现的新推断模型。Jev 的结构化用量没有统一采集时先显示“未接入”，不默认读取 Codex 私人 rollout 补全。

## 6. 已实现的增量服务与成本

```text
现有检索/交付/读取/候选治理代码完成已有事实
    → 内部来源资格判断 + 安全字段白名单
    → 仅活动页面租约内的本机能力认证事件通道
    → 本机服务再次校验 + 独立且有界的24小时监控副本
    → 带签名水位的分页快照 + SSE 变更通知
    → 本机浏览器
```

监控是旁路。模型和 Hook 不等待网页；网页不调用 LLM/Jev、不重新推荐资产，也不把事件推回模型上下文。发送端只检查本机受管实例与采样租约，未开启时不发送事件；已开启时发送白名单元数据，传输设 100ms 终止上限，不等待网页。队列发送不是确认交付回执；服务实际写入后才能查询。失败只返回辅助状态，不改变业务工具、资料加载及预算返回结果。

源码位置：`mcp/ted-avc-manager/src/monitor/`；事件接入 `asset-discovery.js`、`execution.js`、`awareness.js` 和 `governance/candidate-trials.js`。已支持已返回发现/推荐卡、摘要/分段正文交付、去重与预算阻止、字面读取及声明、候选登记和试用阶段；未在这些路径提供可核验来源的资料不录入。角色 PROFILE 的完整交付也有独立事件。中央知识目录里的 candidate 条目按候选展示；多个条目引用同一正文时，正文交付只记录一份，不按条目数放大。中央稳定/活动包还须绑定受管分发清单或当前版本 Release tag 的准确正文与元数据摘要；未发布的源码改动不会冒充正式资料，个人正式技能必须已有有效登记；中央仓库独立 Markdown 索引项尚无独立治理证明时不收录。本地摘要核验不冒充发布签名验证或自动晋升。

首版没有扫描旧 Hook 日志、台账和资料正文的历史投影器，也不安装文件观察器、全局常驻服务或周期模型任务。第 5 节列出已有事实源，不代表全部持续复制。只有新版发送端产生的新事件可以进入监控；未升级的 1.8.4 客户端不会自动获得新字段。候选/正式阶段来自对应内部校验路径，网页和公开 API 无录入资料或升级端点。

存储采用内容摘要命名的专属记录文件，精确核对 schema、归属目录和内容 SHA 后删除；启动分批恢复自己的未到期记录，不回读业务历史。单服务独占写入，自动端口与实例锁防重复；游标绑定实例、事实水位、最后条目和精确筛选并附 HMAC，后续页不因新事件插入而错位，重启/过期/变更筛选必须刷新。没有跨实例断点续传保证。

首版实际限额：单事件入站 4 KiB；事件页默认 100 项、最多 200 项、响应约 64 KiB 上限；浏览器最多显示 500 条，保留历史分页；服务最多 10,000 条或 16 MiB 监控记录，触顶提前淘汰最旧条目并报告。使用 SSE 只推变更通知，数据由分页接口读取，页面每 10 秒保活/校对，流断开会显示覆盖缺口。正常新事件 2 秒内可见是验收目标，尚无长期生产 p95 承诺。

类型维度为 skill（技能）、knowledge（知识）、framework（框架）、role（岗位）和 material（其他已登记资料）；类型不是晋升阶段。分类统计、时间线、柱状图及分页使用相同过滤。正式资料与候选分别着色，不把候选数量当作有效采用。新增事件只触发柱体高度过渡、计数增长提示和新行短暂高亮；暂停显示时不更新视图，恢复取最新有界快照。`prefers-reduced-motion` 下关闭动画。权威计数即时更新，不等待动画帧，后台标签页暂停动画也不滞留旧值。监控计数仅存在于专属副本与页面，不回写资料使用次数、评分、趋势、升级证据或上下文账本；打开/刷新页面和播放动画不新增采用样本。通过 Ted 命令打开监控时，该命令本身仍按现有协议正常记账，不与网页观察次数混计。

监控记录仅滚动保留 24 小时，索引、聚合、会话列表和浏览器缓存同步退休对应条目，不能在派生统计里无限积累。监控专属副本设 10,000 条或 16 MiB 上限；容量不足时提前淘汰最旧条目并显示“因容量提前清理”，不是保证可保存全天全部事件。界面过滤到期记录后刷新游标，引用已清理数据时明确 reset/expired。

只在监控专属目录内，按实例所有权、精确清单和摘要核验后清理自己的副本；拒绝符号链接、路径逃逸和未知新增文件，不递归删除未知目录内容。不得对原始事件、业务台账、活动任务、用户原文或已有审计数据应用此 24 小时策略。到期条目不可继续查询；物理清理失败如实标记待清理，不能声称已删除。

最后页面关闭后停止监控采样，保留到期清理定时器，清完所有本实例记录后自动退出；定时器不发模型/API请求、不继续收集事件，不安装全局常驻服务。进程崩溃或机器关机时无法保证准点物理删除，下次启动必须先按原 recordedAt 清理过期副本再对外提供数据。实例元数据不保存事件内容，清空缓存时一并退休。

## 7. 如何启动与停止

推荐交互：聊天输入 `/ted monitor`（中文“打开监控”），由 Ted/MCP 后端启动或复用本机受管服务，并打开默认浏览器。模型只拿到“地址、来源、筛选、进程状态”的短回执，不拿实时事件正文。页面可独立于聊天持续展示。

以下为**当前源码入口**；已安装旧客户端需在后续发布更新后才能使用：

```sh
# 打开/复用，记录开启后的事件；可查看保留中的最近24小时
node mcp/ted-avc-manager/src/cli.js monitor open
# 定位当前会话；身份来自原生绑定，不由模型猜测
node mcp/ted-avc-manager/src/cli.js monitor open --session <native-session-id>
# 只报告状态/健康/版本，不拉业务历史
node mcp/ted-avc-manager/src/cli.js monitor status
# 只停本监控实例，不终止模型、MCP或采集 Hook
node mcp/ted-avc-manager/src/cli.js monitor stop
# 手动前台运行，Ctrl+C 退出
node mcp/ted-avc-manager/src/cli.js monitor serve --open
```

`/ted monitor` 后端 operation 为 open/status/stop；会话筛选只影响查看，当前会话没有数据时显示“尚无事件”，可切换全部，不要求先绑定或补采集。

启动步骤：解析对应 CODEX_HOME/部署 stateRoot → 清理本监控已到期副本 → 检查现有实例与来源版本 → 复用健康实例或启动受管子进程 → 绑定 `127.0.0.1` 自动分配空闲端口 → 本地访问握手就绪 → 打开浏览器。地址形态为 `http://127.0.0.1:<自动端口>/`，不固定假定 3000，不监听 0.0.0.0。手工启动可指定空闲端口，冲突只换端口/报明原因，不结束其他程序。

重复打开复用服务；多个标签页按独立页面连接计数，关闭一个不影响其他页面。最后页面正常关闭时立即停止新增监控采样；不能仅靠 beforeunload，须结合连接断开与心跳租约，以 30 秒租约失效处理浏览器崩溃/异常断线。刷新在短重连窗口内复用同一实例和未过期数据，不给记录续期。

关闭后仅执行已有副本的到期清理，保留满 24 小时的记录自动清除；重开从新水位恢复采样，关闭期间不补录，形成明确“未监控”区间。`monitor stop` 先核验实例身份再停采样和交互服务，保留到期清理职责；不停止模型、MCP或业务 Hook，也不能仅凭 pid 文件杀进程。无记录时直接退出，不默认安装登录项或全局 daemon。

浏览器自动打开失败时返回可安全重新签发访问入口的方法，不将长期鉴权 token 打印到聊天。旧进程/协议不兼容时明确 upgrade-required 或只读旧版覆盖，不为监控强制中断任务、自动重建客户端。当前客户端只有旧版事实也能观察，但新字段保持未知。

## 8. 本地页面权限与接口

本地数据也可能敏感。首版只读 API，使用本次实例的访问能力与短期浏览器会话；无公网、无跨机器自动连接、无开放 CORS、无 CDN 和外部埋点。

- 校验 Host 与 Origin，防 DNS rebinding；未授权请求不得读取事件。页面静态壳不含私人数据。
- CLI 打开带一次性 bootstrap 片段的本机地址；页面立即移除地址片段，以同源 POST 交换短期 HttpOnly/SameSite=Strict 会话。bootstrap 不进服务器 URL 日志、Referer、聊天或导出；过期重新由本机命令签发，具体存储和超时需安全用例验证。
- SSE 使用同源会话，访问过期明确断开；停止进程撤销本实例凭据。浏览器侧按文本渲染事件，禁止执行来源 Markdown/HTML；设置 CSP，防止资产名称等内容注入脚本。
- 服务只按源适配器的白名单相对路径读取，不接受任意文件 API；来源根/中间链接与权限需核对。错误不返回绝对路径、nonce 或工具原始参数。
- 导出为后续显式功能，默认不导出；后续须继承当前时间/会话过滤及字段白名单，不以“监控启动”扩大资料授权。

已实现 API：`GET /api/status`（认证后）、`GET /api/sessions`、`GET /api/events`、`GET /api/assets`、`GET /api/stream`；均支持严格校验的来源和筛选条件、有界输出及不透明分页/续传游标。认证交换不写业务台账；没有从网页创建任务、执行工具、改变评分或清理源数据的端点。

## 9. 实施顺序与验收

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| A：事实与来源 | 只读来源适配、写入前准入、统一投影、覆盖/未知状态 | 多项目、缺 ID、混合版本、损坏单源不误归因；不读取正文和私人聊天 |
| B：时间与会话 | 分页 API、快照水位/增量流、会话/回合/代理筛选 | 时区与半开区间正确；重连/轮转/迟到不漏报成完整；快照无未来补造成事实 |
| C：页面与启动 | 中文页面、证据徽标、Ted/CLI open/status/stop | 一键打开、重复复用、端口冲突、浏览器失败及停止实例安全；原生任务不受影响 |
| D：真实使用验收 | 主/子代理与缺 Post、预算耗尽、资料分段、声明采用的真实会话 | 页面所示与实际台账逐项对应；准确区别“被推荐/交付/声明/未知” |

准入验收：未登记草稿即使命中检索也不写副本；候选/正式资产有准确身份及修订才记录；同名未知资料不误收；多资产记录裁去未准入部分；后登记不回填；失效版本只保留原记录且不重新启用；普通工具与原始对话不落盘；共享预算不入资料历史；健康告警无被排除资料身份。

常驻反例：同 session 多项目不重复；同名不同会话不合并；未知父关系不画假树；同一资产不同 SHA 不沿用旧采用；v2 共享预算不按代理求和；空闲聊天不假报离线；旧历史无分块时间不凭 mtime 生成；恶意资产名称不执行脚本；无访问能力不能读取本机事实；副本索引损坏/磁盘只读/网页慢或关闭都不阻断业务；多标签只在最后连接关闭后停采样；重开不续期；过期记录不会从旧源复活；清理失败不误报已删除。

后续容量基准计划使用 1 万/10 万事件、并发会话、长连接、关闭/重开、24 小时边界、进程崩溃和重连，记录源读取量、浏览器/服务 RSS 和可见延迟。旁路开启相对关闭时，应无新增模型/API请求、无重复正文注入；Hook 额外耗时须实测，新增安全观测字段必须有界且失败降级。原始源和唯一资料清理不纳入监控服务。

本轮实现源码及隔离回归，不改变既有 1.9.1 发布，不重建当前客户端。真实原生加载器事件、辅助配置损坏、24 小时边界、分页并发、多页面租约及网页认证分别验收；当前已安装客户端的端到端验收仍待正式更新后执行。前台服务收到 SIGINT/SIGTERM 会退出，离线/强制退出期间的物理清理在下次启动前补做；正常 `monitor stop` 保留已有副本的到期清理职责。
