## 部署与模板边界

中央 role/framework/knowledge 是通用方法模板，不携带个人身份、历史训练成绩或私人配置。专业包中文名字与职业是通用包的稳定显示身份，不是自然人实名。部署实例须单独维护组织名、个人存储和平台适配证据。旧公司的 bootstrap、身份和 Hook 属于部署层，不由通用目录校验代替。

v1.1.1 增加 [Codex 原生署名 Hook 适配器](10-Codex署名钩子.md)：显式安装、开始/每回合注入、Stop 校验、一次补正和回合关联回执。代码可用不等于客户端已启用；每个部署须另验信任、实际生命周期触发和既有会话加载。

存储配置的实际优先级和失败行为见 [08](08-个人目录规约.md)。中央默认不指定个人目录；本机覆盖保存于 Git 忽略的 runtime/storage.json。缺少部署路径时，本机临时骨架只用于机制验证。

中介层 [候选入口](../packs/framework/company/intermediary/BOOTSTRAP.md) 仍是设计候选；受保护发布、统一配额账本、可信桌面适配和真实长任务续跑分别验收，不能通过改写文档宣称启用。

## 2026-10-13 个人资料治理增量

周度入口由会话启动 Hook 在到期且本机为登记写入设备时提示派发子代理；Hook 不自行启动或证明子代理已完成。`governance-weekly-prepare` 只生成去重窗口统计、经验来源摘要和容量报告，`governance-weekly-complete` 只接收来源摘要匹配的待复核建议。现有任务历史未保存完整 bundle 摘要的记录不会被追认为旧版实证；历史反馈与满意度也不能从对话沉默推算。

`experience-recovery-*` 需要调用方提供已复核覆盖映射，目前仅校验声明、文件摘要和路径，不验证复核者真实身份。现有版本不能自动判断经验正文已经完整提炼，因而不得批量将旧资料移入回收区。跨设备离线并发仍缺强一致协调；首版状态只接受一个写入设备，其余设备应保持只读。

本机首轮周度准备和子代理只读提炼已完成：扫描 408 条经验路径，保存 4 条来源摘要匹配、状态为待人工复核的建议，覆盖截止 2026-10-13T09:23:55Z。可归因资产事件为 0，不产生实证评分。个人资料约 19.4 MiB，未超过 1 GiB 软阈值；未移动或删除任何旧经验。已实际生成本地全景图并核对建议数、容量和公开数据隔离。浏览器对 `file:` 页面访问施加限制，故本轮没有完成浏览器视觉验收，不能把 HTML 生成视为视觉验收。
