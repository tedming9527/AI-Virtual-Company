# 07 · 升级需求文档（全量 · 不分阶段）

> 依据：本套开发文档 01~08。
> 范围：**一次全量升级**，不做分阶段交付。
> 中央仓库：**本项目仓库即中央仓库地址**，升级后仓库根同时承担「技能包注册表 + 初始化引导源 + 版本账本 + 预设下发源 + 全景图发布源」职责。

---

## 1. 升级目标

将现有项目升级为「多类型 AI 技能包生命周期平台」：

1. 仓库按**约定大于配置**的目录规约重构，成为中央仓库；
2. 大模型（豆包/Codex）可通过**命令协议**（`github://` + 动作词）初始化、升级、回传；
3. 本地运行时成为 **Agent 中介层**（自建直连），本地演化（记忆/技能/等级）；
4. **本地临时信息统一进 runtime/**，不写系统 tmp，根治临时文件膨胀；
5. **个人项目信息按强制规约分离到部署配置的个人存储**（跨机器同步），doctor 校验；
6. **所有通用型候选数据走统一升级路线**（自动打标 → 台账 → 人工复核 → 转正）；
7. **预设统一下发、preset/custom 配置分层**，升级不覆盖用户定制；
8. **全景图生成脚本与统计规则中央/本地同源**，差异仅在数据；
9. 建立**版本可见性**：代理流程启用后，最终汇报语句带当前版本号；
10. 建立**治理闭环**（反馈双通道 / 评分 / 周期改进 / 全景图）；
11. **清理无效测试代码与失效门禁**，仓库只保留真实生效的逻辑与校验。

## 3. 需求详述

### FR-1 中央仓库目录规约（约定大于配置）

**要求**：

1. 仓库根必须包含：`bootstrap.json`、`CHANGELOG.md`、`README.md`、`AGENTS.md`、`mcp/`、`packs/`、`presets/`、`rules/`、`runtime/`、`panorama/`、`docs/`；
2. `packs/` 下按类型分目录：`skill/`、`knowledge/`、`framework/`、`role/`；
3. 每个包必须包含 `SKILL.md`（入口）与 `meta.json`（类型/版本/rubric）；
4. **新增专业包 = 建目录即被发现**，不得要求修改配置；
5. `mcp/` 目录名即工具名，自动注册。

**验收**：新建仅含 SKILL.md + meta.json 的空包，扫描器无需配置即可发现；bootstrap.json 不随包数量变化。

### FR-2 初始化流程

**要求**：

1. 一次性引导：用户给出仓库地址，Agent 读取/clone；
2. 读 `bootstrap.json` → 扫描目录规约发现四类包 → 安装 `mcp/` 预置；
3. 同步 `presets/` 到个人目录 `preset/`（`custom/` 保留）；
4. 分层注入：索引/规则常驻、知识按需、工具注册即用；
5. 恢复已配置个人目录记忆与项目状态；
6. 初始化完成汇报，**必须包含当前版本号**。

**验收**：从空目录执行初始化，全自动完成「读清单 → 发现包 → 装 MCP → 同步预设 → 分层注入 → 汇报（含版本号）」，无人工步骤。

### FR-3 命令协议

**要求**：

1. 动作词：初始化/安装mcp、升级、检查、同步、生成全景图、体检/doctor、配置/config、导入/import-scan、绑定/bind；
2. 三层解析：① URI 正则（确定性代码）→ ② 意图映射（动作词→流程ID）→ ③ 预定义流程；
3. 地址/版本解析必须代码实现，模型不得编造；
4. 歧义/失败停下询问，不得猜、不得续跑。

**验收**：「根据 github://xxx 开始执行初始化，安装 mcp」自动命中 init_flow；未知动作词明确报错等待指示。

### FR-4 版本管理

**要求**：

1. semver：patch 自动、minor opt-in、major 人审；tag 与 CHANGELOG 对应；
2. lockfile 钉版本 + override：新版只提示，不静默覆盖本地定制；
3. `check_update` 报版本差异；`upgrade` 增量应用，重大变更给迁移说明；
4. 新版本带迁移脚本；旧资产标 legacy，逐步重推导。

**验收**：本地改过某包后中央发新版，upgrade 提示冲突且不覆盖；check_update 正确报告差异。

### FR-5 版本可见性

**要求**：

1. **每次流程结束的最终汇报语句必须包含当前生效版本号**；
2. 版本号取自 lockfile，不得口头声称；
3. 全景图同步标注当前版本。

**验收**：执行任意流程后汇报中可见生效版本号，且与 lockfile 一致。

### FR-6 本地运行时（Agent 中介层）

**要求**：

1. 本地自成体系（本地 git 分支），只有转正走中央；
2. 本地演化：记忆 / 技能 / 等级；`等级 = f(使用频次, 成功/被采纳率, 适用范围)`；
3. **允许本地自定义角色**（与 packs/role 同构，进 staging 走统一升级路线）；
4. 等级为本地私有，只上报聚合指标，不上报记忆本体。

**验收**：本地可完成「使用→记录→升级→候选→申请转正」闭环；上报仅含聚合指标与归因标签。

### FR-7 本地临时信息迁移

**要求**：

1. `runtime/` 作为本地运行态（会话草稿、缓存、临时输出、logs、scores）唯一落点，**不再写系统 tmp**；
2. runtime/ 必须有 **TTL 与清理规则**，瞬时内容到期清理、已消费日志按删除规则清除；
3. 个人持久信息落 部署配置的个人目录，通用资产随中央仓库，三者无交叉；
4. 一次性迁入存量散落的运行态数据并归档。

**验收**：升级后系统 tmp 不再因本项目增长；runtime/ 按 TTL 自动清理。

### FR-8 反馈与治理

**要求**：

1. **统一升级路线**：所有通用型候选走 staging「自动打标 → 台账 → 人工复核 → 转正」（详见 FR-13）；
2. 反馈双通道：使用日志 PR 免审自动合并（必过 schema 校验门）；晋升/转正 PR 人审合并、打新 tag；
3. 日志生命周期：收集 → 累计 → 周期分析（聚合指标+失败归因）→ 删除规则清除；保留窗口 N 天；
4. 评分：LLM 静态分 + 用户实证分，分开存、挂版本、融合为质量分；统计规则中央/本地一致（FR-14）；
5. 评分后果：高分快车道 / 低分淘汰 / 影响排名；
6. 异常（成功率骤降）即时触发治理；最低样本量 + 异常分剔除。

**验收**：日志 PR 未过 schema 门不得合并；超窗已消费日志被删除；分数挂版本可比对；异常即时触发治理。

### FR-9 全景图管线

**要求**：

1. 一份生成器两端触发：扫描规约 → 聚合 meta.json+台账 → 渲染 HTML → 输出 panorama/；
2. CI：tag 发布自动生成部署 GitHub Pages（中央视图：全量台账）；
3. 本地：`generate_panorama` 手动触发（本地视图：个人数据+技能加成）；
4. 全景图展示四类包、每包状态、使用指南、配置来源、当前版本。

**验收**：打 tag 后 Pages 自动更新；本地手动生成同版本逻辑；展示各包状态与当前版本。

### FR-10 清理项（移除无效测试代码与门禁）

**要求**：

1. 移除所有无效/占位测试代码、未生效 mock，只保留真实可运行逻辑；
2. 移除失效门禁（空跑 CI、空检查）；保留并落实 schema 校验门等真实校验；
3. 交付物不含占位符、测试残留与脚手架文件。

**验收**：仓库无无效测试/失效门禁；保留的校验门可实际阻断不合规 PR；干净 clone 可直接运行。

### FR-11 个人目录强制规约

**要求**：

1. 个人目录固定位于 部署配置的 `<personal-root>/`，跨机器同步、不入 git；
2. 根级：`.personal-manifest.json`、README、`memory/`、`projects/<slug>/`；
3. 项目级固定目录：业务 10（memory/learning/inbox/meetings/deliverables/output/research/schedule/plugins/infrastructure）+ 治理 3（experience/staging/archive）+ 配置 2（preset/custom）+ 工具白名单 2（.agents/.codex）；
4. `.project-state.json` 记录 repo/版本/绑定/同步时间；
5. `doctor` 校验：缺失/多余/命名/哈希/state，exit code；
6. `init` 幂等补建缺失目录，不删除、不移动用户文件；命名规则强制（事件文件日期前缀）。

**验收**：删除某固定目录后 init 自动补建；顶层放未约定文件 doctor 报 unexpected；preset 哈希不符报 tampered。

### FR-12 配置分层（preset / custom）

**要求**：

1. 中央 `presets/<name>/` 存预设，bootstrap `presets` 有序声明（后者覆盖前者）；
2. 个人 `preset/<name>/` 只读 + `.preset-manifest.json`（来源/版本/文件清单/sha256）；
3. 个人 `custom/` 存用户后加配置，升级永不覆盖；
4. `config` 输出合并生效配置，逐项标注来源；preset 打底 custom 同名覆盖；
5. 冲突（preset 文件被改/哈希不符）→ 保留 `.local` 副本并提示，不静默覆盖。

**验收**：升级后 custom/ 内容不变；改过 preset 文件再升级出现 .local 与提示；config 能追溯每个配置项来源。

### FR-13 统一通用化升级路线

**要求**：

1. 所有候选源（ai-config 拆解、本地自定义角色、外部导入、本地演化成果）统一进 `staging/`；
2. **自动打标**：规则 + LLM 输出「通用候选/个人特有/待人工」标签与理由；
3. **台账** imports-registry：来源、标签、状态、版本、文件哈希，可追溯；
4. **人工复核**：周期 LLM 初筛 + 人工确认（并入定期分析）；
5. **转正**：通用者入中央 packs/（人审 tag、全景图更新）；个人者留 experience/archive/custom；
6. **ai-config 内容级重新拆解**：逐项分析能否再拆出通用模板/个人配置，不整体二分。

**验收**：导入一批混合资产后台账正确分类；通用候选复核通过后进入 packs 并打 tag；纯个人项不产生 PR。

### FR-14 同源一致性

**要求**：

1. 全景图生成器与评分/统计函数是仓库 `mcp/pack-manager` 的一部分，随 clone/upgrade 分发；
2. CI 与本地执行**同一份脚本、同一 tag 版本、同一统计口径**，禁止本地另写生成器或统计规则；
3. 中央视图与本地视图的差异只能来自输入数据（中央=合并请求与全量台账；本地=个性化信息与技能加成）。

**验收**：对同一份数据集，CI 与本地生成结果一致；本地仅在数据不同时结果不同；不存在第二套统计实现。

### NFR 安全 · 隐私 · 性能

| 类别 | 要求 |
|---|---|
| 供应链安全 | 升级/安装预置 MCP 前验哈希/签名；人审发布 = 最终信任锚 |
| 隐私 | 只上报聚合指标，不带原文/敏感内容；日志保留窗口后删除 |
| 性能 | 上下文只放索引与规则，正文按需拉取；防上下文爆炸与 tmp 膨胀 |
| 可审计 | PR/台账可追溯：谁打分、打哪版、候选来源、复核人 |

## 4. 验收总入口

1. `git clone` → 按 FR-2 初始化（含预设同步）→ 汇报含版本号（FR-5）；
2. 各动作词全部命中预定义流程（FR-3）；
3. 制造版本差异 → check_update / upgrade 符合 FR-4；
4. 日志 PR（含非法字段）被 schema 门拒绝；合法日志免审合并（FR-8）；
5. 混合资产导入 → staging 打标/台账/复核/转正全链路（FR-13）；
6. doctor 对缺失/多余/命名/哈希逐项检出；init 幂等补建（FR-11）；
7. config 合并可追溯；升级不覆盖 custom、冲突出 .local（FR-12）；
8. 同一数据集 CI 与本地生成一致（FR-14）；
9. 打 tag → Pages 更新；本地手动生成全景图（FR-9）；
10. 系统 tmp 不再增长，runtime/ TTL 生效（FR-7）；
11. 全仓无无效测试代码、无失效门禁（FR-10）。

## 5. 关键约束与决策记录

- 中央仓库 = 本项目仓库；bootstrap 极简，其余靠规约发现；
- 内部核心链路**直连**（无 MCP server）；对外保留薄 MCP 适配器；
- 一条统一升级路线覆盖所有候选类型，新增类型复用同一机制；
- 个人目录 个人存储强制规约 + doctor；配置 preset/custom 分层；
- 生成脚本与统计规则同源，中央/本地差异仅数据；
- 版本可见性强制（FR-5）；单次全量交付，不分阶段。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 自动打标准确率不足 | 标签必附理由 + 台账留痕 + 人工复核兜底（FR-13） |
| 免审合并被滥用 | schema 校验门真实生效（FR-8/FR-10） |
| 本地定制被升级覆盖 | lockfile/override + custom 隔离 + .local 冲突保护（FR-4/FR-12） |
| 中央/本地统计口径漂移 | 同源脚本随 tag 分发，禁止第二套实现（FR-14） |
| 部署配置的个人目录结构腐化 | doctor 周期校验 + init 幂等（FR-11） |
| 评分噪声/刷分 | 最低样本量 + 异常分剔除（FR-8） |
