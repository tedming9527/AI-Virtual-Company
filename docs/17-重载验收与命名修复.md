## 可复用的命名修复

doctor 对 inbox 根级事件文件要求日期前缀。已有 JSON 事件有明确 `created_at` 而文件名漏前缀时，可使用：

```sh
# 默认仅预览，不创建备份或更改资料。
python3 scripts/repair_inbox_event_name.py \
  --personal-project '<已有用户资料项目>' --file event.json

# 用户授权后应用同一项修复。
python3 scripts/repair_inbox_event_name.py \
  --personal-project '<已有用户资料项目>' --file event.json --apply
```

工具仅接收 inbox 中单个 JSON 文件名，从明确的 ISO `created_at` 取日期；不猜测文件时间，不修改正文、事件身份、归属或升级状态。应用时复用个人资料锁和保全代码，先将原文与摘要登记在 `staging/naming-repairs/`，独占创建新名称，核验两端内容后才移除旧名称。源与目标位于同一 inbox，文件系统须支持硬链接；不支持时保留原文和备份并报错。

路径逃逸、符号链接、目标已存在、日期缺失或无效、来源在保全过程变化均拒绝移动。目标竞争也不能覆盖另一写入者。中断或验证失败时保留资料及保全回执，须核对剩余名称后处理，不能把预备回执说成已完成。

改名后重新运行 doctor，并刷新本地全景图等生成视图；未知来源与历史审计不自动清理。当前候选治理账本位于 `experience/.avc/`，不能因 inbox 中有同名文件就移动治理账本或更改生命周期归属。

## 契约告警的修正方式

本次告警源于诊断问答工具漏列在精确工具集合中，第一次 shell 探测也早于任务登记。修正是业务工具前固定完整且有界的契约，按实际原生名字声明需要的工具：例如 Codex 终端为 `Bash`，异步问答为 `request_user_input_async`。只读 Ted 诊断仍可不另开文件交付任务。

这不是放开全局白名单。不要通配所有工具、事后扩大已固定契约、清除历史违反，或为了测试而给用户新增无意义问题。原生平台权限与审批继续生效。问答工具未在本轮重复调用时，只能声明名称核对及本轮真实调用无违反，不能伪造问答重放证据。

## 回归覆盖

新命名修复测试覆盖默认只读计划、保全和内容摘要一致、doctor 命名告警消失、重复执行、无效日期/路径、符号链接、目标覆盖、并发目标竞争及保全时源变更。严格契约与 Hook 失败非阻断的现有回归继续运行；线上事件证据与隔离测试分别报告。

## 监控模式的任务待关联状态

事件采集成功而尚未登记任务是正常过渡状态。当前源码将其表示为 `pending-task`，同时保留 `captured=true`、`taskStatus=pending`、`taskVerified=false`；采集入口与状态伴随入口均正常退出。状态查询单独统计 `pendingTaskEvents`，不生成任务、角色、工具成功或署名验证回执。该事件数是历史观察量，不代表仍有同样数量的待处理任务。

配置读取、权限、锁冲突、存储和真实署名故障继续明确告警；独立执行限制不因此放宽。回归应走安装器生成的真实 Hook 程序及状态伴随程序，检查未登记→已登记的转换和错误路径，不能只断言配置写入。源码修正不代表已发布或已安装。
