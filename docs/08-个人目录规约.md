# 08 · 个人目录规约（约定大于配置 · 强制）

> 中央仓库定义通用架构；**用户端个人目录同样受「约定大于配置」强制指导**。
> 个人目录由部署期存储配置定位，可选择 iCloud 等同步目录，不入 git；由 pack-manager 的 `doctor` 命令校验、`init` 幂等补建。

## 1. 定位与原则

| 原则 | 说明 |
|---|---|
| **跨机器同步** | 跨设备部署应选择已配置的同步存储；本机 runtime 回退不提供跨设备恢复 |
| **与中央仓库物理隔离** | 个人数据不进 git、不混入中央仓库；中央仓库只通过 `preset/`（只读）下发预设 |
| **目录即契约** | 固定目录集合 + 固定命名；固定目录之外自建 = 违规（doctor 标记） |
| **工具维护骨架** | manifest/state 由工具读写；`init` 只补建缺失目录，**不删除、不移动用户文件** |
| **可治理** | 导入资产进 `staging/`，非通用经验进 `experience/`，历史只读进 `archive/` |

## 2. 位置

`storage.personal` 必须指向 `<personal-root>/projects/<slug>`，`storage.memory` 可指定记忆目录。中央 `bootstrap.json` 保留通用声明，不记录真实个人路径。

部署路径的覆盖顺序为：`bootstrap.storage` → 本机 `runtime/storage.json` → 环境变量 `AVC_PERSONAL_DIR`、`AVC_MEMORY_DIR`、`AVC_ICLOUD_ROOT`。本机配置被 Git 忽略，升级中央清单不覆盖它。

`icloud://<root>/projects/<slug>` 仅在显式配置可用的 `icloudRoot` 或 `AVC_ICLOUD_ROOT` 后解析；不可用即报错，不静默写入另一个位置。未配置任何个人存储时，只使用 `runtime/personal/projects/<bootstrap.name>` 做本机临时验证，并提示该限制。`doctor`、`config` 的解析不创建目录；`init` 才补建骨架。

配置示例（路径占位符需由部署者替换）：

```json
{"personal": "<personal-root>/projects/demo", "memory": "<personal-root>/projects/demo/memory"}
```

## 3. 根级结构

```
<personal-root>/
├── .personal-manifest.json      # 个人目录清单（版本/创建时间/项目列表）
├── README.md                    # 本规约的人类可读说明（工具生成）
├── memory/                      # 全局记忆（跨项目共享的偏好/画像）
└── projects/
    └── <slug>/                  # 每个中央仓库项目一个目录，slug = 仓库名
```

`.personal-manifest.json` 字段：

```json
{
  "schemaVersion": 1,
  "createdAt": "2026-10-12T00:00:00Z",
  "projects": [{ "slug": "demo", "repo": "github://owner/demo" }]
}
```

## 4. 项目级结构（projects/&lt;slug&gt;/，强制）

```
<slug>/
├── .project-state.json          # 项目绑定与版本状态
├── memory/                      # 项目记忆（会话纪要、决策、画像）
├── learning/                    # 学习/评测记录
├── inbox/                       # 待处理输入（待整理素材、待办捕获）
├── meetings/                    # 会议纪要/录音转写
├── deliverables/                # 交付物（对外提交的成品）
├── output/                      # 工作输出（中间产物、草稿）
├── research/                    # 研究资料
├── schedule/                    # 日程/计划
├── plugins/                     # 个人插件/扩展
├── infrastructure/              # 本机环境信息（网络/设备/服务配置）
├── experience/                  # 非通用型经验清单（本项目特有，不回传）
├── staging/                     # 导入暂存（自动打标 + 台账，待人工复核）
├── archive/                     # 只读归档（历史快照、退役资产，不参与活跃扫描）
├── preset/                      # 中央下发预设（只读 + .preset-manifest.json + sha256）
├── custom/                      # 用户自有配置（升级永不覆盖）
├── .agents/                     # 其他 agent 数据（白名单）
└── .codex/                      # Codex 数据（白名单）
```

### 固定目录分类

| 类别 | 目录 |
|---|---|
| 业务数据（10） | memory · learning · inbox · meetings · deliverables · output · research · schedule · plugins · infrastructure |
| 治理（3） | experience · staging · archive |
| 配置分层（2） | preset · custom |
| 工具白名单（2） | .agents · .codex |

`.project-state.json` 字段：

```json
{
  "slug": "demo",
  "repo": "github://owner/demo",
  "currentVersion": "1.1.0",
  "lastBootstrap": "2026-10-12T00:00:00Z",
  "lastSync": "2026-10-12T00:00:00Z"
}
```

## 5. 命名规则（强制）

- 目录：kebab-case（`research/`、`backend-notes/`）；
- 事件型文件：`YYYY-MM-DD-<topic>` 前缀（如 `2026-10-12-架构讨论.md`）；
- `archive/`、`staging/` 内文件不参与活跃扫描；
- 固定目录内允许自由组织子目录；**固定目录之外新建顶层目录/文件 = 违规**。

## 6. preset / custom 配置分层

```
中央仓库 presets/<name>/  ──init/upgrade──▶  preset/<name>/（只读）
                                                 ▲ 打底
用户自有配置 ───────────────────────────────▶ custom/（升级不覆盖）──▶ 覆盖同名项
```

- `preset/<name>/.preset-manifest.json`：来源、版本、文件清单、sha256；
- 升级后哈希不符（用户改过 preset 文件）→ 保留为 `.local` 副本并提示，不静默覆盖；
- `config` 命令输出合并后的生效配置，逐项标注来源（哪个 preset / custom）。

## 7. staging 导入治理（统一通用化升级路线）

所有外部/候选数据（ai-config 拆解内容、本地自定义角色、其他工具导入、本地演化成果）统一进入 `staging/`：

```
候选数据 → staging/ → ① 自动打标（通用候选/个人特有/待人工，附理由）
                    → ② imports-registry 台账（来源/标签/状态/版本/哈希）
                    → ③ 人工复核（周期 LLM 初筛 + 人工确认）
                    → ④ 通用者转正入中央 packs/（人审 tag）；个人者留 experience/archive/custom
```

## 8. doctor 校验规则

`doctor` 对 `projects/<slug>/` 输出问题清单并以 exit code 表示结果：

| 检查 | 判定 |
|---|---|
| 固定目录缺失 | missing（init 可自动补建） |
| 顶层出现未约定目录/散落文件 | unexpected |
| 事件文件无日期前缀 | naming |
| preset 文件哈希与 manifest 不符 | tampered |
| .project-state.json 缺失/字段不全 | state |
| 业务目录被误当配置目录混用 | layout |

规则：`archive/`、`staging/` 不参与活跃扫描；`doctor` 只报告与（经授权的）修复，不擅自删除。

## 9. 多项目支持

- 每个中央仓库项目在 `projects/` 下各占一个 `<slug>/`，互不干扰；
- 全局共享内容放根级 `memory/`，项目私有内容放项目级 `memory/`；
- 绑定新项目：`bind github://owner/repo` → 注册 manifest + 创建项目骨架。
