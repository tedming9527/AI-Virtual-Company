# 客户端初始化重建设计

状态：代码已实施，2026-10-14 已执行真实 Codex 环境重建。用户资料摘要、文件清单和原生 MCP 调用已核验；原生生命周期事件与锁冲突非阻断测试已有证据；用户已确认橙色状态、具体错误说明和任务继续同时成立。MCP 重载后，正常任务登记、资料加载、工具采集、任务收尾及本轮 Stop 均已有原生证据，本次 Codex 接入验收通过。

## 不可变规则

1. 数据采集、审计、署名、统计不能阻断已授权业务任务。失败只提示风险、证据缺口与修复事项，不要求先修复、记账或重试才继续，也不伪造成功回执。
2. 用户数据初始化只增量补齐用户资料；中央下发的受管副本按来源清单更新，中央废弃时移除；自定义资产与已升级为用户所有的资料不跟随中央删除。
3. 客户端初始化第一步全量重建本项目管理的规则、配置、技能、MCP、Hook 和运行环境，不做差异合并，不继承旧版本的配置项或遗留文件。
4. 第二步才按需导入用户技能等资产。导入是客户端副本，必须登记来源、目标、内容摘要与所有权；用户源数据不变。
5. 清空前按来源与摘要剔除可重新下发的中央/用户副本，再保全客户端独有资料。保全不改变归属；重建后恢复到客户端独立工作区，仍为未升级，不自动启用为规则/技能。尚未保全的唯一副本不能删除；保全失败只暂停破坏性重置，业务继续。
6. 下放线路为中央仓库 → 用户数据中心中央受管区 → 客户端；反向升级为客户端 → 用户资料 → 中央仓库。升级必须由代码计算源/目标 hash、登记映射和回执，模型声明不能改变归属。中央候选未经发布核验不得标记升级成功。
7. 确认废弃且无有效迁移版本的资料，其观察数据、评分、趋势与建议一起清理；路径搬迁或读取故障不是废弃。日志统计不等于资料升级。

## 审计发现

- 原安装器把部署配置放在项目 runtime 中，再将绝对路径写入客户端 Hook。项目搬迁后，旧路径失效。
- 原执行 Hook 将无法读取部署配置转为 PreToolUse 拒绝，影响了不属于该项目的业务工具；原 Stop Hook 还会因署名失败强制续跑或停止。
- 现有客户端更新脚本顺带调用用户数据 init；技能使用目录合并复制，删除于新版本的文件仍可能残留；同名 Hook 只按原部署路径替换，迁移后可能叠加；旧版兼容转发器仍可继续生效。
- 本机还存在旧生成式全局规则，引用已不存在的初始化脚本和目录。只换技能目录不足以完成重建。
- 管理器已具备文件监听与五秒库存轮询；这是发现与摘要记录，不是所有新资料的持久同步。周度整理是会话触发的独立流程，不等于常驻定时归档。
- 已打开的会话可能缓存旧指令、技能清单、MCP 和 Hook 定义；磁盘清理不等于内存上下文已清理。

## 三个独立数据域

| 数据域 | 内容与位置 | 初始化策略 |
| --- | --- | --- |
| 中央仓库 | 通用规范、包、模板、安装器、版本清单 | 按发布版本提供输入，不保存用户私有资料 |
| 用户数据 | 自定义技能、经验、知识、课题资料、交付物、恢复候选；用户明确指定的 personal 项目目录 | 增量补齐、保留已有内容，不依赖某个客户端是否安装 |
| 客户端环境 | 客户端规则入口、受管技能副本、MCP/Hook 注册、部署配置、运行态与审计 | 按平台规范存放；Codex 使用 CODEX_HOME，默认 ~/.codex；重建受管范围，不把它塞入 personal |

项目真实路径、用户数据路径和客户端目录是三个独立绑定值。配置不得靠旧 iCloud 地址或扫描目录名猜测。客户端绑定失效时提示修复；不能退回到未知目录写数据或阻断普通业务。

## 所有权与防残留设计

每个安装代次产生一份可验证清单，至少包含：

- 代次 ID、公司包版本、来源提交、平台和安装状态。
- 公司资产文件的完整相对路径、摘要与来源；明确哪些文件是生成物。
- 用户导入副本的来源资产 ID/摘要、客户端目标位置、导入时间与基线摘要。
- 共享配置中的受管项目：规则块标识、MCP 服务 ID、Hook 标记、技能目录名称、启动器。
- 客户端产物允许写入的专用目录，以及临时事务位置。
- 资产保全回执、上一代清理结果、新代校验和客户端实际加载结果。

文件只能落在平台规定的专用命名空间或已登记的精确入口。共享配置只能替换本项目拥有的块，不能清空整个 CODEX_HOME、其他插件、账号、聊天历史或用户手写配置。不接受清单任意指定删除路径；路径必须同时通过平台允许位置、受管命名空间、真实路径及所有权校验。

清理依据是“上一代清单 + 受管命名空间实盘枚举 + 已知历史入口迁移表”，不能只遍历新版文件。实盘中新增的文件也要分类，防止未入清单的文件漏删。旧生成式全局规则、旧服务别名、旧 Hook 命令和兼容转发入口必须纳入迁移核对；无法确定归属时标记待处理，不删除未知文件，也不声称零残留。

安装器和用户资产导入器使用同一写入登记入口。导入器禁止任意目标路径、路径穿越和符号链接逃逸。源目录只读，导入副本统一处于本项目命名空间；下次初始化不论有无改动，旧副本均退出当前客户端环境。

“本项目可管理资产零残留”是验收范围，不能宣传为清空模型服务端记忆或宿主全部历史。平台无法清除的旧会话上下文需要结束旧会话、重新加载并用新会话验收。

## 重建顺序

### 0. 只读预检与清理前保全

解析三个数据域、当前真实版本、完整受管清单和历史入口。确认新版本包完整、独立运行可用、用户目录存在、目标目录可写；此处不隐式初始化用户资料。

相对上次安装/导入基线分类：

- 公司生成物未改动：按当前版本重新生成。
- 用户导入副本未改动：用户源已存在且摘要可核验，清除客户端副本即可。
- 本机新建或修改的技能、经验、候选知识、规则草稿及不能重建的资料：增量保存到用户 staging/client-recovery 中的独立批次。
- 缓存、依赖与可重建输出：按明确分类清理，不能仅凭扩展名或目录名把未知资料当缓存。
- 审计事实：按审计保留策略保全需要保留的记录，不将历史事实作为新一代已验证回执。

恢复批次记录来源与目标摘要、原始归属、升级状态、资产分类、操作 ID 和待复核状态；保全不得改为用户所有；不覆盖用户现有文件、不自动转正、启用或发布。复制后校验目标摘要，再复查源未变化。已有同摘要归档可幂等复用。失败保留原物及恢复记录。

定期扫描用于减少积压，重置前强制扫描用于避免两次扫描间的新增内容丢失，两者不可互相替代。扫描器故障不能停业务；只有未保全资料的删除不能执行。

### 1. 全量重建公司客户端环境

在客户端本地暂存位置生成完整新代，再进入短时、可恢复的切换事务：

1. 取得同一客户端的初始化互斥锁；检测受管写入者和未完成任务。不能在仍有写入时删除其目录，不强行停止业务会话来凑初始化成功。
2. 固定清理前快照并保存保全回执；停用旧受管入口，防止切换过程中继续写旧环境。
3. 清除旧代全部受管文件、用户导入副本、已废弃配置项与旧引用，随后安装完整新代，再将已剔除下发副本的客户端独有资料恢复到独立未升级工作区。不能使用合并复制，也不能保留“以后可能还用”的兼容入口。
4. 对共享配置原子替换本项目所属块，保留其他内容。原生审批与 Hook 信任走平台机制，不能自行伪造信任或用安装成功代替宿主加载。
5. 核对实盘与新代清单完全一致，受管共享入口精确且唯一；确认已无旧路径、旧服务别名、旧版本文件与导入副本。

临时回退副本只能留在事务隔离区，不作为客户端的技能或配置发现入口；成功后清除。崩溃或失败必须给出明确事务状态并可恢复，不能将新旧文件混杂标记为成功。清理和重建过程不复制个人源资料回公司中央包。

### 2. 按需导入用户资产

第一步校验成功后，独立选择并校验用户资产。为每个资产生成新导入副本、写入所有权清单与基线摘要，再检查客户端实际发现结果。没有选择资产时，保持纯公司基线，不自动重放上次导入清单。

导入失败报告该资产未激活，不恢复旧副本，也不改用户源数据。运行中副本发生变化只能形成新候选，不能自动覆盖用户的正式版本。

### 3. 重新加载与原生验收

区分“文件准备成功”“配置写入成功”“宿主重载成功”和“新会话实际生效”。核验当前规则入口、技能清单、MCP tools/list、Hook 原生事件以及非阻断故障回归；未重载的旧会话保持未验收状态。

2026-10-14 原生验收结果：受管环境已真实重建 6 次，当前配置为 6 个采集/详情 Hook 与 6 个只读状态 Hook。用户已在宿主信任并启用新增状态处理器，并明确确认“看到了橙色状态和具体错误说明，任务也正常继续”。告警显示与锁冲突非阻断验收通过；采用同事件两条关联记录共同呈现，不是单条彩色详情。

最新真实故障测试在采集锁被占用时完成业务命令，退出码为 0，测试锁已清除。采集证据保持未验证，不因业务成功伪造采集回执。15 项客户端事务与适配器测试通过，涵盖六类处理入口、正文与状态分离、避免重复采集、结果缺失以及异常退出不得转成阻断。

本代原生 SessionStart 已在桌面派生临时会话中记录；正常 Stop 有 `footer_verified` 和主会话 completed 证据。临时会话另有 `footer_unverified` 后的宿主 turn/completed 日志，但无持久转录；不能扩展为所有启动方式均验证。当前规则和 UserPromptSubmit 上下文也已在会话中出现。

最终显示标准为：橙色状态与具体警告说明同时可见；说明包含失败/未验证、具体原因、任务继续和修复事项。历史上“仅退出码有颜色”“仅结构化正文无颜色”的两轮方案均不作为最终通过方案。用户确认、原生业务退出码和故障恢复记录共同构成证据，不能只靠模型说明。

重载后的最终原生验收已通过：目录查询与 task_begin 成功，绑定加载测试资料并记录 SHA-256，普通工具产生真实 Pre/Post 响应摘要，task_closeout 返回 closed、零违规、零未观测调用并登记产物摘要；同一回合 Stop 为 footer_verified，宿主回合状态为 completed。Hook 未提供的退出码仍记 unknown，命令退出 0 由宿主执行记录单独证明，不补造缺失字段。此次通过范围限已记录的 Codex 环境和链路。

逐项本机证据保存在 `runtime/cache/client-rebuild-acceptance.json` 的 `currentAcceptance`；历史尝试按其原始代次保留。本次只更新验收结论，不为记录变更重复破坏性重建。其他平台、常驻扫描调度、模型服务端历史清理和发布不在本次验收范围内。

## 多次升级必须通过的回归

| 场景 | 验收 |
| --- | --- |
| A → B → C，删除/重命名包文件、配置项、服务 ID | 新代仅有当前清单，旧内容与引用均消失 |
| 同版本连续初始化 | 完整重建，清单稳定，不增加重复 Hook 或 MCP |
| 导入用户技能 → 修改副本 → 再初始化 | 修改内容先归档，旧副本清除，用户源摘要不变 |
| 新建未登记文件、清单丢失/损坏 | 不漏查；无法确认保全或所有权时不删除、不报成功 |
| 项目搬迁、配置丢失、目录不可写、锁冲突 | 采集只告警，业务工具与正常结束仍可继续 |
| 扫描间隔内新增资料、iCloud 暂不可用 | 重置前扫描发现；保存失败不删唯一副本 |
| 归档中断、替换中断、并发初始化、运行中写入 | 事务可恢复，无假成功、无跨代混装、无丢失 |
| 符号链接、路径穿越、同名非受管资产 | 不越界读写或删除；显式报告归属冲突 |
| 其他客户端/插件/用户手写配置存在 | 不受受管重建影响 |
| 旧会话缓存与新会话 | 分别记录，不把磁盘版本当实际加载版本 |

## 实施边界

按“平台中立清单与事务协议 → Codex 适配器 → 用户导入器 → 旧入口迁移 → 连续升级及宿主验收”实施。先在隔离客户端目录验证，之后才在用户授权的真实客户端执行完整重置。其他平台需各自实现规定目录、注册方式和加载验证，不能机械复制 Codex 路径或权限策略。

本轮不新建定时任务，不宣称扫描/归档在当前客户端已启用；这些状态必须由真实进程、调度记录与成功归档回执分别证明。

## 已实现的代码入口与边界

- `python3 scripts/client_environment.py rebuild --personal-project <已有用户项目目录> --codex-home <客户端目录> --node <Node 22+ 的真实路径>`：不执行用户资料 init，不拉取/合并 Git。中央内容先生成用户中心专用 distribution，再生成客户端；`--migrate-legacy` 仅迁移经过身份/摘要核验的历史入口。未识别的来源保持待核对。
- `recover`：恢复中断的切换事务。配置完整备份仅在客户端本地事务区，成功后删除；不会把可能含凭据的完整共享配置复制到用户同步目录。
- `python3 scripts/asset_lifecycle.py import-user --source <personal/custom 内的 skill> --personal-project <目录>`：独立第二阶段，登记用户来源、版本、摘要与客户端目标，不重放上次导入。
- `promote-user --path <客户端独立工作区相对文件> --name <资产名> --authorization-ref <授权引用>`：核验未升级候选，计算源/目标摘要，复制到用户 custom/materials 的不可变修订目录，代码登记回执后才改变身份。日志审计不能走普通资料升级。
- `propose-central --asset-id <用户资产 ID> --authorization-ref <引用>`：验证用户源未变并冻结中央候选，不写入中央 packs，不声明升级完成。
- `register-central-release --proposal <候选目录> --central-root <中央仓库> --pack-path <packs/type/name> --tag <已评审发布 tag> --review-ref <评审引用>`：读取实际 Git 发布内容逐文件核验 hash、核对版本/身份、登记用户 → 中央回执；候选提交本身不构成成功。授权/评审引用是本地操作者的声明，不能冒充平台认证身份或独立人审证据。

受管客户端路径固定为 CODEX_HOME 下的 `ted-avc-manager/`、一个桥接技能、显式导入命名空间及共享配置中的精确入口。Hook 外层有五秒子进程超时、失败 JSON 告警及阻断字段拦截；原生沙箱与审批不变。初始化互斥锁、活动写入租约、未完成任务检查和代次校验用于避免并发覆盖与旧进程继续写入。

新代清单记录静态文件、桥接文件、资产版本/内容摘要、下发来源、用户导入与恢复回执。确认从完整分发清单删除的资产版本，其观察事件、汇总与建议在重建时剔除；读取失败不生成删除判定。审计放历史区，不恢复为当前回执；库存索引可重建，不作为独有资料恢复。客户端独有材料放独立工作区，只有显式升级入口能改变其归属。

当前升级入口支持单文件及有完整 meta 的资产目录；`scan-client` 重新计算独立工作区摘要，生成未升级候选。原有个人 skill 通过独立导入器管理。未知旧格式、未登记来源和宿主目录之外的文件不自动认领。现有周度整理、日志保留窗口与新观察清理是不同机制：本次未添加常驻调度，也未声称完成独立的人审或模型服务端历史清理。

验证包含连续 A/B/C 与同版本重建、删除中央文件、修改用户导入副本、晋升后再次重建、源目录 hash 不变、中断恢复、并发锁、符号链接/未知归属、活动任务保护、运行时路径隔离、Hook 缺配置/超时/错误阻断输出、MCP 直接握手，以及已发布内容的反向升级登记。真实安装结果及诊断证据保存于仓库本地 runtime/cache，不进入公共发布材料。

恢复事务仅回收已证明退出的写入者锁；共享配置或受管目录在中断后发生额外变化时，拒绝用旧备份覆盖。资料废弃清理同时处理受管历史观察副本与结构化周度汇总，按原摘要核验后修改；未知格式不通过文字猜测删除。
