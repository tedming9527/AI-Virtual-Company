# 01 · ted-avc-manager 架构总览

本平台既管理 skill / knowledge / framework / role 四类资产的生命周期，也通过平台适配器参与资产加载和任务执行。目录或规则存在、模型获得正文、工具真正受检查、产物符合业务要求是不同状态，分别取证。

## 分层与控制点

| 层 | 职责 | 可核验的输出 |
|---|---|---|
| 中央资产 | 发布通用包、中文专业身份、规则、预设、版本 | 已发布 tag、包 meta、正文摘要、CI |
| 本地资产 | 个人 custom、记录、经验、候选、外部技能发现 | 来源、版本、登记摘要与变更记录 |
| 发现与上下文 | MCP 元数据、原生 bridge skill、选定正文交付 | 发现索引、load_asset 回执；交付不证明理解 |
| 执行介入 | 任务绑定、允许工具、预算、资产漂移、结果观察 | 原生 PreToolUse 拒绝/准入、PostToolUse 事实 |
| 交付与演进 | 产物核验、署名、问题候选、PR、发布与本地更新 | task_closeout、Stop、候选 PR 与更新回执 |

执行层契约、实际 API、可见性与限制见 [11 · 执行介入架构](11-执行介入架构.md)。发现及使用追踪见 [12 · 资产发现与使用追踪](12-资产发现与使用追踪.md)。这些本机适配器不自动激活受保护中介层候选，也不能接管宿主不可见的模型请求或内部推理。

## 执行主线

```text
用户当前授权与项目绑定
  → 原生 SessionStart / UserPromptSubmit：版本、角色、资产索引、真实回合标识
  → task_begin：选择专业岗位，读取 PROFILE 全文，固定资产摘要与工具合同
  → list_assets / find_skill / recommend_assets：发现相关资产
  → load_asset：使用前明确交付选定正文；固定来源、版本与摘要
  → PreToolUse：原生会话/回合、合同、名单、外层次数预算与资产漂移检查
  → 宿主实际执行工具：保留平台沙箱与用户审批
  → PostToolUse：观察真实返回与可见退出码，缺失事实保持 unknown
  → task_closeout：调用观察分类、真实产物 SHA、实际执行者与完整性
  → Stop：最终输出的版本、中文名字·职业与回合回执校验
  → 问题/技能升级候选：复核 → PR → 人审发布 → tag/CI → 本地更新
```

模型的使用推荐或自报属于提案/声明；只有管理器正文交付、受支持读取工具的真实事件或平台加载回执，才可计为相应观察事实。新文件进入本机技能目录时，发现扫描与变化监听维护库存，不能将“已发现”直接计为“已安装/已加载/已使用”。

## 三类存储与数据边界

| 存储 | 内容 | 规则 |
|---|---|---|
| 中央仓库 | 通用 packs、presets、引擎、文档和公开产物 | 可发布，不含机器路径、个人正文、凭据和本机配置 |
| 个人目录 | memory、learning、inbox、deliverables、custom、experience、staging、archive 等 | 升级不覆盖 custom；外部资产先 staging 复核 |
| runtime | 索引、缓存、lockfile、技能登记、执行/Hook 回执、本地全景图 | 本机临时状态；不是不可改写的管理员账本 |

存储覆盖顺序与骨架规约见 [08](08-个人目录规约.md)。中央目录版本 catalogVersion 与本机引擎 engineVersion 单独记录，升级引擎不暗中改写已锁定的项目资产。

## 两种全景图、同一渲染器

本地视图包含通用包、个人分类文件、自定义包、外部技能发现、登记状态、生效配置来源和执行观察摘要，输出 `runtime/panorama/`。通用视图仅从干净的已发布 tag 扫描通用包，并从公开 GitHub API 采集固定 base/head SHA 的候选 PR，输出 `panorama/`。PR 候选、个人暂存、历史资料均不计入已发布包。

通用生成路径在读取 storage、personal、custom、私人 scores 之前结束数据收集。CI 在 tag、候选 PR 状态变化或手工触发时重新生成；pull_request_target 仅检出已发布 tag，绝不检出或执行 PR 代码。详见 [06](06-全景图管线.md)。

## 当前能力边界

| 能力 | 实现范围 | 不可外推 |
|---|---|---|
| init / check / upgrade | 包发现、骨架/预设同步、版本账本 | 独立客户端安装、全上下文加载、跨设备恢复仍需实际验收 |
| 模块加载 | 明确选择的正文交付与摘要 | 不能证明模型理解、所有原生隐式加载或技能语义执行 |
| 执行 Hook | 宿主实际暴露的工具事件、精确工具名单及外层调用数 | 用户可关闭；一个 exec 可含多条命令；不是 token/成本或管理员安全边界 |
| 反馈 | 本地候选、可审查 PR、明确授权发布 | schema/分数/目录状态不能代替用户批准或自动合并 |
| 版本更新 | tag、下载提交核对、安装与运行时重载证据 | 签名/可信发布器、统一模型配额和全平台监督仍是单独能力 |

原有受保护中介层文件保留为候选，[BOOTSTRAP](../packs/framework/company/intermediary/BOOTSTRAP.md) 不因本机 Hook 安装而自动获得管理员控制权。部署必须逐项说明支持的事件、不可见部分、观察与强制模式及其验收证据。
