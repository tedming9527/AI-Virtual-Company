# 01 · 架构总览

## 1. 一句话定位

**多类型 AI 技能包的生命周期平台**——中央定义分发、本地自演化、统一升级路线、人审治理、持续改进闭环。
`skill` 只是其中一类包，还包括**专业知识**、**框架规则**、**专业角色**；技能包不一定是 skill。

## 2. 四层模型

| 层 | 载体 | 内容 | 类比 |
|---|---|---|---|
| **L1 中央包仓库** | GitHub | 通用技能 / 专业角色包 / 框架 / 规则 / 预设，语义化版本管理，可扩展；**目录规约**（约定大于配置） | eslint preset / npm 生态 |
| **L2 接入/命令层** | 命令协议 + 大模型 | `github://` 命令 → 三层解析 → 预定义 skill 流程；大模型作为执行端 | 命令协议 / skill 触发 |
| **L3 本地运行时** | mac | Agent 中介层：初始化、分层注入、编排、回传；本地记忆 / 技能 / 等级；doctor 校验 | agent 运行时 |
| **L4 回传/治理层** | 统一升级路线 + PR + 台账 | 自动打标 → 台账 → 人工复核 → 转正；使用日志（免审）与晋升申请（人审）；评分台账、周期改进 | 开源插件市场 + 治理 |

## 3. 三类存储（架构的物理边界）

| 存储 | 位置 | 内容 | 性质 |
|---|---|---|---|
| **中央仓库（通用）** | GitHub `AI-Virtual-Company/` | packs/（四类包）、presets/（预设）、mcp/、docs/、rules/、scripts/、platforms/、templates/ | 唯一事实源；版本化 tag；跨机器拉取 |
| **个人目录（个人）** | 部署配置的 `<personal-root>/` | memory、learning、inbox、deliverables、experience、staging、preset/custom 等 | 跨机器同步；不入 git；**受强制规约**（见 [08](./08-个人目录规约.md)） |
| **运行时（临时）** | 本地 `runtime/` | cache、logs、lockfile、scores | 不写系统 tmp；TTL 清理；可删除 |

> 仓库内相对引用个人目录：通过存储解析器定位 `<personal-root>/projects/<slug>/<dir>`，不在通用模板中硬编码相邻个人目录。

## 4. 统一通用化升级路线（核心机制）

**所有「通用型候选数据」——技能、知识、角色、配置，无论来自 ai-config 内容拆解、本地自定义角色、外部工具导入还是本地演化——统一走同一条通道：**

```
候选源 → staging/ → ① 自动打标（通用候选/个人特有/待人工，附理由）
                  → ② imports-registry 台账（来源/标签/状态/版本/哈希）
                  → ③ 人工复核（周期 LLM 初筛 + 人工确认）
                  → ④ 转正：通用者入中央 packs/（人审 tag）；个人者留 experience/archive/custom
```

- **ai-config 保留但内容级重新拆解**：逐项分析能否再拆出通用模板与个人配置，不做整体二分；
- **本地可自定义角色**：个人角色作为候选源进 staging，通用化后可转正为 `packs/role/`；
- 该路线统一了此前分散的「导入治理 / 晋升 PR / 非通用剔除」三套机制。

## 5. 四大循环（共用一个版本账本：tag）

| 循环 | 方向 | 机制 | 作用 |
|---|---|---|---|
| **版本循环（下发）** | 中央→本地 | tag 发布 → check_update → upgrade；presets 同步到 preset/ | 定义的分发与迭代 |
| **回传循环（信任分层）** | 本地→中央 | 日志PR（免审+CI校验+删除规则）/ 晋升PR（人审） | 反馈与晋升 |
| **评分循环（治理）** | 用户→中央 | LLM 静态分 + 用户实证分（挂版本）→ 台账 | 质量与信誉 |
| **改进循环** | 中央 | 周期人工触发 LLM 分析归因（含 staging 复核）→ 优化 → 新版本 | 持续改进 |

## 6. 配置分层（preset / custom）

- 中央 `presets/<name>/`：bootstrap 的 `presets` 有序声明（后者覆盖前者，类似 eslint extends）；
- 个人 `preset/`：下发的只读预设 + manifest（来源/版本/sha256）；
- 个人 `custom/`：用户后加配置，**升级永不覆盖**；
- `config` 合并：preset 打底 → custom 同名覆盖；冲突保留 `.local` 并提示。

## 7. 架构全景（ASCII 示意）

```
用户输入：根据 github://owner/repo 开始执行初始化，安装 mcp
        │
        ▼
命令协议层：① URI 解析（正则） → ② 意图映射（动作词→流程ID） → ③ 流程执行（预定义 skill）
        │
        ▼
大模型执行端（豆包 / Codex / ChatGPT）—— 上下文注入 + 函数调用（内部直连，无 MCP server）
        │
        ▼
L3 本地运行时（mac）· Agent 中介层（pack-manager）
   ├─ 初始化：读极简 bootstrap.json → 扫描目录规约自动发现（skill/knowledge/framework/role）
   │         → 安装预置 mcp/ → presets 同步到 preset/ → 分层注入
   ├─ 能力：init · check · upgrade · score · anomaly · doctor · config · import-scan · panorama · bind
   ├─ 本地演化：记忆 / 技能 / 等级提升
   └─ 持久度：部署配置的个人目录（跨设备）· runtime/（瞬时+TTL，不写系统 tmp）
        │⇅ 下发：初始化/升级/preset · 回传：日志PR/晋升PR
        ▼
L1 中央仓库（GitHub）
   ├─ bootstrap.json（极简）· 目录规约 · mcp/ · packs/（四类）· presets/ · 版本账本 semver tag
   └─ 治理：统一升级路线（打标→台账→复核→转正）；人审发布 = 最终信任锚
        │
        ▼
全景图：扫描目录规约 → 聚合 meta.json+台账 → 渲染 HTML
       ├─ GitHub Pages（CI 自动）  └─ 本地 MCP 手动触发
```

## 8. 关键决策点总表（已收敛）

| 决策点 | 定稿方案 |
|---|---|
| **统一升级路线** | 所有通用型候选数据（技能/知识/角色/配置）走「自动打标 → 台账 → 人工复核 → 转正」；staging 暂存 |
| **ai-config** | 保留；内容级重新拆解（逐项再拆通用/个人），拆解结果走统一升级路线 |
| **本地自定义角色** | 允许；个人角色进 staging 作为通用候选，转正后入 packs/role/ |
| **配置分层** | 中央 presets/ → 个人 preset/（只读+哈希）+ custom/（升级不覆盖）；config 合并可追溯 |
| **版本** | semver；patch 自动、minor opt-in、major 人审；升级走 opt-in + check_update |
| **锁版本** | 本地 lockfile 钉版本 + override 标记；中央发新版只提示不静默覆盖 |
| **升级迁移** | 新版本带迁移脚本；本地旧资产标 legacy，逐步重推导 |
| **双分融合** | LLM 静态分（发布时）+ 用户实证分（累计）分开存、挂版本；融合 = 质量分 |
| **打分 rubric** | 按包类型分别定义：skill→完成率/复用；知识→准确/时效；框架→结构/适用；角色→胜任/稳定 |
| **分的后果** | 晋升快车道 / 淘汰阈值 / 排名推荐 |
| **防刷/隐私** | 最低样本量 + 异常分剔除；只传聚合指标，不带原文 |
| **反馈双通道** | 日志PR = 免审自动合并 + schema 校验门 + 保留窗口 N 天 + 分析后删除；晋升PR = 人审 |
| **异常升级** | 日志异常（成功率骤降）→ 即时触发治理，不等周期 |
| **存储边界** | 中央=通用（GitHub）/ 个人=iCloud（跨机器，强制规约）/ 运行时=runtime/（TTL，不写系统 tmp） |
| **目录规约** | 约定大于配置：目录即身份 · 入口即文档 · 元数据即契约 · 新增即被发现 |
| **个人目录治理** | doctor 校验（缺失/多余/命名/哈希）；init 幂等补建不删文件（见 [08](./08-个人目录规约.md)） |
| **版本可见性** | 代理流程启用后，每次流程结束的最终汇报语句带当前版本号（如「当前版本 v1.2.0」）；全景图同步标注 |
| **信任锚** | 人审发布新版本；升级/安装前验哈希/签名 |
| **全景图** | 一份生成器：CI tag 触发发布 GitHub Pages；本地 MCP 手动触发生成 |

## 9. 设计原则

1. **机器干重活，人管质量门**——自动化铺开（打标/台账/初筛），但转正与发布保留人审。
2. **中央管合并质量，本地管分支自由**——本地自成体系（本地 git 分支），只有转正走中央。
3. **分层与边界**——存储分层、信任分层、注入分层、配置分层，用明确边界消解复杂度。
4. **上下文只放索引与规则，正文放仓库按需拉取**——防上下文爆炸，与防 tmp 膨胀同源。
5. **机制统一、对象可扩**——一条升级路线覆盖所有候选类型；新增包类型时复用同一机制，不另起炉灶。
