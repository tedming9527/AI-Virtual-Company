# 任务编排与能力发现

## 能力分层

通用规则规定授权、职责、证据和升级边界；平台引擎负责发现、版本固定、流程调度与运行记录；技能包提供可组合的方法；任务与节点指定所需资产。对话承担上下文传递，不作为任务唯一身份。

已有资产发现、正文交付、工具合同、进程监督和任务生命周期继续复用。新加的连接层固定多技能组合、节点依赖、重试预算和原生绑定。网络来源与采用决定见能力发现技能的 references/sources.md。

## 本地与网络查询

`find_skill({query})`、`list_assets({query})`、`recommend_assets({query})` 使用同一元数据匹配规则：名称、展示名、aliases、keywords、description 以及低权重来源/路径。NFKC、大小写、空白、连字符和下划线归一化；多词需全部有命中依据，允许跨字段组合。结果包含 score 和 matches（field、value、terms、kind）。这是声明别名与字面检索，不是任意语义翻译；未声明同义词可能不命中。

`discover_capabilities({zhQuery,enQuery,owners?})` 实际调用公开 GitHub 仓库搜索，分别执行中文和英文查询并去重；默认 owners 为 openai、vercel-labs。结果带 attempts、coverage、matchedQueries、来源 URL 和许可证线索。仓库命中不代表技能存在、许可可用、已安装或启用；部分失败不能冒充完整覆盖。网页、文档和其他维护者来源按需通过已有网页工具补充。

CLI 等价入口：`discover-capabilities <queries.json>`。只发送调用者提供的公开能力词，不读取项目文件；超时或限流返回 partial/unavailable，没有自动重试。

## 任务与流程接口

- `workflow_create({spec})` / CLI `workflow-create <file.json>`：校验并固定 `avc.workflow.v1` 合同，不执行。
- `workflow_status({workflowId})`、`workflow_cancel({workflowId})`、`workflow_templates()`；CLI 对应 `workflow-status`、`workflow-cancel`、`workflow-templates`。
- CLI `workflow-run <id> --authorize-commands`：在当前授权内执行已固定命令节点；无授权开关不执行。不提供可绕过原生工具合同的 MCP 命令执行入口。
- `task_begin` 可选 workflowId 与 nodeId，原有独立任务不变。节点角色、工具集合、调用预算必须是流程及部署合同允许的范围。每个原生节点用当前真实 session/turn/receipt 绑定，随后 `load_asset` 按 requiredAssets 交付正文，`task_closeout` 关联产物。

合同字段：id/title/goal/owner、assets、maxParallel、maxAttemptsTotal、nodes。资产项为 id/usage/purpose，usage 为 primary/support/verify；支持 general:<type>:<name>、local-custom:skill:<name>。节点声明 role/assets/dependsOn/maxAttempts/executor/outputs/acceptance，可选 when 指向直接依赖的 succeeded/failed/timed_out。完整可运行输入见公司 workflows/ 下模板。

上限：32 节点、8 并行、24 个节点上下文资产、单节点最多 5 次尝试；命令 timeoutMs 必填，原生节点受 maxToolCalls 约束且不伪造模型超时。冻结完整包摘要后，文件与引用变化均阻断后续执行。并行节点不能占用相同或互相包含的产物路径；命令 cwd 和产物路径为项目内相对路径，拒绝链接越界。

## 状态与证据

pending/ready 表示等待条件或执行；reserved/running 有已领取尝试；succeeded 表示工具技术结果与新产物满足定义的证据门槛，业务验收仍独立。失败分支可运行，整体保留 completed_with_failures。取消立即停止后续调度，活动命令实际停止后才能变成 cancelled；原生节点停止许可后需客户端收尾确认。

调用未知、进程所有者消失、监督更新失败进入 needs_attention，不能自动重放。运行器锁残留时先核进程与监督记录，在明确恢复决定前不删除锁、不重置节点。运行时状态在 runtime/workflows；跨对话读取同一流程 ID。命令只关联资料引用，不声称模型已应用技能或员工本人参与。

## 本地技能升级

`register_skill` 固定完整包摘要；`validate_local_skill({assetId})` / CLI `validate-local-skill <identity>` 生成结构验证记录；`propose_asset` 增加 assetId、validationId、sources，保留原有文字建议兼容。`list_skill_candidates` / CLI `list-skill-candidates` 返回候选状态和验证时效。

旧登记缺完整包哈希时显示 local-changed，复核后重新登记。候选快照保留源版本、文件摘要与来源，不随本地修改自动更新；任一内容变化使验证失效。结构验证不执行技能里的命令，专业行为验证与人审仍需真实证据。候选拒绝不删除原技能。

## 全景图与接入

公开视图只收集中央资产、公共能力、模板与公开 PR；本地视图另收集组合、节点、绑定、产物证据和本地候选。发布版本不代表已有 MCP 进程热加载。部署端需重启已有服务以加载新工具，按实际需要更新允许工具；新网络发现和候选写入工具不加入绑定前默认放行。
