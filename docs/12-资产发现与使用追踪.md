# 资产发现、按需加载与使用追踪

## 双向接入契约

执行中介层必须同时回答“模型能看见什么”与“系统实际观察到了什么”。资产源、正文交付和执行证据独立记录，避免把文件扫描、技能名称、模型自报和最终署名当作等价证据。

| 状态 | 产生证据的操作 | 可证明范围 |
|---|---|---|
| discovered | 已配置目录扫描、资产 hash 库存 | 文件存在且识别为资产；不是加载 |
| local-managed | 人工复核后原创 custom 技能登记 | 本地受版本与摘要登记；不是原生安装 |
| native-installed | 原生技能目录中发现技能 | 原生目录文件存在；宿主是否发现仍需 skills/list 等原生结果 |
| client-visible | 原生 skills/list 或当前技能清单 | 宿主宣告该技能可用；不是完整正文加载 |
| manager-delivered | 绑定的 load_asset 返回正文及 hash | 选定文件正文通过工具交付；不是语义执行 |
| read-attempted | 原生 PreToolUse 读请求 | 已发起已知资产路径读取 |
| read-completed | 原生 PostToolUse 完成读取 | 已知字面量路径读取工具完成；不是采用技能语义 |
| model-reported | report_asset_use 声明 | 仅模型声明，单独统计 |
| unknown | 宿主没有自动加载或语义采用事件 | 不推断，不补造已执行 |

`loaded:false` 是列表返回的状态：该次列表操作没有交付正文；会话中是否曾交付应查询绑定加载台账，不能从库存字段推断。

## 统一发现与按需正文加载

`packs/skill/ted-avc-manager/SKILL.md` 是已启用客户端的原生桥接技能；按宿主会话/回合关联，不按启动项目目录限定接入。安装到宿主支持的技能目录后，原生元数据发现成本低；使用时读取桥接正文，随后查询 manager 的资产目录。该安装动作单独验收，不把 MCP 注册冒充技能安装。

MCP 提供统一分页的 `list_assets`、`find_skill`、`recommend_assets`、`list_packs` 发现卡，并通过既有 `task_begin` → `load_asset` → `task_closeout` 连接原生 session/turn/receipt。load_asset 只交付允许来源、符合路径与摘要约束的包文件；登记过的个人 custom 技能需要当前登记 hash 匹配。入口或知识目录只是选材依据，具体正文另行加载并记 hash。任务契约、工具观察与产物完整性使用执行层台账，不在发现模块中另造匿名正文读取接口。

架构允许未来原生 skills/list 与资源提供方能力适配；具体宿主没有自动技能采用事件时，仍保持 unknown，不宣称监听模型内部推理。manager 使用名称、别名、标签、标题、原描述、有效双语摘要和查询期正文投影做可解释词法排序，不自动激活。

## 检索投影、双语与近期先验

公共入口由 `core/asset-discovery.js` 组织，`asset-selection.js` 和 `asset-search.js` 统一选择。原始 `listAssets` 仍是供观察模块使用的完整内部清单，不直接全量返回给模型。

- 已知中央、个人和客户端入口正文仅在查询期加入已有资产的检索投影，保留原 identity/load，不另造重复卡，不持久化正文；中央包内参考、docs/rules 和根文档另有 documentId/sourceSha256 路线。
- 文档投影扫描最多 4096 项、深度 12、单文档 256 KiB、合计 8 MiB，延后、失败与不支持来源体现在 coverage。旧库存 bundleFiles 哈希遍历不因此已获得同一 I/O 上限。
- 中英并集召回，英文按完整词匹配，标题/标签/别名/摘要权重高于正文；简单正向子句不等于通用否定、例外或动作适用性引擎。
- 双语缓存保留 zh-CN/en，并绑定来源正文、描述、元数据、版本和策略；缓存失效后回退原字段，不阻断基础发现。配对总量受 1024 B 上限约束，语义保持 model-declared-unverified，不设置独立语言环境。
- 近期先验消费相同资产修订、带 logicalTaskId 的 model-reported 声明，取同任务首次记录，按 7 天时间尺度衰减，加成最高 2%。无关热项不能被先验引入；推荐、加载和重复声明不刷新热度。日志损坏或超过 4 MiB 时停止可选先验，基础相关性继续。
- 私有 trial candidates 仅待审元数据可见；发现和读取均不授予激活资格。其他未接入来源不冒称已经完整覆盖。

发现页默认 8 项、完整 JSON 4096 B，上限 32 项/8192 B；nextCursor 绑定查询及来源/排序快照，源变化要求重查。超大单卡给 deferred/lookupId 并继续后续结果。资源读取也只交付有界卡与加载路线，不返回整个搜索全文。

`load_asset` 默认 summary 为摘录与章节索引；chunk 通过来源 SHA 和 UTF-8 字节位置分页。short card、双语摘要、全文连续交付与实际采用分别记录。完整响应计量及父子共享额度见 [01](01-架构总览.md)。

## 新文件、变更与删除检测

`awareness.refreshInventory` 扫描四类通用包、个人 custom 包和原生技能：

- 用户 `.codex/skills` 与 `.agents/skills`，包括 `.system` 技能层。
- 项目 `.codex/skills` 与 `.agents/skills`。
- 个人项目目录下相应技能根。

测试可显式指定 externalRoots；生产可以按平台适配配置批准的根。对于安装插件自带技能目录，只有显式提供插件根并用宿主清单校验后才纳入原生可见证据；不遍历整个 HOME 或插件缓存推断激活状态。符号链接目录与文件不跟随。

库存保存于 `runtime/asset-inventory.json`，记录来源、路径、版本、管理状态、正文入口与 meta 摘要，并对包内脚本、references 等文件名称和内容摘要计算 bundleSha256；新增支持文件也产生变化事件。新增、hash 变化和删除写入 `runtime/asset-events.jsonl`。inventory 原子替换；事件使用追加写入。调用时同步扫描之外，MCP 连接拥有 `watchAssets` 的目录观察和有限间隔复扫：缺失根的新建也能检测，关闭连接必须 dispose，不安装全局常驻 daemon。多个连接并发扫描允许重复检测事件，消费者按 assetId/hash/change 幂等归并；库存是最近扫描视图而非不可变审计替代。

发现事件不自动修改个人技能、安装外来包、改宿主配置或将内容写进通用仓库。原生目录中资产来源为 external-installed，未知登记状态为 discovered-unregistered；来源与管理状态分别显示。

## 工具读取观测

`recordObservedRead` 接受原生 Hook 字段，不读取原始对话：

- 识别 Read/read_file 的确切 file_path/path。
- 仅识别单个静态 `cat` 命令里的字面量文件路径。
- 复杂 shell 管道、命令替换、包装脚本、动态变量和未支持的工具保持不可观测；不能据此推断没有技能使用。
- PreToolUse 记 attempted。PostToolUse 的失败输出仍不记 completed；原生 Read 完成和已知 shell 成功退出只记工具读取完成。

审核记录保留 session/turn、资产标识、文件相对路径、hash 与证据种类，不保存 prompt、正文或工具输出。`noteDeliveredAsset` 只由 server 在绑定的执行加载成功后调用，不作为模型可任意调用的统计接口。多种证据同属一个 asset 时可以关联展示，不能把自报合并为观察证据。

## 逐步升级与全景图

1. 新原生文件发现 → unregistered 库存，使用事实单独统计。
2. 模型推荐或外部导入 → personal/staging/proposals 中 pending-review 元数据候选，不自动安装。
3. 原创 custom 技能复核 → register_skill 固定摘要；之后再次变化降为 local-changed。
4. 通用化候选 → 单独分支及 PR，在通用全景图展示候选包、版本、head/base、状态和来源。
5. 通过审查与发布门禁 → 合并、tag、发布；客户端更新后分别验证引擎版本、目录版本、原生 Hook、技能可见与正文交付。

本地全景图需要显示 generic / local-custom / external-installed 三类来源和个人知识、框架、记录等本地资产；公开通用全景图只包含通用包与已公开 PR 元数据，不能携带 personal 内容或路径。候选存在不代表已发布；升级验证不可删除个人数据。

### 原生插件技能目录

发现器也检查 `CODEX_HOME/plugins/cache`（默认 `~/.codex/plugins/cache`）中六层以内的 `skills/` 目录，兼容带版本的插件缓存；拒绝链接，不扫描 node_modules。新增插件目录由轮询重新发现。原生 `skills/list` 回执才标记客户端列出；缓存存在仅是外部文件发现，不能证明插件已连接、正文已加载或模型已使用。
