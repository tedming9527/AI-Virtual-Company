# 06 · 全景图管线

> 全景图 = 从目录规约 + 元数据自动生成的「项目说明书 / 状态页」。
> 核心：**一份生成器，两个触发端，同一套统计规则**（CI 发布 GitHub Pages / 本地 MCP 手动触发）。

## 1. 同源原则（代码同源，差异仅在数据）

本地是中央仓库的初始克隆，因此：

1. **生成脚本完全一致**：全景图生成器是仓库 `mcp/pack-manager` 的一部分，随 clone/upgrade 获得；CI 与本地执行的是**同一份脚本、同一个 tag 版本**，不存在"中央版生成器"与"本地版生成器"两套实现；
2. **统计规则完全一致**：评分融合、异常判定、聚合口径（样本量校正、加权、分位数等）是引擎内的共享函数，中央与本地调用同一套规则，**禁止本地另写统计口径**；
3. **差异只在输入数据**：

| 视图 | 数据输入 | 多出的内容 |
|---|---|---|
| **本地视图** | 克隆的 packs/ + 个人目录 | 个性化项目信息（experience/staging/custom）、通用大类下的本地技能等级加成 |
| **中央视图（Pages）** | packs/ + 全量回传台账 | 所有用户合并进来的日志/评分聚合、PR 记录 |

> 即：**同一引擎对不同数据集渲染**。本地视图回答"我这套环境状态如何"，中央视图回答"整个平台与各包的全局状态如何"。

## 2. 全景图内容

- 包目录：**skill / knowledge / framework / role** 四类分类列表；
- 每包状态：版本、stable/test/deprecated、评分、rubric 结果；
- 本地视图额外展示：preset/custom 生效配置来源、staging 候选与台账状态、本地技能等级加成；
- 中央视图额外展示：全量实证分、样本量、PR 与版本分布；
- 使用指南：从各包 SKILL.md 聚合；
- 项目概览：架构说明、规约说明、快速上手；
- 版本横幅：当前生效版本号（与 lockfile 一致）。

## 3. 生成链路

```
扫描目录规约 → 聚合 meta.json + 台账（同一套聚合/统计函数）→ 渲染 HTML → 输出 panorama/
        ▲                                                       │
   生成器（仓库内一份代码，随 tag 版本化）                          ▼
   ├─ CI：tag 发布时自动生成 → GitHub Pages 部署（中央视图）
   └─ MCP tool：generate_panorama 手动触发 → 本地生成（本地视图，可只看不发布）
```

## 4. 两个触发端

| 触发端 | 时机 | 数据视图 | 落点 |
|---|---|---|---|
| **CI（中央）** | 每次 tag 发布 | 中央视图（全量台账） | GitHub Pages |
| **本地 MCP** | 手动触发 `generate_panorama` | 本地视图（个人数据） | 本地 panorama/ |

## 5. 命令协议接入

```
用户：生成全景图
Agent：用仓库内同一份生成器 → 扫描目录规约 → 聚合 meta.json + 本地台账 → 渲染 → panorama/index.html
```

## 6. 数据源依赖（硬前提）

- 渲染需要 **meta.json + 台账** 能自动聚合——否则生成器没数据可画；
- 归因/台账必须持续攒（见 05-治理与反馈），全景图只是它们的**展示层**；
- **生成器与统计规则都跟 tag 版本绑定、随仓库分发**：本地生成的与 Pages 上的差异只能来自数据，不能来自逻辑版本。

## 7. 与规约的关系

约定大于配置是全景图能自动生成的前提：目录规约定了 → 扫描即可发现 → 元数据契约定了 → 聚合即可渲染。同源脚本保证了"所见即同一口径"，全景图因此是项目可信的**活门户**。
