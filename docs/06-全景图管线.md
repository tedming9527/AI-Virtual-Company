# 06 · 全景图管线

同一生成器与渲染器处理两种数据范围；同源不意味着两个视图输入相同。

| 视图 | 输入 | 落点 |
|---|---|---|
| 本地（默认） | 通用工作副本＋个人目录分类索引＋custom 包＋本机技能发现/登记＋配置来源＋本地观察 | `runtime/panorama/index.html` 与 `data.json` |
| 通用 | 干净已发布 tag 的通用包＋公开仓库候选 PR 元数据 | `panorama/` → GitHub Pages |

## 资产来源与状态

每个条目标记来源：通用中央源、中央下发副本、本地自定义、本地个人记录、待复核暂存、只读历史、外部已安装发现。文件数、包数和 PR 数使用不同口径。staging/archive 不自动激活或计入当前能力；preset 是通用预设的本地副本；同名资产也不自动覆盖中央定义。

技能管理状态区分 central-managed、discovered-unregistered、local-managed、local-changed；登记绑定正文与 meta 摘要。发现、登记、客户端安装、上下文交付、实际执行分别取证。配置逐项展示 preset/custom 来源，只有明确公开的运行设置直接显示值，其他值留在本地原文件。

## 用途描述规则

读者应能从资产名称旁的一句话理解“能做什么、什么时候用”。通用包在 `meta.json.description` 填写简短中文用途，建议 20–60 字、最多 160 字，不用内部编号或“强大、高效”等空泛形容替代功能说明。例如：“首次介入项目或跨模块改动时，梳理入口、依赖与约束，优先复用已有资产。”描述应与入口正文一致，不表示工具已连接、员工已参与或资产已执行。

`validate-packs` 将缺失、空白、超长或多行描述判为发布校验失败；这项检查沿用现有 PR 与发布 CI。新增或修改包时同步维护描述和包版本，避免页面与正文各存一份不同说明。

- 通用包和个人自定义包优先读取 `meta.json.description`。旧包、本地及外部技能可回退到入口 frontmatter 中明确声明的单行 `description`，过长内容缩短显示；不读取正文段落来推测用途。
- 知识正文条目直接展示目录中已有的 `summary` 与 `trigger`，分别说明用途和适用场景；不再次生成一份摘要。
- 候选 PR 的用途取固定 head 的包元数据；移除资产时取固定 base 元数据。描述缺失显示待补充，不用主分支描述冒充候选内容。
- 没有可用说明时明确显示“用途待补充”，不根据文件名编造。个人记录文件保持只读目录索引，不为补描述批量读取私人正文。

所有描述按纯文本转义，支持现有页面搜索。公开视图仍只读取通用目录与公开候选元数据，不因补描述读取个人存储。

## 公共数据隔离

`--public` 分支在读取 storage / personal / custom / 本地评分前结束采集。公开页面与 data.json 不包含个人路径、文件索引、执行/Hook 台账或私人评分。已发布目录必须 `--catalog-ref vX.Y.Z`，校验 HEAD、tag、bootstrap 与干净 packs 一致；无发布验证的预览明确标成工作副本，不能冒称发布快照。

## 候选 PR

采集器只读公开 GitHub 仓库元数据，筛出修改 `packs/<type>/<name>/` 的 open PR，逐项列出 base/head 固定 SHA、原版本、提议版本、Draft/Open 与链接。候选不改写已发布目录；API 无法取得数据、未同步或快照过旧时分别显示状态，不能表示“没有候选”。关闭/合并会在刷新后移出 open 列表。

Pages 工作流由 tag、pull_request_target 状态变化与 workflow_dispatch 触发。PR 触发时检出最新已发布 tag，仅把 PR 元数据作为数据；不执行候选代码或安装候选依赖。

## 命令与 MCP

```sh
ted-avc-manager panorama --local
ted-avc-manager panorama --public --catalog-ref vX.Y.Z
ted-avc-manager sync-candidates
```

MCP `generate_panorama` 默认 local，显式 `view: public` 才生成通用视图；`offline` 使用上次候选快照并显示获取时间。新技能和新记录只读索引，原个人资料不移动、不覆盖。CLI 与 MCP 调用同一收集/渲染逻辑，发布版本、工作副本与运行引擎版本明确区分。

## 本地来源筛选与使用证据（工作副本）

本地视图每个表格独立提供“全部 / 中央 / 本地”，初始选择本地；搜索与该表格的来源选择共同生效。技能、知识、框架和岗位列表同时容纳中央与本地资产。公开中央视图不提供来源下拉，也不读取本机使用记录。

本地候选同时读取 `staging/proposals` 的待复核提案和 `staging/trial-candidates` 的试用候选，区分资料类型、候选阶段、版本、试用进度及发布/安装状态。候选数量不是已发布资产数量，试用完成不自动产生评分。

“全部资料评分与使用”按当前身份、版本和内容摘要连接本机保留的事件及任务记录。加载、完成读取、自报采用分开按回合与入口去重；读取尝试和任务成功不能算作实际采用。最近观测和近 30 天次数只描述保留的证据，不能据此宣称从未使用。已有周度窗口单列，不与原始记录累加；未观测或未建立归因的字段标明证据不足。生成器不补造历史、不评分或改写资产。

所有资产展示评分状态；数值仍须通过 `verifiedRating` 的摘要、身份、时间、来源和至少 20 个样本校验。现有中央包沿用 `pack:<type>/<name>@<version>`；独立知识正文使用 `knowledge-entry:<id>@<updated>`；本地资产使用 `asset:<assetId>@<version>`；候选使用 `proposal:<id>` 或 `trial-candidate:<id>@<version>`；普通文件使用 `file:<area>/<relativePath>`。候选试用摘要和普通文件摘要单独校验，不继承父包评分；普通文件仅在已有评分需要验证时读取内容，不为填评分批量读取正文。未有真实采用/反馈采集的项仍为未知，不将加载频率当作质量分。
