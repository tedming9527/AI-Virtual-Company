# 个人资料与资产生命周期优化方案

## 目标与边界

中央仓库定义规则与引擎，个人目录保存私有资料。让原始经验、课题资料、个人自定义资产和四类通用包都能被发现、统计、改进；把“发现价值”“形成候选”“版本质量”“发布”分成可追溯的不同阶段。公开全景图只读公开资产及已公开候选元数据，不输出个人正文、路径、连接状态和本机运行数据。个人知识不要求 GitHub 仓库；只有脱敏且经复核的通用化成果向中央仓库提 PR。

本方案包含目标机制与首期落地。已实现范围、运行证据及缺口以 `docs/09-实现与验收状态.md` 为准；不能从本方案推断全类型评分或自动清理已经启用。

## 首期落地与运行边界（2026-10-13）

已提供四类包与个人自定义资产的摘要绑定事件模型、按窗口去重汇总和仅供复核的升级／优化／审计建议。来源不足 20 个可归因结果时不显示实证质量分；本地与公开全景图对同一公开资产使用相同的版本摘要和评分证据。会话 Hook 只在到期时提示后台提炼，实际子代理是否运行要查周度状态与产物，不能把 Hook 提示当作完成。

首轮周度任务已对 408 条经验文件路径建立摘要索引，得到 4 条来源绑定、待人工复核建议；其中同源副本不能算独立实践。本轮可归因使用窗口无事件，未产生实证评分。个人资料大小约 19.4 MiB，低于 1 GiB 软阈值。原文未移动或删除，建议未自动安装、发布或创建 PR。

运行原始日志最早 30 天且有已核验汇总回执、任务终态、无调查保留时才可显式清理；经验原文进入 90 天可恢复区需要外部提供完整覆盖复核声明和摘要匹配，默认仅预览，并可对中断移动进行显式协调。当前代码不验证复核者真人身份，也未从客户端自动采集满意度、跨设备强一致租约或自动发起中央 PR。对于这些缺口保持未启用状态。

## 统一状态与流转

| 阶段 | 输入与动作 | 产物及门禁 |
|---|---|---|
| 发现 | 按课题扫描个人经验、个人自定义资产与通用包；记录资产身份、内容摘要、版本、来源及最近观察时间 | 只证明存在，不把发现或加载算成实际使用 |
| 周度分析 | 汇总上一窗口的加载、可观察采用、任务结果和用户反馈；大模型检索同课题、相关个人/通用资产及必要的互联网原始来源 | 提炼优先级、相似/冲突说明、来源 URL、待验证项；证据不足标记“未评分” |
| 提炼 | 大模型比较适用边界、取长补短、补全缺口，提出合并或改进已有资产的草案 | 多对一来源映射、逐条覆盖/未覆盖清单、差异、风险和验证方法；草案不得覆盖原文 |
| 个人演化 | 复核草案后在个人目录形成候选或新版本，记录前后摘要和回退依据 | 保留个人身份与私有范围，不要求 PR，不自动覆盖旧版 |
| 通用化 | 判断跨课题复用、脱敏和许可条件；与中央现有资产比较 | 独立人审的中央 PR，固定提交/内容摘要；合并与发布后才成为通用包 |
| 使用治理 | 分开保存静态评估、实证质量和样本量，按资产身份、版本、内容摘要及窗口计算 | 升级、降级、审计优化建议；分数不自动发布、停用或删除 |

原始经验属于升级流程的发现与提炼阶段。发现优先级可用重复出现、关联课题、问题影响和证据完整度排序，不能冒充成品质量分。没有可靠使用结果时仍可提炼，但显示“未评分／证据不足”。新候选或改过的资产以新摘要重新积累质量证据，旧分数不能沿用。网络热度、维护状况、安全公告及 OpenSSF 等外部信号单独展示来源、URL 与时间，不与内部使用质量混为一个保证性总分。

## 每周会话触发

在用户会话开始或提交任务时，只做轻量到期检查。距上次**成功**周度汇总满七天且无同周期运行时，调度一个后台子代理；失败保留原因，下次会话重试。允许用户随时指定课题手动提炼。没有会话时不为这项工作单独启动定时任务。若当前客户端没有可靠的子代理调度能力，报告“待触发”并在受支持的会话中执行，不把 Hook 启动当成工作完成。首版只允许一台指定执行设备写入周度结果，其他同步设备只读；iCloud 文件锁不能证明跨设备互斥。运行记录包含窗口、runId、执行设备、租约和提交代次；过期执行者不得覆盖较新结果。`lastRunSucceededAt` 与 `coveredThrough` 分开保存；按 UTC 半开窗口补算长时间无会话的积压，迟到事件以稳定事件 ID 去重并修订对应窗口。

子代理只取得最小必要的个人目录范围和聚合事实。“本地提炼”仅指资料与产物的存储位置，不能据此声称模型推理不出站；接入时必须明确实际模型服务、允许传输的字段和用户授权，无法核对时只做本地索引并标记待处理。联网搜索词经过独立脱敏检查，不上传会话正文、个人路径或原始经验；导入材料和网页只作为待分析数据，不授予工具指令权。提炼器不获得发布、安装、执行候选脚本或清理权限。输出草案和建议，不自动改写资产、提交 PR 或删除原文。前台给用户显示本周是否完成、覆盖窗口、候选数、异常与需复核事项，不让后台任务阻塞当前会话。

## 数据保留与容量

- 未提炼经验继续保留，下一周期提醒复核；不能因低使用或达到容量阈值自动丢弃。
- 提炼成果通过复核、来源映射完整且有效内容被覆盖后，已吸收原文进入 90 天可恢复区；未吸收片段留在经验区。入区记原路径、内容摘要、提炼目标与到期日；内容变化或引用未解决时停止清理。
- 30 天是运行原始事件的**最早可删时间**，不是强制到期即删。只有任务已结束、汇总摘要与覆盖水位已提交并核验、且无失败调查/待核验回执时，才清除过期调试事件；最小逐任务执行证明单独保留，资产级统计另存。汇总统计不能替代逐任务执行证明。现有 `docs/05` 的“窗口内未消费也删除”表述须在实现清理前统一修订。
- 个人资料目录以 1 GiB 为软阈值（界面可标为约 1 GB）：每周统计大小及增长，超限列出类别、最大来源和瘦身建议，不自动删除长期课题源码、未提炼经验或唯一资料。
- ChatGPT 原生临时工作区沿用客户端位置；中介层新增的临时副本不得进入 iCloud 同步目录。创建副本以及启动依赖安装、构建时都核对真实路径与符号链接祖先；无法证明处于非同步位置则停止。长期课题同步源码、手写配置及锁文件，依赖安装包与构建输出只在本机工作副本中。源码回写核对允许清单、基线摘要和同步目标是否已有改动；未验证唯一产物已持久化前不清理副本。用户原有 Documents 项目不由此规则迁移或清理。

## 证据、发布与回收门禁

资产主键使用无个人路径的来源命名空间与稳定 ID，版本证据使用完整 bundle 的规范化内容摘要；读到的单篇文档另记摘要。事件 schema 升级时加入去重 ID、资产主键、bundle 摘要、信号类型、任务关联与可观察性。旧日志缺少摘要或归因时保持 `unknown`，不强行归到当前版本。静态 LLM 评估与实证质量分开显示：零可靠样本时实证质量为“未评分”，不能把现有 `mergeScore` 返回的静态临时分呈现为使用质量。一次任务中多个资产被加载，不能把任务成功平均归功于每个资产；需定义实际采用证据、归因分母、重复加载去重和最低样本门槛。

### 答案满意度与行为模式

现有评分是项目自定规则，并非从真实用户满意度校准出来的标准：`score.js` 使用静态分 40% 与实证分最高 60%，样本不足 20 时衰减实证权重；实证分又按成功率 60% 与平均评价 40% 合成。当前 `usage-log/v1` 只覆盖 skill、版本和 success/fail 等字段，没有可靠的答案满意度采集、反馈撤回和资产贡献归因。零样本时函数仍给静态临时分，不能在页面写成“用户满意”或“已验证质量”。

新增信号分层：① 用户明确赞同、纠错、采用或评价，绑定具体答案/产物摘要；② 可复核的任务验收与测试结果，绑定任务和版本；③ 重写、反复追问、复制等仅在客户端实际提供事件且用户允许时作为弱行为线索；④ 大模型对措辞/情绪的判断只作为待核查推断。沉默、继续聊天、会话归档或工具退出成功都不代表满意。记录可撤回的事件 ID、答案/产物摘要、维度、信号来源、观察时间和未知状态；同一案例多轮纠正不重复计数。满意度先属于答案，只有可证明资产被采用且贡献可归因时才影响该资产实证分。

大模型从多次独立任务中寻找“条件—动作—结果”模式，同时找失败、撤销和相反案例。回答风格等个人偏好留在个人配置；有稳定触发条件、可复用步骤、适用边界和可验证结果的模式才形成个人 skill 草案。初始转正建议至少三个独立任务可复现、一个未参与提炼的验证案例和人工复核；这个阈值仅供首版试运行，不代表统计显著性。候选未经确认不自动启用，也不自动推广为通用资产。交付处可选择性提供“已采用／需要调整／暂未验证”三种低负担反馈，不询问每一轮；未选择保持未知。模型推断满意度需要人工标注样本验证准确率，资产效果需独立案例或经授权的小规模对比。

每条重要提炼结论标注证据类别（原文明确陈述、外部事实、模型推断、待验证建议）、对应来源片段、固定版本或内容摘要、获取时间和 URL；来源集合相关不等于支持该结论。来源、草案或目标摘要变化后，旧复核失效。原文可按片段标记覆盖状态，未覆盖片段始终受保护。

公开资产的**个人使用统计仍是私有数据**。本地统计与可发布统计分库存储；导出前以递归字段白名单、小样本披露门槛和人工审查核对评分理由、来源及元数据。通用化顺序必须是本地冻结内容与私有来源映射 → 脱敏及许可人审 → 生成只含安全来源的公开 PR；公开草稿 PR 也算披露，不能先创建再审。PR 标题、正文、附件和评分均不得出现个人路径、会话标识或私有课题内容。

已提炼经验的 90 天可恢复区必须与现有旧资料 `discard/` 用途区分，支持课题内 `experience/` 路径。迁移先写可恢复的准备记录，再以操作 ID 原子提交移动与台账；崩溃重试扫描孤儿。台账绑定源/目标摘要、片段覆盖映射、复核凭证、引用版本与到期时间。恢复时处理原路径冲突；清理前重新核对目标未变、没有新增引用、日期有效且所有保护条件满足，默认只预览。

## 实现顺序与验收

1. **模型与台账**：定义个人经验来源映射、资产版本摘要、窗口统计、提炼/复核状态及可恢复区记录；迁移只新增索引，不批量移动旧资料。用同一评分函数供本地和公开视图消费公开可用的同一资产证据。
2. **采集与周度汇总**：扩展现有 skill-only 使用日志至四类包与个人自定义资产，区分发现、加载、实际采用、自报、任务结果、明确满意度反馈与弱行为线索。锁定窗口并原子写汇总；重跑同一窗口不得重复计数。对不可观察的采用和无反馈的满意度保持 `unknown`。先验证 schema 的递归敏感字段拦截，再谈免审的聚合日志通道。
3. **提炼工作流**：按课题检索并由大模型产生可复核的多对一草案；记录本地和互联网来源、冲突、未覆盖项及是否改进现有资产。先建立可手动运行的命令，再接入会话到期触发和子代理能力门禁。
4. **治理动作**：个人演化在本地形成版本与差异；通用化先生成本地脱敏预览并完成公开前人审，再创建中央 PR，继续走合并、tag 与发布门禁。评分只给建议，不直接驱动不可逆动作。
5. **瘦身与视图**：先做只读容量报告、30 天事件清理预览和 90 天原文可恢复区预览；核验汇总、来源与引用后才允许执行清理。全景图同时显示状态、证据等级、窗口、来源与建议，本地和公开对同一公开资产采用相同展示规则。

验收覆盖：多条经验合并到一个候选与改进现有资产、冲突/未覆盖项不丢失、无分数也可提炼、内容变更使旧分数失效、重复周度触发幂等、失败后重试、无客户端子代理能力时保持待触发、30/90 天清理的保护条件、1 GiB 超限仅提示、个人数据不进入公开页面或中央 PR、iCloud 下不生成任务依赖副本。单元测试之外，应对照实际本地全景图和真实会话触发回执验收。

## 评审焦点

需分别检查：一是状态机、幂等、统计与清理在中断和重试时是否安全；二是大模型提炼、来源归因、个人/通用边界和评分建议是否会误导或泄露。评审意见须标明实际执行通道与证据，不能仅凭岗位名称声称具名员工参与。

## 两路独立 AI 专业视角审查（2026-10-13）

两名平台子代理分别以服务端生命周期和 AI 知识治理视角对本方案及当前代码作了只读审查；实际执行者均为 `platform subagent`，没有取得花名册员工本人的派发与产物签名回执，因此不能称为具名员工评审。结论是流转方向成立，但以下门禁必须在启用自动化之前落实：

| 审查视角 | 主要发现 | 纳入方案的处理 |
|---|---|---|
| 服务端生命周期 | iCloud 不能作为跨设备锁；旧清理器只凭文件名和时间可能删掉未消费事件；现有资产身份包含路径且评分未绑定完整内容摘要 | 首版单设备写入、覆盖水位与提交代次；30 天仅为最早可删；事件与资产身份升级、版本摘要隔离；90 天迁移与恢复需可重入事务 |
| AI 知识治理 | “本地提炼”不证明模型本地推理；公开资产的个人使用数据仍可能泄露；静态分被误作实证质量；公开草稿 PR 也已构成披露 | 明确模型与搜索两条出站边界；私有/公共统计分库及公开前审查；静态/实证/满意度分开展示；冻结内容脱敏复核后才创建中央 PR |

两路审查还共同指出：现有公式是项目自定启发式，尚未用真实满意度标注数据校准；对答案的称赞不能自动归功于本轮加载的全部资产。基于行为模式生成 skill 时，应先形成可撤回、可核验的个人候选，并用独立案例验证效果。

**评审状态：**以上为平台 AI 审查及方案修订，不等于具名专业人士本人验收。若后续要求真实员工签核，需具备已验证专属适配器、冻结任务摘要与绑定产物的短时回执；当前不以岗位标签代替这项证据。
