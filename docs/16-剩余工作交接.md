## 接续操作

### 1. 固定候选和发布版本

核对分支、工作区和远端；查询是否已有对应 PR，避免重复创建。本轮功能提交已远端核验一致。先同步最新 master 并处理实际冲突，再改三处版本及发布说明。不得覆盖 v1.6.1 的不可变 tag，也不要直接把候选推到 master。

普通发布门禁与回归入口：

```sh
node mcp/ted-avc-manager/src/cli.js validate-layout
node mcp/ted-avc-manager/src/cli.js validate-packs
node scripts/check-knowledge.mjs
node scripts/mcp-governance.mjs check-company
node scripts/release-master.mjs --check
node mcp/ted-avc-manager/src/cli.js panorama-source-snapshot --check
node --test mcp/ted-avc-manager/src/core/*.test.mjs mcp/ted-avc-manager/src/governance/*.test.mjs mcp/ted-avc-manager/src/panorama/*.test.mjs scripts/*.test.mjs
python3 -m unittest discover -s scripts -p '*_test.py'
```

CI 使用 Node 22、Python 3.11、Yarn 1.22.22，并完整检出历史 tag。正式 PR 另检查版本高于实际 PR base。当前未增版本的分支不能直接作为合格发布 PR。

上轮证据为完整 196 项 Node / 27 项 Python，通过后新增源码搬迁测试单独通过、31 项定向回归通过。最终只读 doctor 通过。完整原生矩阵先于最后一次 doctor 修复执行：旧矩阵中的 doctor 有失败，**最终提交的完整矩阵仍须重跑**。

```sh
# 操作员明确使用已有登录；不会申请新 API key，不进入自动 CI。
python3 scripts/native-session-acceptance.py --use-existing-login --native-default --timeout 240
```

运行器在隔离客户端生成原生事件，核对测试 Hook 精确定义及哈希，结束时清除登录副本。输出的本机 summary 记录断言；同时检查实际工具错误、未知调用、任务违反记录和产物内容，不能只看进程退出码。原始模型记录留本机，不提交会话内容、凭据或个人路径。

### 2. 正式发布后更新本机

PR 人审合并后查看 `master-release` 与 Pages 的真实运行记录。发布完成后，在正式绑定的干净中央仓库执行准确 tag 更新，Node 使用本机实际绝对路径，用户资料项目与客户端目录从当前部署读取：

```sh
python3 scripts/update-local-client.py vX.Y.Z \
  --node '<本机 Node 22+ 绝对路径>' \
  --codex-home '<实际客户端目录>' \
  --personal-project '<当前已绑定用户资料项目>'
```

本轮没有执行这些剩余步骤。安装器拒绝活动任务与未处理事务时，先核对真实状态；保全失败只暂停破坏性重建。独立 CLI/stdio 的成功不证明当前聊天缓存 MCP 已重新加载，不通过重装、强制改信任或重启全部无关 MCP 来伪造证明。

若用户是在对话中请求初始化，仍由模型在授权和平台权限允许范围调用 `yarn setup` / `npm run setup`，非交互传明确参数；不能改回模型逐文件拼装环境。

### 3. 在真实聊天输入框验收

平台目前拒绝电脑控制工具访问 Codex 应用，这是桌面菜单验收缺口的原因；不能用其他界面控制渠道绕过。由用户或合规测试环境完成 `/` 菜单发现、选择 Ted 和实际调用验收。原生 `skills/list` 已确认 Ted 名称、说明、默认提示及启用状态；它证明宿主列出技能，不能代替用户看到菜单。

| 聊天动作 | 验收要点 |
|---|---|
| 帮助 / help | 展示实际可用入口和七个动作；无操作要求时不重建客户端 |
| 检查更新 / update | 安装、本地声明、运行引擎与远端 Release 分开；离线返回不可取得，检查不等于安装 |
| 创建本地全景 / panorama | 返回真实本地文件，升级及评分区清楚；中央目录搬迁不重建旧路径，不泄露个人数据到公开图 |
| 评分 / scores | 展示有效版本/内容绑定、样本与优秀项；证据不足保留未评分 |
| 检查 / doctor、status | 实际调用只读工具，不因组合工具审批误判而转成失败；不为只读诊断专门创建文件交付任务 |
| 修复 / repair | 计划与已执行明确分开；用户授权执行后使用确定性安装器，保留原生信任和审批 |

同时恢复旧会话，在新真实事件上核对当前代次、会话/回合绑定、正文交付和任务关闭。多项目、无工作目录、配置损坏、存储离线、并发旧别名继续覆盖；历史缺失只标未知。新旧会话不能采用不同准入条件。

### 4. 补齐治理数据来源

当前 `weekly.js` 自动汇总 `task.assets` 的 delivered 信号；任务 closed、文件存在、测试退出 0 或模型宣称使用，都不能证明某个资产产生了可归因结果。仅有 `usage.js` 接受带 `verified` 字段的数据结构，不代表存在可信上游记录器。

先定义独立归因和用户反馈采集边界，再实现记录、去重、版本/摘要校验与周度接入，区分任务结果和资产贡献。模拟 20 个样本只能进入隔离测试，不能写真实个人评分。验证重复事件、伪造 verified、过期版本、摘要变化、少于 20 样本、无结果及反馈撤销/资料废弃等路径；资料搬迁不当成废弃。

优秀分至少 4.5/5、样本至少 20、内容/版本匹配且非临时、非静态评估。评分优秀与资料已升级是不同事实。只有评审发布并核验源/目标内容后，生命周期台账才记中央升级完成。
