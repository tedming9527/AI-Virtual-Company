# 05 · 治理与反馈

> 一条统一升级路线；反馈分两种（信任分层）；评分分两源（LLM 静态 + 用户实证）；统计规则中央/本地一致；日志有完整生命周期。

## 1. 统一通用化升级路线（治理总通道）

**所有通用型候选数据——技能、知识、角色、配置，无论来自 ai-config 内容拆解、本地自定义角色、外部工具导入还是本地演化——统一走：**

```
候选源 → staging/
       → ① 自动打标：通用候选 / 个人特有 / 待人工（规则 + LLM，必须给理由）
       → ② 台账 imports-registry：来源 / 标签 / 状态 / 版本 / 文件哈希
       → ③ 人工复核：周期 LLM 初筛 + 人工确认（并入第 7 节定期分析节奏）
       → ④ 转正：通用者入中央 packs/（人审、打 tag）；个人者留 experience/archive/custom
```

- 该路线统一了「导入治理 / 晋升 PR / 非通用剔除」三套旧机制；
- **ai-config** 保留但做内容级重新拆解，逐项再判通用/个人，结果进 staging；
- **本地自定义角色**同样进 staging，通用化后转正入 `packs/role/`。

## 2. 反馈双通道（信任分层）

| 通道 | 内容 | 审核 | 本质 |
|---|---|---|---|
| **使用日志 PR** | 纯数据（聚合指标） | 当前遵循仓库人审流程；自动通道为后续设计 | 数据校验不能替代授权或证明没有隐私风险 |
| **晋升/转正 PR** | 改中央技能定义（含 staging 复核通过项） | **人审** | 高风险：影响所有用户，需质量门 |

> 同一逻辑：**机器可校验的低风险数据走自动道，影响定义的高风险变更走人审道。**

### 数据门禁与发布授权

使用日志须过 schema、来源、版本与隐私校验。当前授权不包含自动提交、推送或合并；未来自动通道还需独立的发布策略和权限验收，不能仅因数据校验通过启用。

## 3. 日志生命周期（数据最小化 + 隐私）

```
收集(本地登记，按授权回传) → 累计 → 周期性分析(抽取聚合指标+失败归因) → 消费完 → 删除规则清除
```

- **保留窗口**：原始调试事件至少保留 30 天；任务结束、统计汇总及覆盖水位核验、无调查或待核验回执后才可删除。未消费或仍受保护的事件超期也不得删除；
- **删前抽什么**：把「聚合指标 + 失败归因」提走，日志本体才可安全删；
- **证明分层**：最小逐任务执行证明与资产级统计分开留存；聚合统计不能替代执行证明；
- **异常升级**：发现异常（成功率骤降/使用率暴跌）→ **即时触发治理，不等周期**。

## 4. 评分融合（两个分，口径不同；统计规则中央/本地一致）

| 分源 | 类型 | 度量 |
|---|---|---|
| **LLM 静态分** | 发布/审查时的预判质量 | 正确性、相关性、可复用性、结构 |
| **用户实证分** | 真实使用后的观测质量 | 成功率、完成率、适用范围 |

- **分开存、挂版本**（挂到具体 tag，不挂技能整体）；
- 融合：`质量分 = f(LLM静态分, 实证分, 使用次数, 成功率)`；
- **统计规则单一来源**：融合、样本量校正、异常判定等函数在引擎内共享，中央聚合与本地视图调用同一套口径，禁止本地另写规则（见 [06](./06-全景图管线.md)）；
- **LLM 当裁判必须有 rubric**（明确维度 + 理由），否则打分漂移、易偏置。

## 5. 打分 rubric（按包类型分别定义）

| 包类型 | rubric 维度 |
|---|---|
| skill（技能） | 完成率、可复用性 |
| knowledge（专业知识） | 准确性、相关性、时效 |
| framework（框架/规则） | 结构性、适用性 |
| role（专业角色） | 胜任度、稳定性 |

## 6. 分数的后果（必须有决策挂钩）

- 高分可建议优先复核；低分可建议审计或调整，均不自动晋升、降级或删除资产；
- 当前相关性排序的近期先验仅来自同修订、按逻辑任务去重的模型采用声明，最高 2%，不是质量评分；
- 未曝光或低使用量不等于负面效果。真实采用、业务结果和用户反馈需独立证据。

## 7. 周期改进（人工执行大模型）

```
Plan: LLM 分析评分台账 + staging 待复核清单（可归因）→ 定位问题
Do:   改造优化中央技能定义；复核通过的候选转正
Check: 评分 + 实证分（版本间对比：v1.3 vs v1.4 分是否回升）
Act:   tag 发布新版本 → MCP upgrade → 再使用
```

- **触发机制**：周期兜底（每 N 周/月）+ 异常即时触发（分数骤降不等周期）；
- **可归因是硬依赖**：没有失败归因数据，改进环节空转；
- **版本间分数对比**是「持续改进是否成立」的唯一客观验证。

## 8. 防刷与隐私底线

- 最低样本量门槛 + 异常分剔除（防小样本噪声、恶意刷分）；
- **只上报聚合指标，不带对话原文/敏感内容**；
- PR 可审计可追溯：谁打的、打在哪版。

## 9. 信任锚

- **人审发布新版本 = 最终信任锚**：机器干重活，人管质量门；
- 升级/安装须核对已发布提交与内容摘要；签名验证与受保护发布器未部署时明确 unavailable，不宣称已完成。

## 10. 当前提炼与清理控制（2026-10-15 源码）

周度来源快照及索引留盘，按有界索引页和来源 SHA 游标取片段，共用客户端累计上下文预算。冻结来源未完整交付、变化或超限时不推进覆盖水位；候选仍待复核。逐来源 backlog、跨设备事务与统一升级状态机尚未完成，不把辅助故障变成用户任务门禁。

runtime/cache、日志、明确废弃资料和唯一原文分别处理。路径及中间链接拒绝跟随；非法 ISO 日期或不足保留期不删除；日志需精确 SHA 的汇总/任务终态依据。经验隔离要求完整 UTF-8 字节覆盖和候选中可核验的唯一摘录；摘要 approved/complete 不授权删除。删除原文另需绑定来源路径/SHA 的显式本地处置声明；无此依据的旧记录保留可恢复。未知同目录文件保持待处理，只删除核验文件及非递归移除空目录。
