# 02 · 中央仓库规约（约定大于配置）

> 核心原则：**目录结构本身即契约**。Agent 初始化靠「扫描规约」而不是「读配置」。
> 本文件同时给出**仓库模板落地样例**，与当前中央仓库实际结构一致。

## 1. 目录规约清单

| 规约 | 含义 |
|---|---|
| **目录即身份** | packs/skill/名称 = 可执行技能；packs/knowledge/名称 = 专业知识；packs/framework/名称 = 框架/规则；packs/role/名称 = 专业角色 |
| **入口即文档** | skill / knowledge / framework 必须有非空 SKILL.md；role 可用非空 PROFILE.md 作为等价入口，作为使用说明与 Agent 注入入口 |
| **元数据即契约** | 每个包必须有 meta.json（类型、版本、rubric 维度），供扫描聚合与全景图渲染 |
| **新增即被发现** | 新增专业包 = 建目录放对位置，扫描自动发现，**不改任何配置** |
| **预设统一下发** | presets/ 存统一下发的预设配置；个人侧 preset/custom 物理隔离（见第 6 节） |
| **产物有定所** | panorama/ 是全景图 HTML 的统一落点；mcp/ 目录名即工具名，自动注册；runtime/ 是本地运行态唯一落点 |

## 2. 中央仓库目录结构（与实际一致）

```
repo/                                    # 中央仓库根（GitHub）
├── bootstrap.json                       # 极简初始化清单（name/version/update/storage）
├── CHANGELOG.md                         # 版本账本（与 tag 对应）
├── README.md                            # 仓库说明（可发布为 Pages 首页）
├── AGENTS.md                            # Agent 行为总入口
├── .github/workflows/                   # CI：validate（包校验/日志门）· panorama（Pages 发布）
├── mcp/                                 # 预置 MCP / 引擎（目录名即工具名，自动注册）
│   └── ted-avc-manager/                    # 包管理器（含全景图生成器、评分/统计共享函数）
├── packs/                               # 多类型包注册表（约定大于配置）
│   ├── skill/        # 可执行技能（对齐 tool），扫描自动发现
│   ├── knowledge/    # 专业知识（对齐 resource），扫描自动发现
│   ├── framework/    # 框架/规则包
│   │   └── company/  # 通用公司框架：AI_RULES / platforms / targets / intermediary / policies/（16 策略）
│   └── role/         # 专业角色包，当前 8 包（backend-expert、frontend-expert 等）
├── presets/                             # 统一下发的预设配置（有序声明，后者覆盖前者）
├── rules/                               # 全局框架 / 规则（跨包约束）：base.md
├── scripts/                             # 仓库脚本（含架构图生成器等真实工具）
├── templates/                          # 通用任务模板；平台适配由部署提供
├── runtime/                             # 本地运行态：cache/ logs/ lockfile.json（TTL，不写系统 tmp）
├── panorama/                            # 全景图生成产物（CI / 本地共同写入）
└── docs/                                # 开发文档 01~08（可发布 Pages）
```

> 每个包的标准结构：`<pack>/SKILL.md`（role 也可为 PROFILE.md）+ `<pack>/meta.json`，可含 `rules/`、`scripts/` 等子目录。

## 3. 关键文件示例

### 3.1 bootstrap.json（极简——其余靠规约发现）

```json
{
  "name": "ai-virtual-company",
  "version": "1.1.0",
  "update": { "channel": "master", "check": "on-start" },
  "presets": ["base"],
  "storage": {}
}
```

### 3.2 packs/&lt;type&gt;/&lt;name&gt;/meta.json

```json
{
  "type": "skill",
  "name": "backend-training",
  "version": "1.2.0",
  "rubric": ["completion_rate", "reusability"],
  "status": "stable"
}
```

`type` 取值：`skill` / `knowledge` / `framework` / `role`；role 包 rubric 用 `competence`（胜任度）、`stability`（稳定性）。

## 4. 约定大于配置收益

- bootstrap.json 只保留少量引导字段，无需为每个包写配置；
- 「后面可新增扩展专业包」天然满足——**建目录即可被发现**；
- 全景图可自动生成：扫描规约 → 聚合 meta.json → 渲染 HTML；
- Agent 初始化 = 扫描目录规约构建索引，行为可预测、可审计。

## 5. 版本与治理

- 版本账本：semver tag（major=破坏性 / minor=新增 / patch=修），与 CHANGELOG.md 对应；
- 发布流程：**人审合并 → 打 tag → CI 校验 → 发布**（人审 = 最终信任锚）；
- 升级纪律：patch 自动、minor opt-in、major 人审；升级前验哈希/签名；
- 迁移：新版本必须带迁移脚本；本地旧资产标 legacy，逐步重推导。

## 6. 预设与配置分层

```
中央 presets/<name>/ ──init/upgrade──▶ 个人项目 preset/<name>/（只读+manifest+sha256）
个人自有配置 ──────────────────────▶ 个人项目 custom/（升级永不覆盖）
生效配置 = preset 打底 → custom 同名覆盖；config 命令逐项标注来源
```

- bootstrap 的 `presets` 为有序声明，后者覆盖前者（类似 eslint extends）；
- preset 文件哈希不符（用户改过）→ 保留 `.local` 副本并提示，不静默覆盖。

## 7. 新增专业包流程（三步）

1. 在 packs/类型/名称/ 下建目录；
2. 写入 SKILL.md（入口）与 meta.json（元数据）；
3. 提交 PR → 人审合并 → 打 tag → 全景图自动更新。

> 本地新增的候选包/角色/配置不直接入库，先进个人 staging/，走「自动打标 → 台账 → 人工复核 → 转正」统一升级路线（见 [01 第 4 节](./01-架构总览.md)）。

## 8. 个人项目信息安置规约

> 原则：**中央仓库只存通用架构**；个人记忆、学习/评测、会话事件、交付物、输出、会议、研究、调度、插件、本机基础设施等个人项目信息按强制规约安置在个人目录，不入库。

- **个人目录根**：由部署期 `bootstrap.storage.personal` 配置提供（支持 `icloud://<root>/` 逻辑 URI，通过显式 AVC_ICLOUD_ROOT 映射；也可配置绝对或仓库相对路径，必须包含 projects/<slug> 层级）
- **项目级位置**：`<个人目录根>/projects/<slug>/<dir>`（slug = 仓库名）
- **仓库内相对引用**：按部署配置解析（iCloud 部署下形如 `../<root>/projects/<slug>/<dir>`，按引用文件深度叠加 `../`）
- **完整强制骨架**（固定目录、manifest/state、命名规则、doctor 校验、preset/custom、staging/experience）见 [08-个人目录规约](./08-个人目录规约.md)。
