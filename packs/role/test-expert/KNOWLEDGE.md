# test-expert · 专业方法

## 方法与证据边界

本包内容类型为 `method_template`，是可复用流程候选；未附本模板的实测、独立评审或生产收益证据。`candidate` 表示待当前任务验证，不表示历史成绩延续。岗位说明不证明自然人身份、已连接工具、实际参与或能力认证。

## 当前任务介入

先建立关键链路、状态、失败代价和证据矩阵；早期与产品、设计核对验收口径，与实现者核对稳定契约和数据隔离。测试数量不能代表质量或能力。

## 主张、风险与同层证据

对每个关键主张记录最大失败风险、环境/版本/身份、所需证据与结论；失败风险应可被反驳，证据直接命中。构建、静态、截图、Mock、浏览器、真实接口/数据库及生产证据逐层标注，组合证据不能自动升级未覆盖层。

UI 视觉与交互、本地与远端、分支与集成、所有权与副作用分别验收。并发验证用相称真实数据库、独立连接、成功数和终态；CountDownLatch 不保证 SQL 实际重叠。共享文件明确单写者和集成负责人。

unknown 可分 existence（是否发生）、semantics（业务口径）、scope（环境/版本/覆盖）、terminal（终态/副作用），可多标签；按最高失败风险决定观察、补证或阻断，记录事实所有者与关闭条件。发布授权始终独立。

理解验收保留初答、修订、核心语义来源和帮助程度，按五维分别记录，不设总分；少展示不能变为少验证，AI 代做不能计学习者能力。采用示例（假设）：同业务键的并发、超时、重复回执测试同时核对外部副作用和对账终态。拒绝示例（假设）：测试绿色而未连接真实扣款环境便关闭重复风险。

详情：[主张—证据门禁](CLAIM_EVIDENCE_GATE.md)。

## 类型化判断

1. 分开取证、有限判断与生成；确定性事实优先由程序直出。单项低风险且证据充分的判断可由负责人直接完成，多项同状态且判断成本显著时才使用可用判断器。
2. 状态包只包含本题必要的主张、风险、环境/版本、来源、选项、硬门槛和 unknown；预先冻结 yes/no、choice 或 score 的语义与尺度，同状态问题一次批处理。
3. 低把握、证据冲突、高风险、不可补偿风险或工具不可达项标记 `escalate: true`，回到负责人裁决或补证；机器先验、人工基线和最终裁决分栏记录，升级项不得继续自动执行。
4. 判断器不生成开放式方案，不授予数据、安装、账号、发布或删除权限；工具名字不证明可用。事实在文件时用受控脚本传入，避免无关日志进入上下文。

## 有界规划—执行—审查

已有测试、单用例、简单断言和常规冒烟直接完成；跨模块策略、疑难回归、AI 评测体系或首次高风险验收设计才评估额外协作成本。只有复杂度与成本确需多角色时才增加规划/执行/审查通道。先检查当前平台、模式、模型、预算、工具与权限；未登记或未验证的能力保持 `unknown`。默认最多两轮审查，仍不通过时停止并提交冲突、证据、影响与选项给当前决策者，不循环空转。

执行通道不改变任务分级、授权、证据、顾问状态或收口要求；多个代理不能自动算多名员工参与。共享节点健康状态按运行配置维护，不写入个人经验；远程首错只记录瞬时失败，有界退避与确认阈值可配置，成功清零，缓存按 TTL 重探。本地存在性检查一次即可；关键节点缺失且不能安全降级时保持 blocked。

## 复用与复核

命中时记录采用/拒绝理由、目标环境和证据缺口；摘要只负责发现，正文不替代当前用户授权和项目事实。来源、版本、风险、权限或契约变化，出现反例或正文漂移时停止直接采用并复核。效果验证应预先约定可比样本与指标，如返工、遗漏、人工时间和缺陷；没有基线与真实样本时收益为 `unknown`。
