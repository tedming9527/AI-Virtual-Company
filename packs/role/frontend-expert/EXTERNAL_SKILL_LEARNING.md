# 外部前端方法：框架与系统一致性

- ID：`frontend-framework-aware-delivery`
- Owner：`frontend-expert`
- 内容类型：`method_template`
- 状态：`candidate`
- 证据：本模板无实测、独立评审或生产收益证据；以下示例为假设，不是历史运行记录。

## 触发

陌生框架项目跨页面改动、性能/可访问性审查、组件 API 或共享状态改造。

## 稳定行动规则

先建最小架构地图，按现有边界审查数据/状态所有权、完整状态、输入方式、可访问性、响应式、渲染/包体与设计一致性。性能先查请求瀑布、重复请求和大依赖；组件 API 膨胀时评估组合式重构，不为抽象而抽象。

外部 Skill 只作候选方法，使用前核对来源、当前版本、适用技术栈与项目约束；检索不授权安装或执行外部脚本。研究时间和成本上限由任务配置。

## 假设示例与反例

应采用：复用路由壳、查询缓存、表格/空态组件与 token，确认依赖后并行独立 I/O，覆盖 loading/empty/error/permission/窄屏。

不应采用：未查约定便引新状态库、样式或平行组件；仅因多个 boolean props 重写全部组件；未测量声称性能改善。

## 候选参考入口

[Vercel agent-skills](https://github.com/vercel-labs/agent-skills) 中的 React 最佳实践、Web 设计指南与组合模式可作定向候选；[第三方前端设计方法](https://github.com/PracticalSwan/agent-skills/tree/main/frontend-design) 只作辅助线索。来源名称不证明当前内容、安装、运行或目标项目适用性，使用前重新读取并核对版本。

## 边界与复核

某框架建议不能自动套另一个框架或数据层。目标版本、bundle/性能、设计与接口须当前核验；地图、公开指南和构建不证明实际可访问性或收益。记录实际复用、检查与证据，来源变更、框架不匹配或反例时停止采用。

本方法不扩大当前用户授权；结论仅限本次实际取得的证据层。
