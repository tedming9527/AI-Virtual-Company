# 跨系统业务终态证据

- ID：`backend-cross-system-terminal-evidence`
- Owner：`backend-expert`
- 内容类型：`method_template`
- 状态：`candidate`
- 证据：本模板无实测、独立评审或生产收益证据；以下示例为假设，不是历史运行记录。

## 触发

跨服务副作用涉及重试、超时、回调、租约重领、金额或库存变化，本地执行成功不能直接证明远端成功。

## 稳定行动规则

1. 用稳定业务键标识同一次操作，分别记录本地所有权、远端引用、尝试次数、最后证据与人工责任。
2. 本地短事务只声明本地真相，原子写状态与审计，用条件更新防止旧执行者覆盖。确需异步可靠投递时增加 outbox 或等价持久意图；同步可核验且无此需求时不强制。
3. 远端超时进入 unknown，先查终态/对账；明确未受理才同键有限重试。不可查询、不可去重或证据冲突时转人工，不用租约承诺 exactly-once。
4. owner/token 只保护检查它的资源，租约到期不终止旧 worker；fencing 须下游执行。分别验证领取、本地条件回写和远端副作用。

## 假设示例与反例

应采用：扣款超时保存业务键与远端引用，查询/对账后决定有限恢复或人工处理，金额精度和尾差按当前契约确认。

不应采用：afterCommit 后远端调用/消息丢失，本地事务仍可能成功；把异常降为金额 0、成功或失败会掩盖 unknown。重领生成新业务键可能重复副作用。

## 边界与复核

适用于可定义业务键并保存恢复状态的操作。纯函数时间边界测试只支持对应本地算法；不证明持久化、数据库时区、并发领取或下游终态。H2、Mock、同进程测试和锁所有权不得外推生产。

下游不支持幂等或查询时明确受限方案或 blocked。下游契约、隔离级别、金额精度、对账责任或 SLA 变化时重新核验。可比真实任务记录相关返工、重复/漏副作用、人工量、关闭时间、unknown 超期与上线后补偿；真实下游能力、数据库并发与收益在取得当前证据前为 unknown。

本方法不扩大当前用户授权；结论仅限本次实际取得的证据层。
