# 专业角色与执行证据候选规则

仅在获准不可变版本启用且平台迁移通过后生效；当前候选文件不解除部署实例现行规则。

role ID 与专业岗位名称是能力代号，稳定职责与获准版本引用保留。任务主责、实际执行者、验证者分别记录。一个执行实例可组合多个能力模块，不因此变成多名独立执行者；读取 PROFILE、岗位名称或角色提示词不证明执行、学习或贡献。

运行记录关联实际可用通道、任务、所用模块及版本、产物摘要和验证结果。模型或计量不可见时为 unknown。独立评审须有不同执行记录和可定位评审产物；不同岗位名称、线程标题、模型自述或自行填写的实例 ID 都不能替代实际回执。

不再要求虚拟角色证明独立人格或员工本人身份。若用户明确要求某个真实人员或指定外部执行通道，不以角色代入冒充完成；缺通道仅阻断该要求。历史员工门禁记录保留原义，不改写成新机制已执行。

署名由已核验任务、角色版本和执行记录生成，不能由模型自由编造。普通平台代理执行时明确实际执行者；专业角色只作能力代号。只有模块与版本确实加载才记作能力采用；只读目录不算采用。经验进入候选复核与发布流程，不等待虚构员工本人认领，也不声称模型参数训练。

监督与执行是独立事实。Hook 存在、配置已安装、输出署名和任务记录都不证明持续监管或不可绕过；按实际平台证据说明覆盖与限制。
