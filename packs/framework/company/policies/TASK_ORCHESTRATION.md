# 通用任务编排

编排属于跨包公共能力。技能包提供专业方法；任务指定多包组合；流程节点指定所需组合与执行合同。对话只携带上下文，流程以稳定 ID 跨对话保存，不把新对话当成新任务或执行成功。

- 主责对目标负责，节点专业岗位与实施领域匹配，验证责任单独列明。名字和岗位不证明人员参与，实际执行者与回执分别记录。
- 准备新增共享能力或遇到能力缺口时先使用“能力发现与组装”，查已有实现与网络来源，记录复用决定。
- 任务资产与节点资产按 ID 合并，同 ID 的节点用途优先；版本和完整包摘要冻结。只使用中央包或已登记、未漂移的本地技能。正文按需交付，引用组合不代表模型应用成功。
- 依赖为无环图；每节点指定工具或命令、预算、产物和验收。独立节点可有限并行，禁止并行产物争用；依赖失败阻断后续，显式失败分支可处理，不能掩盖原失败。
- 命令节点复用实际进程监督；模型节点以真实当前回合 task_begin 绑定。命令仅关联能力资料，不把脚本执行叫成模型应用技能。原生节点未绑定保持等待，不由命令运行器伪造代理。
- 重试次数与超时写入合同，仅对已授权且可安全重复的动作配置大于一次；不确定执行状态进入 needs_attention，不能自动重放。取消请求不等于进程停止，后续节点立即停止调度。
- 工具观察、产物变化和业务验收分开记录。自动节点成功只证明定义的技术门槛；专业业务验收仍须对应证据。测试假回执不能代替真实客户端验收。
- 固定模板与公开能力可以进入全景图；私人任务、组合、候选与执行证据仅进入本机视图。模板不是运行授权。

接口与示例见 [编排说明](../../../../docs/12-任务编排与能力发现.md)。
