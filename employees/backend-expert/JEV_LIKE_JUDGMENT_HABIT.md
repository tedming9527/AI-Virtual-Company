# 后端岗位 JEV-like 判断习惯

- 稳定 ID：`backend-jev-like-judgment-habit-v1`
- 状态：`reviewed_case`
- 复核日期：`2026-09-22`
- 岗位负责人：陆行远 · 可靠服务官（Backend Engineer）
- 复核人：顾清妍 · 质量工程师（Test Expert）
- 适用范围：后端测试分诊、发布就绪判断、迁移处置与下一步动作选择

## 触发

当后端任务需要判断“测试是否通过、严重性多高、应执行哪个有限动作、迁移应采用哪个已枚举处置”时，先启动本习惯。若事实尚未取得，先取证；若任务要求生成代码、SQL、方案或开放式解释，直接由岗位负责人处理，不强行转成判断题。

JEV MCP 是可选实现，不是流程前提。JEV 不可达时仍按同一判断循环运行；文件或工具输出中的大批事实优先由脚本管道交给 `jev-use judge` CLI，避免原文进入主对话。MCP 成功不代表 CLI 同时可用。

## 岗位判断循环

1. **分流**：标记任务为判断、取证或生成。只让可类型化判断进入后续步骤。
2. **压缩状态**：只保留目标、已证实事实、未知项、约束、候选动作和停止条件；不得把推断伪装成事实。
3. **类型化**：是否成立用 `noul`，互斥动作选择用 `choice`，有序质量或严重性用 `score`。
4. **冻结尺子**：先写清选项、等级、通过门槛和责任人，再看答案；选项应互斥且尽量穷尽。
5. **同状态批处理**：同一事实包上的问题一次判断；状态改变后另开批次，禁止为了得到“通过”反复刷结果。
6. **显式不确定性**：记录 `answer / confidence-or-unknown / escalate / reason`；无可靠校准时不用伪精确小数。
7. **升级改变控制流**：事实冲突、选项不全、低置信、`unsure`、`unreachable`、高风险或开放式任务立即停止自动采纳，交回陆行远 · 可靠服务官或对应具名责任人。
8. **执行未升级项**：只执行证据覆盖且未升级的离散结论；JEV 先验、人工基线和最终责任人裁决分栏记录。
9. **事后校准**：用真实结果复查题型、阈值和选项；没有可比生产样本时不宣称提速、节省或准确率提升。

## 岗位最小模板

```text
ID: <稳定判断 ID>
STATE: <目标 / 已证实事实 / 未知项 / 约束 / 停止条件>
QUESTION: <noul|choice|score> <问题>
OPTIONS_OR_LEVELS: <先冻结的互斥选项或有序等级>
EVIDENCE: <测试、日志、迁移或接口证据引用>
RESULT: <answer / confidence-or-unknown / escalate / reason>
OWNER: <具名岗位负责人>
NEXT_ACTION: <只执行未升级项；升级则写接手人与补证据动作>
```

## 采用例

合成预发布验证中，单元测试 418/418 通过、集成测试 37/38 通过；并发幂等测试出现重复写，影子库缺少目标唯一约束，且已有 12 个重复键。可先冻结四个判断：发布是否通过（`noul`）、严重性（`score`）、下一步（`choice`）、迁移处置（`choice`），共享一次最小 state 批量判断。有效、未升级的离散结论是“不放行、重大、整改后重测、整改后分阶段部署”；具体去重 SQL、锁评估与回滚设计仍交给陆行远 · 可靠服务官。这里采用的是判断循环，是否调用 JEV MCP 不影响责任归属。

## 拒绝例

请求“根据部分日志直接生成生产去重 SQL，并由 JEV 独立批准不可逆迁移”必须拒绝进入自动判断：SQL 生成不是可枚举判断，部分日志不足以证明数据状态，不可逆生产动作也不能由 JEV 作为唯一决策者。正确动作是补齐数据分布、约束、锁影响、备份与回滚证据，由陆行远 · 可靠服务官设计方案并由发布责任人审批；JEV 最多辅助已枚举的风险分流，任何升级项均停止自动执行。

## 边界

- 本卡仅为已复核的去身份化模拟案例沉淀，状态为 `reviewed_case`；生产收益、长期准确率、真实提速、token 节省和发布质量均为 `unknown`。
- 使用本卡或 JEV MCP 不扩大数据范围、系统权限、外部写入授权或岗位责任。敏感数据不得因工具可用而外发。
- JEV MCP 可选；不可达、低置信或 `escalate: true` 时按岗位循环回退，不得刷调用直到通过。
- 生成任务、开放式设计、证据冲突、高风险或不可逆事项，以及所有升级项，仍由陆行远 · 可靠服务官或对应具名岗位负责人处理。
- 机器 verdict 是类型化先验，不替代测试证据、数据库事实、接口契约、变更审批或专业验收。
