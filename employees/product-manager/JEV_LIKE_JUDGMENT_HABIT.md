# 产品岗位 JEV-like 判断习惯

- ID：`product-jev-like-judgment-habit`
- 状态：`reviewed_case`
- 日期：2026-09-22
- Owner：林知夏 · 目标规划官（Product Manager）
- Reviewer：顾清妍 · 质量测试工程师（Test Expert）
- 置信度：medium；已复核模拟案例，生产收益与长期稳定性未知

## 触发

当产品工作进入优先级、试点继续/暂停/放量、证据等级、护栏状态或下一验证动作等“基于既有事实做判断”的阶段时，先运行本循环。是否调用 JEV MCP 是可选实现，不是循环成立的前提。

先分流任务性质：

- **判断**：事实已存在，答案可表达为真假概率、互斥动作或有序等级，进入判断循环。
- **取证**：关键事实缺失、冲突或过期，先补证据，不能用判断工具填空。
- **生成**：需要提出新策略、撰写 PRD、生成选项或解释开放问题，由林知夏 · 目标规划官或相应岗位负责人处理，不交给 JEV。

## 岗位判断循环

1. **压缩状态**：只保留产品目标、已证实事实、未知项、约束/护栏、候选动作和停止条件；原始大文件保留引用，不为调用工具整份搬入对话。
2. **冻结判断结构**：按需要选用 `noul`（真假/概率）、`choice`（互斥动作）或 `score`（有序质量）；先写清 true/false、选项含义、等级和验收规则，再看答案。
3. **核对硬门槛**：事实可获得、任务可类型化、选项/等级清楚、状态可压缩、升级项有具名接手人，五项必须同时成立。多数票不能补偿任一硬门槛失败。
4. **同状态批处理**：一次处理同一事实包上的全部判断；状态变化后开新批次，不逐题重复加载背景。
5. **显式不确定性**：有 JEV 时记录 `answer / confidence / confidenceFrom / escalate`；无 JEV 时只用 `high / medium / low / unknown` 或证据等级，不伪造精确概率。
6. **升级改变控制流**：`unsure`、`unreachable`、事实冲突、选项不全、开放式问题、敏感/高风险或不可逆事项均暂停自动采纳，交回具名岗位负责人补证据或裁决。
7. **分离来源并收缩输出**：机器先验、人工基线和责任人最终结论分别记录；只执行未升级项，并保留稳定 ID、理由、责任人和下一动作。
8. **事后校准**：用真实结果检查门槛和等级是否过严或过松。没有可比样本时，生产准确率、提速、节省 token 和真实用户收益均保持 `unknown`。

JEV 是否值得调用采用三层判断：

- **硬门槛**：上述第 3 步全部满足，且数据和授权范围不因工具而扩大。
- **价值增强**：同状态多判断、重复度高、选项稳定、结果可撤销或有后续保护；满足越多，调用价值越高，但不是安全门槛。
- **生产化条件**：准备长期或自动化使用前，另行闭环真实凭据与连接、MCP/CLI 分通道可达、日志审计、SLO、成本、校准、独立测试集、失败回退、隐私与责任人。

## 证据

1. [林知夏产品岗位训练](../../learning/jev-mcp-training-2026-09-22/product-manager.md)：两个去身份化合成案例共取得 10 个有效 verdict；8 个未升级项与冻结人工基线同方向，2 个 `score` 为 `unsure`，均停止直接采纳并由岗位负责人按硬规则复核。
2. [全员训练报告](../../learning/jev-mcp-training-2026-09-22/REPORT.md)：八岗内容验收 `pass=8 / partial=0 / fail=0`；确认 JEV-like 循环可脱离 MCP 运行，JEV 是可选的类型化判断加速器，不是前提。
3. [独立质量复核](../../learning/jev-mcp-training-2026-09-22/quality-review.md)：林知夏七项要求全部 `pass`；复核同意用“硬门槛 / 价值增强 / 生产化条件”替代扁平多数投票，并要求所有 `unsure` 人工升级。

这些证据只证明已复核模拟案例中的行为与记录完整性。有效 MCP 后端记录不能证明 CLI 同时可达，也不能证明端到端提速、成本下降、token 节省或生产准确率。

## 岗位最小模板

```text
JUDGMENT_ID: <稳定ID>
OWNER: <名字 + 职务>
STATE:
  goal: <目标>
  facts: <已证实事实>
  unknowns: <未知项>
  constraints: <授权、护栏、停止条件>
QUESTIONS:
  - id: <id>
    type: <noul|choice|score>
    options_or_levels: <互斥选项或递增等级>
    acceptance_rule: <采纳标准>
RESULTS:
  - id: <id>
    answer: <答案或null>
    confidence: <值或unknown>
    source: <JEV|人工基线|负责人裁决>
    escalate: <true|false>
    reason: <证据或升级原因>
DISPOSITION:
  owner: <最终责任人>
  next_action: <采纳|补证据|复核|停止>
```

## 采用例

场景：试点准备决定 `scale / continue_pilot / pause_fix / stop`，已有固定指标、样本可比性、数据完整率、严重错误、隐私事件、成本和明确护栏。

采用方式：压缩同一状态；用 `noul` 判断放量门槛与因果归因，用 `choice` 选择下一动作，用 `score` 评估证据等级；一次批处理。若 `score` 为 `unsure`，停止直接采用，由林知夏 · 目标规划官按已冻结的混杂与证据规则裁决。JEV 可用时可调用，不可用时使用同一模板人工完成。

为什么采用：事实和选项可枚举、同一状态有多个判断、护栏明确、升级后有责任人，满足硬门槛。

## 拒绝例

场景：要求“读取未经授权的原始客户访谈，直接生成新产品战略和完整 PRD，并自动决定不可逆全量发布”。

拒绝方式：不把任务包装成 `choice` 或 `score`，不向 JEV 发送原始客户数据，也不让 JEV 成为发布的唯一决策者。先确认数据授权；由产品负责人完成开放式问题定义与方案生成；再由相应责任人对发布证据、风险和权限做独立裁决。

为什么拒绝：它同时包含未授权数据、开放式生成和不可逆高风险决定，违反硬门槛；其他“适合 JEV”的条件再多也不能补偿。

## 边界与复核触发

- 本卡仅为 2026-09-22 已复核的去身份化模拟案例，状态为 `reviewed_case`；生产收益、长期稳定性、真实用户影响与自动化安全均为 `unknown`。
- JEV MCP 可选。MCP 不可用时按同一循环人工处理；任务明确要求工具不可用即停止时，记录升级后停止，不用 mock 或其他模型冒充。
- 工具使用不扩大数据、隐私、授权、发布或外部写入权限；敏感数据先按原权限边界处理。
- JEV 只承担类型化判断。生成任务、升级项、高风险/不可逆决定和最终责任仍由林知夏 · 目标规划官或相应具名岗位负责人处理。
- 以下情况触发复核：出现真实任务反例；选项或等级不再互斥；JEV/人工结论与结果持续偏离；MCP/CLI、模型、阈值或权限边界变化；累计至少三个可比生产任务可评估收益。
