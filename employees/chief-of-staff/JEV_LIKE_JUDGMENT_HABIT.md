# 路由岗位 JEV-like 判断习惯

- 稳定 ID：`chief-of-staff-jev-like-judgment-habit`
- 状态：`reviewed_case`
- 日期：2026-09-22
- 负责人：陈知行 · 路由官（Chief of Staff）
- 复核人：顾清妍 · 质量测试工程师
- 证据等级：已复核的去身份化模拟案例
- 生产收益：`unknown`

## 触发

当路由任务同时具备以下特征时，启动本习惯：事实已经可获得，需要在同一事实包上完成多项分流、监督充分性、停止条件或下一步动作判断，并且问题能表达为真假/概率、互斥选项或有序等级。

以下情形不直接进入类型化判断：事实仍缺失、需要生成任务书或说明文字、选项不能可靠枚举、题目混合多个责任维度、涉及权限扩大，或结论可能触发高风险/不可逆动作。这些情形先取证、拆题或交由具名岗位负责人处理。

## 岗位判断循环

1. **先分流性质**：区分判断、生成和取证。只有可类型化判断继续；生成由岗位负责人完成，缺事实先取证。
2. **压缩状态**：只保留目标、已证实事实、未知项、约束、候选动作、监督证据和停止条件。
3. **拆开责任维度**：主责分配、执行动作、监督门禁、发布状态和授权分别判断，不把不同层级混成一个选项集合。
4. **冻结题型与尺子**：在看答案前确定稳定 ID、`noul`/`choice`/`score`、互斥选项或有序等级、接受标准和升级条件。
5. **选择实现通道**：JEV MCP 只是可选实现；上下文内的同状态判断可批量使用 MCP，文件或工具输出中的批量事实应按适用规则由脚本处理。工具不可用时仍按相同结构人工判断。
6. **同状态批处理**：一次处理同一事实包上的全部判断；事实发生变化后才开启新批次。
7. **显式不确定性**：保留答案来源、`confidence` 或人工的 `high / medium / low / unknown`、`escalate` 与理由；没有校准接口时不伪造精确概率。
8. **升级改变控制流**：事实冲突、选项不全、题目含混、低把握、状态过大、开放式生成或工具不可达时，停止自动采纳，补证据、重构问题或交回具名负责人。
9. **只执行未升级项**：机器先验、人工基线和最终裁决分开记录；升级项的原答案最多作为 prior，不能冒充门禁通过。
10. **事后校准**：用真实结果复核选项、阈值和停止条件。没有真实可比样本时，生产准确率与收益保持 `unknown`。

## 证据

- [路由岗位训练记录](../../learning/jev-mcp-training-2026-09-22/chief-of-staff.md)：去身份化模拟批次中，6 个未升级判断与冻结人工基线同方向；一个把“修复主责”和“发布门禁”混在一起的问题返回 `unsure`，停止采纳后拆为两题复测，分别得到未升级结果。
- [全员训练报告](../../learning/jev-mcp-training-2026-09-22/REPORT.md)：八岗最终为 `pass=8 / partial=0 / fail=0`，并把压缩状态、类型化、冻结选项、批量判断、显式不确定性、升级例外和收缩输出确认为可脱离 JEV 的日常判断循环。
- [独立质量复核](../../learning/jev-mcp-training-2026-09-22/quality-review.md)：顾清妍 · 质量测试工程师对路由岗位七项要求判定为 `pass`；同时确认 CLI 文件复核曾 `unreachable`，复核结论来自人工完整回读，不能扩展为工具稳定性或生产效果证明。

以上证据只支持“该习惯在已复核模拟案例中可执行”。训练文件中的 MCP 元数据缺少统一原始服务端收据，人工侧也没有同口径耗时与 token 基线，因此不据此宣称生产提速、降本、准确率提升或长期稳定。

## 边界

- 本卡是 `reviewed_case`，不是生产策略验收；生产收益、真实准确率和长期效果均为 `unknown`。
- JEV MCP 可用时可加速类型化判断，不可用时岗位判断循环仍完整运行；MCP 成功不代表 CLI 同时可达。
- 使用 JEV-like 结构不扩大数据范围、访问权限、审批权限、发布权限或外部发送权限；输入仍服从原任务的数据与授权边界。
- JEV 或人工类型化判断都不得成为高风险或不可逆事项的唯一决策者。
- 生成任务、开放式写作、不可枚举问题、`unsure`/`unreachable`/低把握等升级项，仍由陈知行 · 路由官（Chief of Staff）或相应具名岗位负责人接管并承担最终判断。
- 未经独立真实样本、分通道可达性、失败回退、阈值校准和结果审计，不把本卡升级为生产自动化规则。

## 岗位最小模板

```text
CASE_ID: <稳定 ID>
STATE: 目标 / 已证实事实 / 未知项 / 约束 / 监督证据 / 停止条件
QUESTIONS:
- id=<稳定题号>; type=<noul|choice|score>; options-or-levels=<冻结定义>; acceptance=<通过标准>
RESULTS:
- id=<题号>; answer=<答案>; confidence=<数值或 high|medium|low|unknown>; source=<JEV|人工>; escalate=<true|false>; reason=<原因>
OWNER: <具名岗位负责人>
NEXT_ACTION: <只执行未升级项；升级项补证据/拆题/人工裁决>
BOUNDARY: <数据、权限、发布与不可逆风险边界>
```

## 采用例

已复核模拟案例中，一个接口故障位于后端缓存键，但缺少变更审批和回滚演练。采用本循环后，不把“谁修复”和“能否发布”混为一题：

- `fix_owner`：在后端工程师、前端工程师、测试工程师、安全顾问之间选择修复主责；结论为后端工程师。
- `release_gate`：在继续发布、停止并补齐审批与回滚证据之间选择；结论为停止发布并补证据。

采用理由：两个问题均能基于同一最小事实包类型化，选项互斥，停止条件明确；拆题后既保留责任归属，又没有用修复责任替代发布授权。该例只证明模拟案例中的判断结构有效。

## 拒绝例

拒绝把“请生成跨岗位任务书，并决定是否立即向新外部接收方发送数据”整体交给 JEV 或机械选择流程。

拒绝理由：任务书属于生成任务；新的外部接收方涉及数据和授权边界；“立即发送”在缺少接收方授权与数据处理证据时可能造成不可逆外部影响。正确处理是由路由官先冻结发送停止条件、补齐授权与数据处理证据，再把可枚举的“证据是否齐备/下一步是哪一个”作为辅助判断；任何升级项和最终外发决定仍由具名岗位负责人承担。
