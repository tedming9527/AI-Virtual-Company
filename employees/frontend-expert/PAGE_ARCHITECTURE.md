# 独立页面架构与设计实例核验

## 2026-09-16 · 独立页迁移的先决检查

- ID：`frontend-page-architecture-visual-validation`；状态：`candidate`。
- Owner：周启明 · 体验工程官（Frontend Engineer）；review：自审；confidence：medium（一次真实项目复盘）。
- 触发：将弹窗、抽屉或局部浮层迁为独立路由页，且需按 Figma 还原页面视觉。
- 决策：先确定三层职责：路由页拥有页面壳、通用导航和加载/错误/内容状态；内容组件只渲染业务区块；样式按页面壳与内容区块分层。不得把旧浮层根节点、导航和列表职责原样迁入同一组件。
- 设计核验：以目标节点的实际实例尺寸、截图和标注交叉确认；通用组件变体或生成代码默认值只能作线索。实现前列出页面外边距、容器内边距、控件尺寸和元素间距，检查其合成值后再写样式。
- 设计协作：Figma 还原、视觉层级、组件状态或交互取舍涉及设计判断时，苏映雪 · 信任设计官（Design Master）必须实际参与。开始实现前共同确认目标节点、关键尺寸、状态与验收证据；结束时记录其实际发现和处理结果。未获得这些产物时，协作方应登记为 none，不得把可咨询角色写作已参与。
- 验收：从路由页入口覆盖正常、加载、错误、返回及选择后的数据刷新；仅渲染内容组件的测试不能证明独立页结构正确。
- 采用例：把一个选择浮层改为独立页时，先由页面入口承载导航与全部状态，再将搜索和列表抽为纯内容组件，并以目标实例验证尺寸。
- 拒绝例：先复制旧弹窗组件到新路由，再通过多轮局部 CSS 补丁修正导航归属、尺寸和边距。
- 证据：一次真实页面迁移中的用户反馈、目标设计实例核验和路由入口定向测试；其中未形成设计师实际交接，被识别为协作证据缺口。证据证明该项目的复盘结论，不证明长期返工率改善。
- 适用边界：不替代具体框架的路由规范、无障碍要求或真实接口契约；设计实例缺失时不得臆测数值。
- 复核触发：下一个同类独立页任务，检查该流程是否减少结构返工；出现反例、设计工具输出与实例不一致时复核。
