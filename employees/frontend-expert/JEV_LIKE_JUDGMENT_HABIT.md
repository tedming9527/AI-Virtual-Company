# 前端 JEV-like 类型化判断习惯

- 稳定 ID：`frontend-jev-like-judgment-habit`
- 状态：`reviewed_case`
- 日期：2026-09-22
- Owner：周启明 · 体验工程官（Frontend Engineer）
- Reviewer：顾清妍 · 质量测试工程师（Test Expert）
- 证据性质：已复核的去身份化模拟案例；生产收益 `unknown`

## 触发

前端任务已取得最小充分事实，需要对构建、测试、无障碍、响应式、性能预算、回归严重度或候选版本下一动作作有限判断时，使用本循环。若事实仍在构建日志、扫描报告或测试输出中，先保留在文件/工具侧处理；若尚缺浏览器、设计、接口或运行证据，先取证，不用判断模板填补未知。

以下情况不触发本循环的自动判断部分：需要生成新组件、代码、文案或设计方案；选项尚不能枚举；涉及未经授权的数据或动作；高风险、不可逆或升级项没有具名接手人。

## 岗位判断循环

1. **分流性质**：先标记为 `evidence`、`judgment` 或 `generation`。只有事实充分且可枚举的 `judgment` 继续；`generation` 由岗位负责人完成，缺事实先取证。
2. **压缩状态**：只保留目标、已证实事实、未知项、验收规则、候选动作和停止条件。不得用长叙事掩盖证据缺口。
3. **分开证据类型**：构建退出码、测试结果、浏览器行为、无障碍检查、视觉对照和接口状态分别标明来源；一种证据不得冒充另一种验收。
4. **类型化问题**：真假/概率使用 `noul`，互斥动作使用 `choice`，有序成熟度使用 `score`。无法形成有限且清晰的选项时，返回负责人而不是强行选择。
5. **冻结选项与门槛**：在查看答案前写清 true/false 语义、互斥动作、等级定义及发布阻断条件，避免事后移动标准。
6. **同状态批处理**：一次处理同一候选版本上的构建、回归、无障碍和下一动作；状态发生变化后再开启新批次。
7. **显式不确定性**：有 JEV 时保留 `confidence / confidenceFrom / escalate`；无 JEV 时使用 `high / medium / low / unknown` 或证据等级，不伪造精确小数。
8. **升级改变控制流**：事实冲突、选项不全、低把握、开放式问题、工具不可达、高风险或不可逆时，标记 `escalate=true` 并暂停自动采纳；由周启明 · 体验工程官或任务中具名专业负责人补证据、裁决或停止。
9. **只执行未升级项并校准**：结果按稳定 ID 记录来源、责任人和下一动作；事后用真实结果复核门槛。没有可比生产样本时，生产准确率、提效和 token 节省均为 `unknown`。

JEV MCP 是这个循环的可选执行器，不是前提。短且已在上下文中的同状态判断可批量交给 MCP；大量事实仍在文件或工具输出时由脚本管道给 CLI；JEV 不可用时按相同结构人工判断。无论是否使用 JEV，授权、数据范围、发布权限和最终专业责任都不会扩大。

## 岗位最小模板

```text
ID: <稳定判断 ID>
TRIGGER: <为什么现在需要判断>
MODE: evidence | judgment | generation
STATE:
- goal: <目标>
- facts: <已证实事实及来源>
- unknowns: <未知项>
- acceptance: <冻结的验收/阻断规则>
- stop: <停止条件>
QUESTIONS:
- id=<id>; type=noul; true=<含义>; false=<含义>
- id=<id>; type=choice; options=<互斥动作>
- id=<id>; type=score; levels=<从低到高的等级>
RESULTS:
- answer=<答案>; confidence=<值或 high|medium|low|unknown>;
  escalate=<true|false>; reason=<原因>; owner=<具名负责人>
NEXT_ACTION: <执行 | 补证据 | 生成方案 | 停止>
```

## 采用例

合成筛选抽屉在 320 CSS px 出现横向滚动并把 Apply 按钮挤出屏幕；375、768、1440 CSS px 通过；构建成功；已列无障碍检查通过；软包体预算超出但未到硬上限。验收标准已明确要求 320–1440 CSS px 流程可操作且无横向页面滚动。

- 这是事实充分、选项可枚举的发布分诊，采用本循环。
- 一次批量判断：构建是否成功（`noul`）、下一动作（`choice`）、准备度（`score`）、首要阻断项（`choice`）、修复后首项验证（`choice`）。
- 冻结动作选项为 `ship / ship_with_followup / fix_then_rerun / rollback`。
- 根据既定标准，响应式回归进入 `fix_then_rerun`；包体软告警留作跟进；修复后先复测 320 CSS px 的按钮可达性和横向滚动。
- 若无障碍门禁答案低于阈值或状态只证明“已列检查通过”，该项升级给负责人，不用机器先验替代完整审计。

这个例子采用的是类型化循环；是否调用 JEV MCP 取决于可达性、数据边界和调用价值。

## 拒绝例

需求为“重新设计结账页，让它更高级、更有品牌感，并写出完整 React 实现”，但没有设计系统、目标用户、品牌原则、候选方案或验收标准。

- 这是开放式生成加证据缺口，不是可枚举判断，拒绝交给 JEV 或强行套成 `choice`。
- 先由周启明 · 体验工程官澄清技术边界，并由相应设计负责人提供真实设计输入；代码、文案和布局仍由具名负责人生成与验证。
- 后续只有在候选方案和可观察标准已经形成时，才可把其中有限的合规、回归或准备度问题纳入本循环。
- 不因启用 JEV、CLI 或模板扩大 Figma、仓库、客户数据、发布环境或外部写入权限。

## 边界与失效条件

- 本卡只沉淀已复核模拟案例，不是生产能力认证；真实收益、长期一致性、端到端时延和成本均为 `unknown`。
- JEV MCP 可选；MCP 可用不证明 CLI 可用，工具不可达时必须升级或按人工替代流程执行。
- 文件、日志和工具输出优先留在脚本/CLI 侧；敏感或未经授权的数据不得为了判断而扩大读取、复制或发送范围。
- JEV、JEV-like 模板和置信度都不能替代浏览器、真实接口、无障碍、视觉、构建或回归证据。
- 生成任务、选项不可穷举的问题、`escalate=true` 项及高风险不可逆决定始终由具名岗位负责人处理。
- 若后续真实任务出现反例、阈值失准、来源冲突或权限边界变化，停止直接采用本卡，回到上述三份证据和新的原始结果复核。
