## 触发

页面包含大量 loading、empty、error、角色、活动、订单或容器状态，且视觉与布局仍在快速调整；团队开始为每个页面状态堆积 jsdom 测试，维护成本上升。

## 决策

采用三层验证，不追求“所有 UI 状态自动化”：

1. **Debug 状态浮板覆盖 UI 状态空间。** 在开发或受控测试环境通过显式入口（案例中为 URL `debug=1`）切换页面 ViewModel/fixture，直接观察视觉、布局、文案、按钮和组合状态。
2. **单元测试锁定稳定逻辑。** 保留入口决策、字段转换、项目编码、权限、跳转参数、请求所有权、埋点 payload 等脱离 DOM 仍成立的规则。
3. **页面/端到端测试只守关键旅程。** 仅覆盖失败代价高且跨层的用户路径，如登录授权、下单支付、预约、防重复提交和关键状态流转。

判断标准不是“能不能写测试”，而是：该断言是否保护稳定、昂贵且用户可见的契约；若只是 CSS 类、组件库 DOM、文件路径、普通文案或易变布局，应由浮板人工验收或删除。

## 证据

- `summoner` 远端 `origin/feat/2026_09_10_ddm` 的朴里节相关历史包含多轮背景、布局、字体、跳转和活动状态调整；这类问题高度依赖真实视口与状态组合。用户确认其实际工作方式是 URL 加 `debug=1` 后出现浮板，可快速切换状态查看页面 UI。
- 同一分支保留的朴里节相关测试主要面向 `entryAction`、`projectCode`、`miniProgram`、`tracking`、`userInfo` 等稳定逻辑，支持“状态探索与逻辑回归分层”的方向。
- `azeroth` 静态复核发现大量页面、组件与结构契约测试；部分行为测试能保护筛选、分页、错误恢复和权限，但 CSS 类、文件存在性、迁移结构等断言更脆，且当前检出的入库 CI/Docker 配置没有调用完整 `check`。详见[选择性蒸馏](../../learning/2026-09-13-vanke-frontend-code-distillation.md)和[质量复核](../../learning/2026-09-13-vanke-frontend-code-distillation-review.md)。

## 实施护栏

- Debug 浮板默认不进入生产；若确需线上诊断，必须有内部身份/环境门禁，不得仅凭公开 URL 参数开放。
- 浮板只替换读取侧状态或注入无副作用 adapter；支付、领取、提交、删除、埋点等真实副作用默认禁用。
- fixture 与单元测试共享事实源；不得各维护一份逐渐漂移的状态数据。
- 真实模式必须保持默认路径，关闭 debug 后不得残留 mock 状态、缓存或全局副作用。
- jsdom 不能证明真实视口、滚动、安全区、Portal、WebView/小程序桥接和视觉正确；这些必须在目标容器或浏览器中验收。
- 浮板不能证明业务规则正确、请求竞态安全或后端授权；相应逻辑仍需自动化测试和服务端验收。

## 正例与反例

**应采用：** 活动页要检查加载、失败、无资格、三个入口分别可用、窄屏背景拉伸等十余种组合。用浮板切换场景并在真实移动视口检查；对入口动作、项目编码和跳转参数保留纯逻辑单测；只为一条主活动旅程保留端到端测试。

**不应采用：** 支付页用 `debug=1` 直接调用真实支付接口，再以“人工看起来正常”替代 requestId、防重复提交、金额转换和回调验收。此时浮板只能使用假 transport，稳定规则与关键旅程测试必须保留。
