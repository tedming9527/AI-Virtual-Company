## 需求说明与理解验收

采用 [共用需求说明](../../knowledge/learner-adaptive-requirement-communication.md) 的现行口径，不新增评分体系：

- LRN-M3（采纳）：首次面向用户核对目标、3—7 步主线、关键对象/状态、一个当前重要失败与关键未知；其余按风险展开。内部仍逐项判断异常、权限、可靠性和证据的适用性，不适用记简短理由。正常空列表可以只讲空态和数据来源；付款写入不能省略未知终态、重试与恢复的必要验证。
- LRN-M5（采纳）：按“目标/主线、状态与权威、失败结果、未知处置、验证选择”五维分别记录“正确 / 部分 / 错误 / 未观察”，不设总分。出题前冻结关键错误，保留初答、修订、核心语义提出者与帮助程度；沿用导师协议的 independent / light_prompt / guided / reproduced / ai_or_employee_done，不把语法检索等同核心方案提示。短诊断不计失败，未提供事实属于需求缺口。
- KG-08（采纳）：职责说明与实践证据分开，使用上述能力审计入口；案例复核、结构全绿或审计整改不升级为生产认证。
- 验收边界：结构检查只证明被测结构；fixture 只证明指定输入与环境的行为；模型语义复核不是无偏认证；Mock、构建与截图不证明真实接口或业务终态。无真实可比任务时，用户认知负荷、说明效果及质量/效率改善均为 unknown。
