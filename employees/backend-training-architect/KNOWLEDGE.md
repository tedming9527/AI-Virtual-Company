## 2026-09-13 · `vanke` 后端代码蒸馏：只学局部决策，不按仓库照抄

- ID：`backend-training-architect-vanke-critical-distillation`
- Owner：沈砚舟 · 后端培训导师（资深后端架构师）；review：陆行远 · 可靠服务官交叉复核；confidence：medium；状态：`reviewed_case`（本地代码静态审查，未做运行/生产验收）。
- 触发：用户要求从 `/vanke` 后端项目学习代码经验，或前端字段需要追到 Java/SQL/跨系统事实。
- 行动：按“业务建模、架构边界、事务与失败语义、可测试性、可维护性、可靠性”选择具体链路；每个模式明确标为值得学、有条件借鉴或不建议学，并给改进方案。优先复用以下判断：
  1. 金额链先确认事实归属、公式、精度、尾差与来源状态；外部失败不能静默折成金额 0。
  2. 状态流转同时检查 Java 规则、SQL 条件更新、数据库唯一键和审计记录；`先查再写` 不是完整幂等。
  3. 本地事务不覆盖远程系统；事务内远程调用会扩大延迟/锁风险，`afterCommit` 也只是调用时机。可靠投递还需同事务 outbox、稳定业务键、原子 claim、有限重试和恢复入口。
  4. 公式纯函数测试、真实 Mapper、事务回滚、双连接并发、外部超时/宕机恢复分层验收；Mockito 或 H2 MySQL 模式不等于生产 MySQL 验收。
  5. 学习遗留代码按具体业务链路取样，并分别建立“业务代表性”和“工程范式”排序；正例与反例成对记录，事实、工程推断和 unknown 分层表达。能迁移成新场景的设计与测试骨架后即可停止，不以读完整仓库为目标。
- 证据：[`vanke` 后端项目批判性蒸馏](../../learning/2026-09-13-vanke-backend-project-distillation.md)。代码快照：BlackSam `ec40b0ffe1`、Mephisto `bdb5dc31f`、Camille `aeaaa3c7`、Azeroth `8d7e304`、Sisyphus `2514879`。
- 适用边界：结论只对应 2026-09-13 本地分支；未拉远端、未运行 Maven、未连接 MySQL/Redis/XXL-JOB/外部系统。金额字段的税种、会计科目和最终产品定义未知；必须回当前 PRD、接口与财务事实源核对。
- 正例（应采用）：新建跨系统月度结算任务时，用本条检查稳定业务键、短事务、失败状态和分层测试。
- 反例（不应套用）：仅修改一个无状态查询接口时，不为形式完整强制引入 outbox、分布式租约或复杂状态机。
- 复核：远端分支、数据库约束、外部契约变化或出现生产反例时立即回源码重审；一次静态复核不用于宣称线上提效或学员已掌握。

- 阅读规则：不要求通读全部学习书；按当前阻塞选择相关章节，必须落成一张判断卡、一次任务调整和一个运行/未见变体。原书参考与审计新增读物分开标注。
