# 用户专业能力与市场价值评估协议

版本：1.0 · 2026-09-18
Owner：沈砚舟 · 后端培训导师（资深后端架构师）
授权：用户明确要求在每个中大型任务会话和培训会话后进行能力分析，并持续评估市场价值。

## 目标与触发

- 触发：每个 M/L 任务会话收口、每个培训会话收口，以及用户主动询问能力、职级、求职方向或薪资时。
- 目标：从真实工作中识别用户已经能独立完成什么、在何种提示下能完成什么、哪些仍未验证，并据此安排训练和形成条件化市场判断。
- 本协议不授权后台读取其他聊天、私人账户、整机文件或生产数据；只处理当前会话及明确交接的最小证据。

## 最小采集字段

每个观测点只记录：

1. 日期、任务 ID、领域、难度与目标；
2. 用户本人完成的步骤和可定位证据；
3. 独立程度：`independent` / `light_prompt` / `guided` / `reproduced` / `ai_or_employee_done`；
4. 用户的关键判断、初始错误、修订原因与提示层级；
5. 结果层级：解释、设计、实现、测试、真实运行、生产效果；
6. 暴露出的优势、缺口、迁移表现和仍为 `unknown` 的项目；
7. 对现有能力结论的影响：支持、反驳、无新增证据；
8. 下一次应安排的真实任务或未见题。

统一字段为：`observation_id`、`task_ref`、`observed_at`、`task_level`、`domain_and_risk`、`user_goal`、`user_actions`、`initial_judgment`、`assistance_level`、`revision_process`、`result_scope`、`evidence_refs`、`evidence_level`、`attribution`、`capability_signals`、`capability_gaps`、`unknown`、`market_relevance`、`confidence`、`privacy_redactions`、`observer`、`review_status`、`supersedes`。其中 `attribution` 只允许 `user` / `mixed` / `ai_or_employee`；`review_status` 使用 `pending` / `delivered` / `no_evidence` / `incorporated` / `discarded`。必须保留首次错误及修订过程，不能只保存最终正确答案。

不得收集原始对话、提示词全文、密钥、账号、身份证明、健康、家庭、私人关系或其他与职业能力无关的信息。用户主动提供的敏感材料也只引用脱敏结论，不复制原文。

## 能力维度与证据门槛

按目标岗位选择相关维度：需求澄清、架构与边界、前端、Java/Spring、SQL/数据、事务/并发/可靠性、测试与证据、故障定位、业务理解、AI/Skill/工具协作、沟通与交付。

- 单次观测不生成“提升百分比”；只记录发生了什么。
- 至少两个可比任务、证据方向一致，才能描述“正在提升”或“出现退步风险”。
- 原则上三个可比任务或一次相称的真实项目独立验收，才能标记为稳定能力。
- 学过、看懂、复现、提示完成、独立完成、真实环境验证和生产效果分别记录，不能相互替代。
- AI 或员工完成的内容只能评估用户的目标判断、复核和纠错能力，不能记成用户的实现能力。

## 市场价值评估

评估时必须同时注明：目标岗位与级别、城市/远程市场、评估日期、税前月薪/年包等薪酬口径、公开市场来源、岗位匹配证据、主要短板、置信度与失效日期。至少使用一份近期第一方招聘信息或招聘机构薪酬基准；重要区间尽量交叉验证。

深圳全栈与 AI 应用岗位的候选来源、来源审计门槛、采样口径、更新频率和失效规则见 `memory/learner/MARKET_SOURCE_REGISTRY.md`。来源未通过可靠性、可用性、容量、时效性、地域性和代表性审计前，不得称为固定来源或用于高置信度薪酬判断；来源临时不可用时记录替代关系，不静默更换口径。

职业路线、市场优劣势、学习优先级与薪酬建议共用该数据面板，并与能力档案中的用户本人证据交叉判断。市场热度不能代替个人能力证据，个人偏好或学习完成也不能代替真实岗位需求；任一侧证据不足时必须保留不确定性。

输出分为：

- 当前可竞争岗位；
- 条件化薪资区间与建议报价；
- 能支撑上沿的证据；
- 压低报价或导致降级的证据缺口；
- 未来 1—3 个真实任务如何提高市场证明力。

市场区间是时点估计，不是录用、涨薪或收入承诺。缺少地区、工作年限、项目责任、生产证据或面试表现时，明确降置信度，不补猜。

每次观察只记录 `market_relevance`，不自动重算薪资。只有稳定能力结论发生变化、目标岗位或地区变化、用户主动询问、或既有市场来源超过有效期时，才启动新的市场价值评估。

## 会后处理与回执

1. 主责先完成业务验收，再提交能力交接；能力分析不得影响对业务结果的诚实报告。
2. 沈砚舟核对用户归属和证据层级，更新 `memory/learner/CAPABILITY_PROFILE.md`；无新增证据时只登记“无变化”，不重复扩写。
3. 发现与历史结论冲突时保留新旧证据和修订原因，不静默改分。
4. 回执记录任务 ID、处理日期、档案位置和下一次验证题；没有真实消息或档案更新不得声称已通知或已评估。
5. 用户可随时要求查阅、更正、暂停采集、缩小范围或删除专项档案。
