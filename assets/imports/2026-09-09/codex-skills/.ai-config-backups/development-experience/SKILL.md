# 持续成长的开发经验

目标：提高第一次方案的正确率，减少用户纠正、返工与无效 token 开销。专业判断由执行者承担，用户不必反复指定“高级工程师”。本技能提供判断依据，不启动角色代理、不自动安装其他技能，也不增加审批门禁。

## 使用方式

先识别当前任务最相关的视角，按需要加载环境中真实可用的专项技能，不能把角色宣言称为已加载技能。

- 前端架构：框架入口、路由树、Layout 层级、权限、状态和请求边界。
- UI 与设计：信息层级、搜索栅格、间距、背景、选中态、响应式及加载/空/错误状态。优先复用现有组件库标准能力；视觉变更遵守本次用户约束。
- 后端：接口契约、鉴权、事务、幂等、数据一致性与可观测性，仅在任务涉及后端时采用。
- 构建与发布：安装目录、workspace、锁文件、构建上下文和运行环境的一致性。

相关技能缺失时如实说明；仍需完成当前授权范围内的专业分析。遵守上级规则对缺失必需技能的限制。

## 开发中的判断

1. 动手前用简短判断明确目标、不可变行为、影响入口、主要风险和验收证据。复用已有规格，不重复扩写。框架或编译器行为不明时先验证一个最小样例。
2. 多页面或多项目改造，先完成一个代表性纵向流程再推广；例如搜索、列表、详情、权限共同覆盖的页面。迁移前追踪实际依赖，不为目录整齐反复移动代码。
3. 按风险验证：类型、Lint、格式与构建验证静态问题；测试保护权限、认证、支付、数据转换、错误处理和重要交互。已有覆盖足够时不新增测试。不默认写版本、目录存在性、源码字符串断言或精确源码相等测试。
4. 样式验证对应真实编译产物与页面行为。构建成功不能证明 UI 正确；用户禁止浏览器时明确视觉未验收。标准组件配置应先于样式补丁。
5. 区分现象、假设和证实原因。进程空闲不能证明缓存锁；隔离构建通过也不能单独证明本地停滞原因。
6. 聚焦搜索，保存工具会话，失败时读取完整日志。检查通过且无新改动时不要重复全量检查。延续已授权动作，避免重复业务确认；遵守平台实际权限边界。

### 前端测试边界

前端默认只为可独立验证的逻辑写单元测试：纯函数、数据转换、校验、状态机、权限判定、请求封装、错误映射和支付/认证桥接。页面组件的渲染、DOM 查询、快照、样式类名和“能否显示某标题”默认不写单元测试；这类测试成本高、容易随 UI 调整失效，不能替代真实视觉验收。

页面改动优先使用 TypeScript、Lint、构建和少量路由/接口烟囱检查；关键用户流程只有在风险、回归代价或发布要求足够高时才增加集成测试或 E2E。可复用组件若包含独立且复杂的交互逻辑，可测试其逻辑或交互契约，但不要为普通页面包装层建立测试文件。

删除既有页面测试前先确认它没有承担权限、请求、数据映射或关键流程保护；没有替代证据时标记为待清理，不为了减少文件数强行删除。新增测试前先回答“它保护了哪个容易回归的逻辑”；答不出来就不写。

涉及历史类似问题时按主题读取 [经验库](references/lessons.md)，无需每次全量读取。需要收录经验或校准来源时读取 [维护规则](references/maintenance.md)。

## 低开销的目标收敛

在正常理解输入时提炼当前目标、约束、优先级与完成标准；能从上下文合理推断就继续，不另外调用模型评估提示词，不逐条评分、改写或展示完整分析。

仅当目标冲突、范围明显扩张，或缺失选择会导致实质返工时提醒。用一两句话指出具体影响并给出一个推荐方案；只有确需用户决定的取舍才询问，已有授权不重复确认。不要要求用户“想清楚再来”。

连续讨论局部实现而尚未推进验收时，简短关联回本轮目标，将非必要细节记为后续项，避免反复展开。是否提醒取决于对结果的影响，不取决于消息长短、提问数量或打断次数；权限、业务正确性和视觉异常的必要追问不视为偏题。用户明确要求深入或调整范围时尊重其选择。

新要求到来时判断是补充验收、替换旧约束还是新增批次；只有影响实施时才简短说明。维护当前批次与后续项即可，不为每次输入新增文档、Issue 或检查流程；独立的项目门禁仍按适用规则执行。

- “帮我收敛”：简短给出当前目标、真正待决定的关键取舍（没有则不编造）与推荐下一步；咨询请求不自动授权代码修改。
- “按推荐方案推进”：在现有授权内承担实现选择，推进已明确的推荐方案；不视为提交、发布、删除数据等额外权限。

## 成长触发

用户指出返工或方法问题、验证推翻先前判断、发现可复现的新兼容行为，或任务完成形成可复用经验时，审视是否值得收录。只有有证据且改变未来决策的内容才写入；没有新经验就不修改。

用户已授权本技能在后续相关开发中积累经验。此授权只覆盖本技能自身经验维护，不扩展为修改其他技能、全局规则、业务项目或外部服务的授权；平台写权限仍适用。每次维护在交付时简短说明变更。

官方对标在相关任务中机会性执行：出现规则冲突、重大版本变化，或相关主题超过 90 天未核对且会影响当前决策时校准。不创建后台定时任务，不每次开发都联网扫全库。
