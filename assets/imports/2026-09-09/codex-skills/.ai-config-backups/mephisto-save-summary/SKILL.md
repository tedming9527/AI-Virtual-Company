# 保存总结到 mephisto 解析目录

将对话中产生的知识总结、代码解析、概念详解等内容，保存为 Markdown 文件到 iCloud 同步的 mephisto 解析目录。

## ⚠️ 强制执行规则（命中此 skill 时必须遵守，不得跳过）

1. **目录必须存在** — 保存前必须确认目标目录存在。如果目录不存在，必须先创建再保存，不得报错放弃。
2. **编号必须连续** — 必须扫描已有文件的最大编号并 +1，不得使用已存在的编号（避免覆盖）。
3. **文件名必须中文** — 自动生成的文件名必须使用中文，与目录内已有文件风格保持一致。
4. **内容必须结构化** — 保存的 Markdown 必须包含标题层级、代码块、表格等，不得是一段纯文本。
5. **禁止在项目内留副本** — 统一存入 iCloud 解析目录，不得在项目 `docs/` 或其他位置留拷贝。

## 保存目录

`MEPHISTO_SUMMARY_DIR` 环境变量指定的目录；未设置时使用 iCloud Drive 下的 `mephisto解析/`。

## 执行步骤（必须按顺序执行）

### 1. 确认目录存在

```bash
summary_dir="${MEPHISTO_SUMMARY_DIR:-$HOME/Library/Mobile Documents/com~apple~CloudDocs/mephisto解析}"
mkdir -p "$summary_dir"
```

### 2. 扫描已有编号，确定下一个序号

```bash
ls "$summary_dir" | grep -oE '^[0-9]+' | sort -n | tail -1
```

取最大编号 +1，补零为两位数（如 `08` → `09`）。若目录为空则从 `00` 开始。

**禁止**使用硬编码或猜测编号。必须每次扫描。

### 3. 生成文件名（必须遵守命名规则）

**如果用户指定了文件名（$ARGUMENTS）：** 直接使用，仅补编号前缀。

**如果用户未指定：** 根据总结内容的核心主题，生成简洁的中文文件名。格式：

```
{编号}-{主题}.md
```

示例：
- `09-MyBatis-Plus自动填充机制.md`
- `10-订单状态机流转规则.md`
- `11-Spring事务传播行为.md`

命名规则：
- 主题必须是中文，简洁准确
- 如果是 Java 类解析，文件名中必须包含类名
- 禁止使用纯英文或拼音文件名

### 4. 整理总结内容（必须结构化）

从当前对话中提取需要保存的内容，整理为结构化的 Markdown 文档：

- 标题清晰，层级分明
- 保留对话中的代码示例、表格、图示
- 如有生活化比喻，一并保留（这是精华）
- 开头加一行 `> 来源：项目代码阅读` 的引用说明
- 末尾加保存日期

### 5. 写入文件

使用 Write 工具将内容写入目标路径。

### 6. 确认结果（必须输出）

输出保存路径和文件编号，让用户知道已保存。格式：

```
✅ 已保存到 mephisto 解析目录：
   📄 {编号}-{文件名}.md
   📁 ~/Library/Mobile Documents/com~apple~CloudDocs/mephisto解析/
```

## 🚫 禁止行为

- ❌ 目录不存在时直接报错不创建
- ❌ 不扫描直接猜测编号（可能导致覆盖）
- ❌ 文件名使用英文或拼音
- ❌ 保存为纯文本无结构化格式
- ❌ 在项目目录下留副本
