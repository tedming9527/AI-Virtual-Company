# 跨 AI 全局工作规则

## 同事称呼

- 在协作沟通、任务路由、复盘和交接中，统一使用“名字 + 职务（岗位）”称呼公司同事，例如“陈知行 · 路由官（Chief of Staff）”。

## 代码修改

- 默认计划优先：所有后续任务，以及对话进行中判断为长时、多步骤或需要较多执行的工作，先在 Codex Plan Mode 完成必要的只读核对、澄清与可执行计划；仅在用户明确切换至执行模式或明确授权按计划执行后，才进行文件修改、命令执行或其他会改变状态的操作。此规则用于降低长任务中途停顿的风险。
- 只修改用户明确要求的内容，不顺手改动无关逻辑。
- 需要回退已跟踪文件时，优先从版本库精确还原，避免手工还原造成格式差异。
- 修改后检查变更统计和完整差异，确认没有超出用户要求。
- 完成代码改动后，优先运行与改动风险相匹配的验证。

## Git 与发布

- 未经用户明确要求，不执行暂存、提交、推送、合并或部署。
- 不使用破坏性 Git 命令覆盖用户的未提交改动。
- 工作区已有的无关改动属于用户，应保留并避免混入本次任务。

## Skill 使用

- 用户明确点名 skill 时必须使用。
- 任务明显匹配某个可用 skill 时，先阅读该 skill 的完整说明再执行。
- 规则要求的 skill 缺失时，必须停止并报告缺失项，不得自行改用手工等价流程。
- 写或修改 CSS、Less、SCSS 或 React 样式时，使用 `react-scoped-styles`，避免污染全局作用域。
- 解释 Java 代码时使用 `java-code-explainer`。
- 用户提供 Figma 链接或要求对照设计稿时，使用 `figma-reader`。
- 用户要求合并到测试分支或部署时，必须使用 `vanke-merge-to-test-and-deploy`；不得手工拼接 Git、GitHub CLI 或 CI/CD 命令替代。
- 用户要求邮件操作时，使用 `agently-mail`。
- 用户说“保存到解析”、“记下来”或“保存总结”时，使用 `mephisto-save-summary`。
- 用户询问使用哪个模型或要求切换模型时，使用 `model-router`，并使用当前平台的模型映射。

## 安全与敏感信息

- 不在全局指令、仓库文件或同步目录中写入密钥、token、密码或凭据原文。
- 需要凭据时只引用环境变量名或平台安全存储中的标识符。
- 机器绝对路径、帐号标识和本地安装细节属于平台本地配置，不放入跨平台主配置。

## 配置放置

- 项目级 AI 指令只放在各平台规定的配置目录，不在项目根目录随意新建指令文件。
- 跨平台规则修改应先更新中立主配置，再由适配器生成平台文件。
