# Java Redis 教学计划纠偏与 9 月目标

## 教师独立判断

- 过去两天最大问题不是理论错误，而是把口头答对过早判定为掌握；用户的概念推理领先于编码、并发验证和故障诊断约两个阶段。
- 用户兴趣可以影响案例、节奏和能量安排，但课程先后与晋级门槛由教师控制。
- 主线必须改为：缓存正确性证据 → 锁所有权与原子解锁 → 并发重建证据 → 一致性失败窗口 → 容量实验 → 第三方治理工具。
- 暂停扩展逻辑过期、完整熔断算法、全局限流、Watchdog 内部机制等；将其放入后续停车场。

## 当前能力校准

- 已有实践证据：Cache-Aside 首次 SQL/二次无 SQL；`null` 与 `[]`；空结果短 TTL；更新数据库后删除父分类缓存并回源得到新数据。
- 仅概念理解、尚未验收：互斥重建、UUID 锁租约、Lua 原子解锁、TTL 超时、中断链路、QPS/并发、连接池、限流/熔断/退避。
- 主要缺口：当前 `spring-test-web` 没有 category/Redis 自动化验收；锁解锁仍非原子，锁 Key 前缀职责重复，第三次等待后可能不再检查缓存而直接报错。

## 科学教学规则

- 每节只引入一个主要机制、一个失败场景、一个真实接口和一组可重复证据。
- 75–90 分钟节奏：隔日无提示复习 5 分钟 → 目标/验收 5 分钟 → 预测 5 分钟 → 先运行观察 10 分钟 → 最小理论 10 分钟 → 用户编码 30–40 分钟 → 正常/异常/并发验收 10–15 分钟 → Mephisto 对照与一个顶层原则 5 分钟。
- 连续纯理论最多 2–3 题或 15 分钟；没有运行证据不进入下一模块。
- 使用渐隐脚手架：完整示范 → 补全代码 → 只给验收目标 → 独立迁移。
- 评分改为：识别、解释、指导下实现、独立实现并迁移；口头答对不再使用“满分=掌握”的表述。

## 9 月 30 日目标

- 不承诺在约六周内达到通用意义的成熟中级后端工程师；该水平还需要持续生产交付经验。
- 在每周稳定投入约 12–15 小时并通过全部门槛时，目标设为：能够独立交付并验证一个中小型 Spring Boot 功能，具备初中级 Java 后端能力，并在 Redis 缓存/并发治理专项达到接近中级的可验证水平。
- 最终验收以独立实现、自动化测试、并发/故障实验、代码评审、运行证据和设计说明为准，而非课程完成数。

## 立即下一课

- 不先做连接池实验；先关闭当前锁实践。
- 修正最终锁 Key 边界与最后一次等待后的缓存检查。
- 实现 Lua 比较 UUID 后原子删除。
- 10–20 个相同 parentId 的并发请求必须全部成功、业务结果一致、SQL 恰好一次、缓存 TTL 正确、请求结束后锁不存在。
- 再做错误 UUID、旧租约不能删除新租约、数据库异常不污染缓存、查询超过 TTL 导致双重回源的失败实验。
