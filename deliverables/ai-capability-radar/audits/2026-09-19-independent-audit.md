## 4. 发现

### F-01 · 高风险 · 来源类型完全由填表者自报，X 与厂商宣传可被洗成“官方/实测”

**证据**：README 第 24–26、74–80 行要求 X 只作线索、厂商自报保持 `vendor_claim`。但校验器第 43–51 行只比较调用者填写的 `kind` 字符串，不核对 URL 域名、来源所有权、登记表层级或主张归属。T6 把 X URL 标成 `official_docs/runtime_test` 后通过；T1 把泛域名标成 `official_docs` 后通过。

校验器对厂商主张的交叉验证也是“条目级存在性”：只要条目中任意位置存在一个 `independent_test/runtime_test/security_research`，所有 `vendor_claim` 都被视为有独立证据。T2 用与可靠性主张无关的安装测试成功洗白 99.99% 可靠性主张。

**影响**：X 只作线索与厂商宣传边界没有形成可执行控制；低质量或营销条目可以成为 `publishable`。

### F-02 · 高风险 · `schema.json` 不是校验器实际执行的契约

**证据**：校验器没有加载或执行 `schema.json`。Schema 要求 `run.scope`、`run.audit_status`、每条工具的 `evidence` 和 `dependencies`，并禁止额外字段；校验器没有执行这些约束。T1 同时缺少 run 必填字段、使用空证据数组和错误类型的依赖字段、加入未声明属性，仍返回有效。Schema 要求 `evidence` 至少一项，T1 的空数组仍通过。Schema 的 URI 格式允许多种 URI，而脚本只接受 HTTPS，反向也存在契约漂移。

`isDate` 只做正则加 `Date.parse`；JavaScript 会归一化部分不存在的日期，T1 的 `2026-02-30` 被接受。

**影响**：调用方无法知道应信 Schema 还是脚本；“结构校验通过”不能证明满足公开契约，并直接提供低质量发布绕过。

### F-03 · 高风险 · 到期复核、波动等级和淘汰期限没有门禁

**证据**：README 第 53、57–59 行规定到期未复核不得继续显示为当前可用，并给出 7/30/90 天周期。校验器第 37–38 行仅检查日期形态及 `next_review_at >= checked_at`，不比较当前日期或 `run.collected_at`，也没有波动类别与周期上限。T3 的复核期限已过一年多仍通过。T1 把下一次复核设为 2099 年也通过。

**影响**：系统无法自动阻止过时能力继续以 `verified_current/publishable` 出现，核心“淘汰过时工具”目标未实现。

### F-04 · 高风险 · 审计失败不阻止发布，审计引用也可缺失

**证据**：`run.audit_status` 虽在 Schema 中必填，但校验器完全忽略它，也未要求 `audit_status: passed` 才允许存在可发布条目，未要求 `audit_ref` 在 passed 时非空。T2 的 run 明确为 `failed`，仍得到 `valid: true` 与 `publishable: 1`。

**影响**：独立审计成为装饰性元数据；发布消费者若按 README 第 90 行只筛 `publishable`，会接收已明确审计失败的条目。

### F-05 · 高风险 · “当前版本”和原始证据不可稳定回溯

**证据**：README 第 39、49 行要求当前版本及核验时的版本、提交或页面日期。Schema 没有工具版本、提交 SHA、Release ID、页面版本/抓取摘要、证据内容哈希、发布主体、证据标题、访问快照、主张 ID 或证据与主张的显式映射。`url + supports + checked_at` 只能指向可变页面，无法证明审计时看到的内容，也无法判断某份独立证据究竟支持哪个核心主张。

**影响**：即使 URL 真实，也不能复核“当时哪个版本、哪段证据支持哪个结论”；后续页面变化会破坏追溯链。

### F-06 · 高风险 · 许可证、权限和数据风险只检查“非空”，`unknown` 可发布

**证据**：README 第 51、78 行要求明确权限、数据外发、许可证状态等。Schema 与脚本都把 `permissions_and_data` 和 `license` 设计为自由文本；脚本第 32–34 行只检查非空。T1、T2、T3、T4 和 T6 均可用 `unknown/unspecified/not reassessed` 通过。发布门禁不要求许可证证据；也没有权限范围、凭据类型、网络目标、数据类别、第三方接收者、保留/训练政策、本地/云执行、用户同意、最小权限或撤销方式的结构化状态。

**影响**：许可证冲突、过度权限或敏感数据外发未知时仍可发布，信息治理和安全风险没有形成 fail-closed 控制。

### F-07 · 高风险 · 生命周期模型自相矛盾，且不能证明“降级而不静默删除”

**证据**：README 第 37 行定义 `discovered` 为尚未定位原始项目，但 Schema 第 24、37 行及脚本第 40 行要求所有状态必须至少有一个 `primary_source`。T5 是符合 README 定义的 X-only discovered 记录，却被校验器拒绝。实际使用者要么无法记录早期线索，要么被诱导伪造“原始来源”。

数据契约没有状态变更历史、变更原因、前一状态、审核者、淘汰日期、最后可用版本/环境或证据保留引用。替代关系只检查 ID 是否存在，T4 的自替代环也能通过；没有循环检查，也不要求替代目标本身当前、合格或可发布。

**影响**：体系既不能忠实记录发现阶段，也不能审计从 current 到 watch/deprecated/replaced 的真实转移，无法证明历史证据得到保留。

### F-08 · 中风险 · 来源登记是方向清单，不是可重复的持续发现配置

**证据**：`source-registry.json` 的 GitHub、X、Hacker News 多为站点根地址，Vendor docs 与研究条目为 `project-specific/query-specific`。没有查询式、账号/组织列表、项目定位规则、抓取入口、来源 owner、启停状态、上次/下次成功时间、游标、失败状态或去重键。`cadence` 仅是自由字符串。README 第 28、94 行也明确没有账号连接、订阅或后台调度。

**影响**：它能指导人工发现，但目前不足以复现“每次查了什么”，也不能单独支持持续发现、漏采监测或失败恢复。该边界披露是诚实的，但不能被表述成持续能力已经建立。

### F-09 · 中风险 · `publishable` 同时覆盖当前、观察、淘汰和已替代，网站消费语义不清

**证据**：脚本第 15 行允许 `watch/deprecated/replaced` 全部成为 `publishable`；README 第 70 行要求观察/淘汰项醒目标识且不得与当前推荐混排，第 90 行却只说网站使用通过门禁的条目。契约没有单独的可见性、推荐资格、历史归档或展示分区字段，也没有对应校验。

**影响**：即使状态填写正确，简单筛选 `publication_status=publishable` 的消费者仍可能把过时条目混入当前推荐。

### F-10 · 低风险 · 官方采集模板不能直接通过官方校验入口

**证据**：`collection-template.json` 的 `collected_at: YYYY-MM-DD` 被校验器判为 `run metadata is incomplete`。模板可以是占位模板，但 README 没有提供生成/替换步骤或最小有效示例。

**影响**：增加首次运行误用和自动化集成失败概率；不单独构成发布安全漏洞。

## 6. 总结论

**FAIL。**

当前版本可以作为人工采集方法的早期说明稿和数据字段草案，但不足以支持“持续发现并淘汰过时 AI 能力扩展工具”，也不能把校验器绿色当作可发布证明。至少 F-01 至 F-07 均为高风险问题，直接命中审计强制失败条件。

在整改前，安全使用方式应是：所有条目默认 `hold`；`validate-radar.mjs` 仅作为有限格式检查，不得称为发布门禁；不得让网站、自动任务或人工流程仅依据其退出码发布。

## 7. 通过条件

只有以下条件全部完成并由未参与修复者在新快照重测后，才可改判 PASS：

1. **单一可执行契约**：校验器实际执行完整 JSON Schema；README、Schema、模板和脚本字段/枚举/条件一致。为缺字段、错误类型、额外字段、空证据和真实日历非法日期加入回归测试。
2. **X 与来源身份门禁**：X/论坛/Newsletter URL 只能进入 `discovered/candidate + hold`；来源层级不能仅靠填表者自报。原始来源至少记录项目/厂商身份与规范 URL，并对“官方”归属做可审计核对。
3. **主张级证据**：核心主张使用稳定 claim ID；每份证据明确支持/反驳哪些 claim。独立证据必须与被提升的厂商主张同一指标、版本和环境；无关证据不能解除 `vendor_claim` 限制。
4. **版本与不可变追溯**：记录工具版本/提交/Release、证据页面或工件版本、抓取时间及内容摘要/哈希（或等价不可变引用）。`verified_current` 不能只由可变 URL 和自由文本产生。
5. **到期 fail-closed**：按运行日期检查 `next_review_at`；过期条目自动阻止当前推荐并降为 hold/watch。结构化记录波动类别，强制 7/30/90 天上限；拒绝异常远期复核日期。
6. **真实审计门禁**：存在 publishable 条目时，run 必须为 `audit_status: passed` 且有非空、可定位的 `audit_ref`；failed/partial/pending 一律不能发布。审计状态不能由同一个采集动作无证据自填生效。
7. **风险 fail-closed**：将许可证、权限和数据处理拆为结构化状态并要求证据。许可证未知/冲突、权限范围未知、数据去向/保留/训练用途未知、需高权限但无缓解时均不得 `publishable`。
8. **可审计生命周期**：允许 X-only `discovered` 在无 primary source 时合法保存但永不发布；保存状态历史、原因、审核者、最后可用版本/环境和淘汰时间。拒绝替代自环/循环，并要求替代目标满足明确质量条件。
9. **发布语义分离**：至少区分“可展示”“当前推荐”“观察”“历史归档”；网站过滤规则必须受契约校验，不能把 deprecated/replaced 与当前推荐混用。
10. **可重复发现运行**：来源登记补充可执行入口/查询、owner、启停、上次与下次运行、游标/去重和失败状态；在真实调度与失败通知有证据前，只能称人工运行目标，不能称持续发现已建立。
11. **独立负例重测**：至少保留本报告 T1–T6 等价用例，并新增跨主张证据错配、许可证未知、过期、远期日期、审计失败、自替代/循环、来源冒充和页面内容漂移用例；所有负例必须 fail，最小正例必须 pass。
