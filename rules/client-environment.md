# Ted 客户端环境规则

已安装并启用本项目适配器的客户端中，所有会话都接入中介层；以宿主会话/回合标识关联，一个任务可涉及多个项目，项目目录不作为准入条件。部署配置与采集程序由当前 CODEX_HOME 下的 ted-avc-manager 管理；项目路径从部署配置读取，不猜测旧 iCloud 位置。

采集、审计、统计、署名失败只提示风险与修复事项；继续用户已授权任务，不要求先绑定、补记账、重试或追加回合，不伪造已验证回执。原生权限、沙箱与审批继续有效。

区分逻辑任务主责与实际执行者；未取得具名员工专属回执时，实际执行者为 platform agent。岗位只按当前目录元数据、实际加载资料和执行证据声明。

资料下放：中央仓库 → 用户数据中心的中央受管区 → 客户端。采集升级：客户端 → 经确认登记的用户资产 → 经评审的中央资料。来源、当前归属和升级状态分别登记；复制、保全、统计均不等于升级。

初始化全量替换公司受管客户端环境，第二步才按需导入用户资料。用户资料中心不全量覆盖，中央受管副本按清单更新。重建前去除可核验的中央/用户下发副本，保全客户端独有资料并恢复到独立工作区，保持未升级身份；不得重新启用旧版通用资料。

资料确认废弃后清理对应观察、评分、趋势和建议。搬迁、读取故障不等于废弃。未知来源不自动删除；客户端独立工作区和待升级区不能当作正式技能加载。

保全、归属、来源映射与升级必须通过项目代码登记和校验。模型声明不构成升级回执。任务授权不自动包含 Git 提交、推送、发布、安装其他插件或扩大权限。

初始化由确定性安装器执行：用户在对话中要求初始化时，引导并在授权及平台权限允许范围调用 `yarn setup` 或 `npm run setup`；非交互使用明确参数，不由模型逐文件拼装环境。安装、宿主信任/加载、原生事件捕获、上下文交付、任务路由与署名分别报告。
经验以实际修改文件和产物关联的项目为来源；跨项目经验保留多项目来源，通用经验进入待评审候选，不按聊天启动目录直接归属。
