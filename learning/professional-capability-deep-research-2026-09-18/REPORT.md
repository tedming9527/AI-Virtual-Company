## 三、八岗核心新结论

### 3.1 陈知行：薄信封统一关联，原生回执决定状态

跨通道不能仅凭统一的 `id/status/result` 字符串判定状态。可共享的是包含 channel、execution/work ID、attempt/operation key、时间、原生起止证据和适配器版本的薄信封；`queued → running`、取消终态和恢复都必须回读通道原生事实。执行 ID 只防同一 attempt 重启，稳定 operation key 才用于防止新 attempt 重复业务副作用；心跳过期只能进入 `needs_attention/unknown`，不能自动判失败并重派。

### 3.2 林知夏：事实账本、来源适配与决策快照三层分离

统一试点数据链不能压成单一内容状态。最低结构是不可覆盖的追加式事实账本、保留原始值的来源适配层、版本化决策快照；`authority/execution/evidence/business terminal/release` 五个状态正交。`accepted`、平台终态和成熟效果必须分账，未成熟、缺失、不适用、终态 unknown 与归因 unknown 不能填 0。阈值必须有来源和事实所有者，本轮不代填业务数值。

### 3.3 周启明：请求归属是页面作用域、资源、输入和尝试的四元组

单一整页 owner 会牺牲部分成功，完全独立资源 owner 又会拼出跨路由混合页面；候选解是层级 owner：`scopeKey + resourceKey + inputKey + attempt`。页面状态从当前 scope 的资源状态派生，必需/可选由业务契约决定；Abort 只能减少客户端浪费和陈旧回写，不能证明服务端副作用取消。是否提炼通用 hook 必须等待一个真实页面验证。

### 3.4 陆行远：无幂等、无查询不应按行业一刀切

准入应由歧义能否关闭、重复/遗漏容忍、可逆性、独立证据和影响等级共同决定。低影响且由事实所有者接受后果的操作可受限单次或有限 best-effort；高影响且无独立确认的金额、履约、唯一权益、身份或破坏性动作必须阻断。本地锁、唯一键或 outbox 只保护本地意图，不能补出远端 exactly-once；一次客户端尝试也不等于远端 at-most-once。

### 3.5 苏映雪：可信异步界面需要能力事实，不只需要诚实文案

`pending/unknown` 并非天然不可发布，也不能仅凭“处理中”文案放行。条件式进入发布评审的前提是：受理可证明、操作可定位、状态可查询或人工核对、重复动作受控、能力承诺真实，并在目标浏览器与辅助技术中验证。取消、补偿、重试为 unknown 时不显示对应能力控件；受理、终态、能力、恢复和发布结论必须分开。

### 3.6 顾清妍：关闭具体 unknown 主张，而不是关闭一个词

高风险终态没有万能凭证。`existence / semantics / scope / terminal` 四类 unknown 各自要求同层证据，并以稳定业务键把证据绑定到同一操作。单笔终态收口不等于恢复机制已验证；只有在相称环境覆盖故障矩阵后才可能讨论能力解阻。若高风险路径被服务端全入口证据证明不可达，可只放行隔离后的无关范围，不能写成高风险能力通过。

### 3.7 辛澈：外部工具闭环是主张匹配的五类证据组合

外部工具可形成有限闭环，但不能把成功工具回执统一写成业务完成。最低组合是业务授权、服务连接/最小 scope、写工具回执、同对象或下游结果证据、模糊失败恢复。Gmail 发件箱对象、WordPress post、GitHub issue/PR/commit 各只能证明对应对象层；送达、公开分发、合并、CI 或部署需要额外事实。`research_complete` 仅表示本地只读盘点与官方能力审计已回答，真实账号实验仍 unknown。

### 3.8 沈砚舟：五段式有内容合理性，尚无预测效度

五段式覆盖预测、解释、实现、测试、迁移，但历史材料混合独立、提示和完整示例，不能据此预测下一次交付。候选方案是双阶段评测：短闭卷观察问题模型，随后允许 IDE、官方文档和 AI，但记录帮助层级、产物归属和真实验收；能力以“阶段证据 × 帮助成本 × 任务范围”向量记录，不压成总分。一次通过只生成候选，至少三个准入一致的真实可比任务才讨论对同类下一任务的初步预测价值，仍不等于统计或全域能力证明。

## 四、竞争假设、反例与共同协议

### 4.1 经反例保留下来的共同判断

| 竞争命题 | 关键反例 | 综合处理 |
|---|---|---|
| 统一字段或一次成功回执即可统一判定 | `turn/completed`、进程 exit 0、HTTP 202、工具 `ok` 各自只结束不同层 | 统一信封只做关联，语义由原生通道和目标事实解释。 |
| 所有 high-risk unknown 都阻断整个版本 | 风险路径若经服务端权限/路由/任务/旧客户端全入口证明不可达，无关修复无需永久等待 | 阻断可达的高风险范围；允许经验证的范围隔离，不升级能力结论。 |
| 诚实写“处理中”即可发布 | 有 jobId 但不能查询、人工也无法定位时，用户仍可能重复扣款或删除 | 非终态体验还必须可观察、可定位并可安全处置。 |
| 无幂等、无查询的写入一律禁止 | 事实所有者可接受重复与遗漏的低影响通知仍可单次 best-effort | 按影响、容忍度、可逆性和独立证据分级；技术岗位不代定风险。 |
| 对象存在或写后 GET 足以证明业务终态 | 邮件对象可回读但可能退信；PR 存在但未合并，合并也不等于部署 | 先声明主张层级，再收同层 outcome evidence。 |
| 前端用整页 owner 或全资源独立即可 | 前者使可选失败拖垮整页，后者可拼出 A/B 两个 scope 的混合页面 | 以页面 scope 隔离、资源 owner 支持部分成功、attempt 防重试乱序。 |
| 教学绿灯或一次无提示通过即可预测能力 | 题目泄露、AI 给核心补丁、测试遗漏并发窗口都能制造假阳性 | 保留初答、帮助和运行证据，使用未见迁移及前瞻可比任务。 |

### 4.2 最小真实验证协议共识

八岗协议虽面向不同领域，但共享同一骨架：

1. **输入：**先冻结主张、目标对象、版本、稳定身份、事实所有者、风险与允许范围；没有具体对象不进入写入实验。
2. **环境：**使用目标框架、官方 sandbox、隔离租户、测试站点/仓库或教学环境；Mock、H2、规范和静态设计单列，不升级为真实链路。
3. **权限：**默认只读；任何写入限获批测试对象和最小权限，不制造生产资金、履约、身份、发布或删除副作用。
4. **步骤：**覆盖成功、明确失败、已受理但响应丢失、重复/迟到/乱序、查询不可用、取消/恢复、旧 attempt 与新 attempt 冲突；专业岗位另加页面、指标、无障碍或教学场景。
5. **证据：**保存原生 ID、稳定业务键、版本/环境/身份、时间序、原始回执、目标当前状态、产物归属、人工事实和独立复核。
6. **通过：**证据与主张同层，重复执行不产生第二副作用，unknown 不被填成成功/失败，放行范围与覆盖范围一致。
7. **阻断：**无权威查询/对账、无稳定身份、契约或风险未签核、隐藏重试不可控、测试可能触发真实高风险副作用。
8. **退出：**停止新副作用，保留原 ID 和未决状态，撤销测试权限并按另行授权清理；不得靠补发、删记录或改状态制造收口。

## 六、reviewed_case 候选与稳定知识门禁

### 6.1 可形成的共享候选

- 主张级证据分层：执行受理、对象存在、业务终态与发布授权正交；
- 稳定身份与旧执行查询：execution/work ID、attempt、operation/business key、resource ID 分责；
- 模糊终态恢复门禁：先查旧执行及目标状态，再决定重试、补偿、人工或阻断；
- unknown 不盲重试：日志、队列、HTTP 2xx、本地 DB、签名或 outbox 不能单独跨层；
- 最低真实验证协议的“输入—环境—权限—步骤—证据—通过/阻断—退出”骨架。

### 6.2 仅作岗位内试用或待真实触发的候选

- Chief：薄统一回执信封与 `execution-receipt-audit`，须至少两个非本地通道完成状态矩阵；
- Product：追加事件账、五个正交状态与 `measurable-pilot-brief`，须获批试点和双人重算；
- Frontend：四元层级 owner，须在真实 React 路由、浏览器和接口中验证；
- Backend：下游六项能力门禁及受限执行/人工/阻断矩阵，须具体契约、测试租户和业务签核；
- Design：条件式异步状态契约，须真实接口、目标设计和辅助技术实测；
- Test：四类 unknown 关闭矩阵，可作为方法候选，但供应商示例不得普遍化；
- AI：`external_action_contract` 与外部工具地图字段，须真实测试账号完成一种工具的最小闭环；
- Training：双阶段五段式及帮助成本向量，须学员原始产物、未见迁移和后续可比任务。

本轮**不自动更新稳定知识**，原因是：研究通过只证明方法经过独立语义复核，多数结论仍缺具体业务对象、相称环境、运行回执与事实所有者签核；工具、契约、框架、供应商和辅助技术会变化；角色内候选尚未经历真实反例；更没有三个满足各自准入条件的可比任务证明效果。先保留 `reviewed_case` 候选和触发条件，避免把纸面完整度固化为公司能力。

## 七、后续真实触发主线

1. **P0：首次高风险异步外部写入。** 触发条件是出现具体邮件、发布、支付、履约、权限或其他外部副作用，并提供当前契约、授权测试身份、稳定 operation key、目标状态查询/人工对账及业务风险所有者。由 Chief 维护原生执行回执，Backend 审能力与重试，AI 审授权/scope/工具结果，Design 定义真实状态呈现，Test 关闭四类 unknown。若两轮仍无契约或运行证据，保持 blocked。
2. **P1：真实跨路由多数据源页面。** 触发条件是获授权 React 项目、目标路由、至少两个必需和两个可选资源、可控时序与真实浏览器。Frontend 验证层级 owner，Design/Test 验证 partial、恢复及可访问反馈；无稳定 scope 或真实接口终态时不提炼通用 hook。
3. **P1：获批试点数据链。** 触发条件是用户批准试点、事实所有者、测试账号/脱敏事件、数据范围、成熟窗口和阈值签核。Product 先冻结口径并建立追加账，AI 只在明确授权下验证一种来源工具，Test 独立重算；工具接收不得进入发布成功或效果分子。
4. **P1：下一次真实后端课程纵向切片。** 触发条件是未讲解任务、可用 MySQL/Redis/XXL-JOB 环境、封存迁移题和学员原始作答。Training 记录闭卷初答、帮助、diff、运行与清理，Test 独立复核；一次通过只记候选，随后三个可比任务才讨论初步预测价值。

四条主线按真实触发而非固定日程启动；一次只验证最小闭环，问题解决或连续两轮无新增有效证据即停止。
