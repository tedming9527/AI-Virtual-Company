# 沈砚舟 · 五段式对真实独立交付的预测效度研究

- 日期：2026-09-18
- 负责人：沈砚舟 · 后端培训导师（资深后端架构师）
- 复核人：顾清妍 · 质量测试工程师（Test Expert）
- 模型 / 推理：`gpt-5.6-sol / high`
- 状态：`partial`
- 能力边界：已核对当前课程事实、真实代码/测试、上一轮知识与官方评测资料，并形成可执行的前瞻验证协议；没有学员闭卷初答、实际实现、提示轨迹和未见题表现，不能更新学员能力状态，也不能声称五段式已具备预测效度。

## 1. P0 问题与会改变的具体决策

**问题：**“预测→解释→实现→测试→迁移”五段式，能否预测学员在下一条真实后端纵向切片中独立完成需求拆解、代码实现、风险验证与交付收口，而非只复现熟悉案例？

这里的预测目标必须限定为：在同一技术栈和相近风险等级下，学员能否在没有导师提供核心语义或代码答案时，完成一个此前未见的中小型 Spring Boot 切片。它不是“通用后端职级”“生产系统任意任务”或“无工具闭卷编程”。

结论会改变四项具体决策：何时把课程状态从“提示完成”升级为“独立完成”；何时允许进入 RabbitMQ 等下一阶段；导师应继续给完整示例、只给语法提示，还是退回业务/机制补课；课程进度能否记录“独立交付候选”。事实所有者是学员本人、当前课程事实源、代码/数据库运行证据与顾清妍的独立复核。禁止把导师答案、AI 生成代码、测试绿灯或一次熟悉题通过单独计为学员成绩。

## 3. 专业研究结论及来源

**结论一：五段式目前具备内容合理性，但没有预测效度证据。** 它覆盖需求前置推理、机制解释、代码产出、风险相称测试和迁移，能阻止“代码存在/测试通过=学员会了”的常见误判；然而预测是一项新的用途，必须把本次五段式表现与之后的真实、未见任务表现做前瞻配对。现有材料只记录了历史实现、提示程度和运行结果，没有这样的配对。

**结论二：不应把五段压成一个总分，而应记录“阶段证据 × 帮助成本 × 任务范围”的能力向量。** 同一学员可能能独立判断状态机，却需要 Java/MyBatis 语法提示；也可能能复述事务，但不会设计能推翻自己的并发测试。至少记录：每段是否有原始产物、核心语义由谁提出、提示层级、运行证据层级、任务是否提前见过。National Academies 的 graduated prompting 与本课程“问题定位→概念→最小语法→完整示例”可直接对齐；帮助越具体，越不能把结果记为独立。

**结论三：最有希望的预测器是“双阶段评测”，而不是纯闭卷或纯 AI 协作。** 第一阶段短闭卷完成预测、解释与测试意图，用来观察学员是否真正拥有问题模型；第二阶段允许正常使用 IDE、官方文档和 AI，但记录所有语义提示、补丁来源和验收操作，由学员负责取舍、实现、运行、清理和复盘；下一课再做一个未泄题的相似迁移。纯闭卷会把 API 记忆误当能力，纯 AI 协作又可能把生成器能力误记给学员。

**当前可做的决策只有：**继续采用五段式作为评测协议，但不得据现有历史升级能力状态。一次无提示通过只能形成“独立完成候选”；至少三个满足准入条件、难度相近而表面不同的真实任务均能复现，且有独立复核，才讨论其对“下一项同类任务”的预测价值。即使如此，也不得外推为生产系统全域能力。

## 4. 竞争假设与反例分析

**H1：五段式无提示通过能预测下一项同类真实交付。** 支持理由是它同时观察前置模型、实现、证据和迁移，比提交数或测试绿灯更接近目标能力。反例：学员已经见过相同状态机或答案，能在分类同步题高分，却在换成退款/奖励后无法识别事实所有者与外部 unknown；此时测到的是熟悉度而非迁移。**判定：可验证的首选假设，但当前未证实。**

**H2：五段式主要测量记忆、表达与导师提示适配，不能预测 AI 协作下的真实交付。** 反例：学员闭卷记不住 MyBatis 注解，却能独立发现旧 owner 风险，查官方语法、拒绝 AI 的错误建议、写出 token 条件更新和双连接测试；若据闭卷语法判失败，会低估真实能力。相反，学员可能复述流畅，却让 AI 完成核心补丁。**判定：能推翻“纯闭卷五段式”，不能推翻带来源台账的双阶段版本。**

**H3：只要真实代码和测试通过，就比五段式更能预测。** 当前代码提供直接反例：首次原子领取测试通过，却没有覆盖租约过期后旧执行者回写；绿灯只能证明已测行为。若学员不能预测遗漏窗口或设计反证测试，现有成功无法支持独立交付判断。**判定：拒绝。**

## 5. 三条可立即采用的行动规则

1. **先固定预测用途和任务族。** 每次评测先写“要预测下一项什么任务、允许哪些工具、哪些核心决策必须由学员提出”；不再使用无范围的“已掌握后端”标签。
2. **证据和帮助同时记账。** 保存闭卷初答、时间顺序、提示层级、AI/导师提供的语义、Git diff、命令/数据库证据和清理结果；核心状态机、SQL 条件或测试断言被提示后，只能记提示完成。
3. **一次通过只生成候选，不升级能力。** 下一课用未泄题迁移，随后在三个可比真实任务中观察首次报验缺口、提示成本和返工；缺任一配对证据时保持 unknown。

## 6. 未见迁移题及独立作答

**题目：**当前分类事件中，W1 以 token-A 领取事件后长时间暂停；租约过期，恢复 SQL 把事件放回 `PENDING`，W2 再以 token-B 领取。此时 W1 恢复并先执行失败回队，W2 随后执行成功回写。现有代码会有什么风险？应怎样实现和验证“旧执行者不能改新执行者拥有的事件”？

**独立作答：**当前 `rescheduleForRetry(id, ...)`、`markFailed(id, ...)` 和 `markSuccess(id, ...)` 都只按事件 ID 更新，没有检查 `status=PROCESSING` 与 `processing_token`。因此 W1 的旧回队可能清掉 W2 的 token、把其正在处理的事件退回 `PENDING`；之后 W2 的无条件成功又可能覆盖新一轮状态。首次领取的原子性不能保护终态写入。

最小设计是把 token 贯穿 Job 与所有终态 Mapper，更新条件至少包含 `id + status='PROCESSING' + processing_token`；影响行数 1 才代表当前 owner 完成迁移，0 表示已失去所有权，旧执行者不得继续改写或把 0 行伪报成功。真实 MySQL 测试应固定序列：W1 领取 A→令租约到期并恢复→W2 领取 B→W1 回队/成功均为 0 行且数据库仍为 B 所有→W2 按 B 结束为 1 行→断言最终状态和元数据。还要覆盖 W2 先成功、W1 后失败，确保终态不回退。

该答案来自本轮研究者对当前代码的独立静态分析，未运行复现，也不是学员成绩；题目写入报告后已泄露，未来真实评测必须由复核人另出同构但未公开的变体。

## 7. 最小真实验证协议

**目标解释：**验证“五段式表现是否能预测下一项同类任务的独立交付”，而非评定通用职级。

**输入：**评测前冻结的仓库提交、当前 `PROGRESS/TEACHING_STRATEGY`、一条真实且尚未讲解的纵向切片、成功与一个失败边界、验收环境、允许工具清单、由顾清妍封存的未见迁移题。任务不得直接复用本报告已公开的 token 答案。

**环境与权限：**仅在 `spring-test-web` 本地学习环境及隔离 MySQL/Redis/XXL-JOB 测试数据中进行；学员拥有正常读写代码、运行测试和查询教学数据的权限。导师只观察和记录，不代写代码、不操作管理台、不创建或清理验收数据；无生产库、真实资金或外部业务副作用。

**允许支持：**闭卷阶段只允许任务说明和必要的非语义澄清；实现阶段允许 IDE、项目既有文档、维护者官方文档和 AI。所有 AI/导师输入需保留。若只提供 API 名称或最小语法片段，可标“语法提示”；若提供状态迁移、SQL 条件、关键断言、补丁或完整示例，则该段分别记“机制提示/结构提示/导师代做”，不得记独立。

**步骤：**

1. **预测：**学员在看答案和搜索前提交输入、前后状态、关键 SQL 影响行数、一个成功和一个失败序列；原稿冻结。
2. **解释：**独立画 Controller/Job→Service→Mapper→双库调用链，说明事实归属、事务、并发裁决、恢复与 unknown；导师只记录缺口。
3. **实现：**在预先约定的时间盒内由学员完成最小补丁；记录 Git diff、每次 AI/导师提示和核心决策最初由谁提出。时间只用于比较同一学员的变化，不单独作为通过阈值。
4. **测试：**学员先写会失败的最小反证，再运行静态检查及风险相称的真实 Mapper/事务/双连接测试，查询最终状态并精确清理数据；导师不代操作。
5. **迁移：**下一课由顾清妍给出未公开、机制同构但业务表面不同的任务；先无语义提示作答，再按“通用提醒→概念→机制→语法”逐级提示，并记录首次正确所需帮助。
6. **前瞻比对：**在随后三个可比真实任务中记录第一次方案的必需缺口、核心提示层级、真实测试遗漏、用户/导师纠正导致的返工和最终验收；评测结果在任务开始前锁定，避免事后改口径。

**必需证据：**冻结的初答和时间戳、帮助台账、AI 对话/导师提示摘要、完整 Git diff、测试命令与原始结果、主从库最终查询、测试数据清理、未见题原始答案、复核结论，以及后续三项任务的同口径结果。提交数、代码行数和测试数量不能替代这些证据。

**通过条件：**单任务只可记“独立完成候选”：五段核心语义均由学员先提出，允许的工具未给出核心答案，补丁和风险相称测试由学员完成，未见迁移在无语义提示下指出关键状态/SQL/断言。只有连续三个可比任务中，该候选持续对应低提示、无重大遗漏且首次报验覆盖必需证据，才支持“对下一项同类任务具有初步预测价值”；效果大小和误判率仍需保留。

**阻断条件：**任务答案已泄露；导师/AI先给出核心方案；没有闭卷初答、补丁归属、真实运行或未见题；仓库/契约在评测中变化；只用 Mock/H2 替代目标 MySQL 并发；任务难度不可比；复核人参与出答案又单独宣称独立复核。任一出现时只记录提示完成、复现或导师代做。

**退出与清理：**停止应用/Job 的教学触发，按教学标识和精确 ID 清理测试事件，恢复从库测试数据，保留脱敏证据包；不自动提交、推送或更新 `PROGRESS.md`。能力状态更新须在学员完成、顾清妍复核且用户授权的真实课程轮次另行执行。

## 8. 适用、禁止套用与失效条件

- 适用：同一学习项目、相近技术栈与风险等级下的中小型后端纵向切片，且能取得当前代码、真实测试环境、学员原始产物与帮助轨迹。
- 禁止套用：用一次分类同步结果推断支付、财务、安全、性能容量或陌生框架的生产能力；用导师研究答案给学员计分；用代码存在、测试绿灯、复述流畅或提交频率单独判独立。
- 不能把“允许 AI 的真实交付”偷换成“AI 生成即学员独立”。核心问题模型、取舍、反证测试与验收责任必须可归属学员；语法检索不应与核心机制提示混为一类。
- 失效条件：课程目标、代码/DDL、数据库、外部契约、允许工具、提示政策、任务难度或评测用途变化；出现一次与预测相反的高风险遗漏时立即回看任务可比性和评分解释，不维护“永远有效”的总分。

## 9. 仍需真实任务关闭的 unknown

尚未知：学员能否闭卷识别当前 owner/token 风险；能否独立写出条件终态 SQL、贯穿参数并设计真实双连接测试；使用 AI 时核心决策归属如何；迁移到不同业务对象后提示成本是否稳定；五段各自与后续交付结果的相关方向；是否存在高分但高返工、低分但工具协作良好的误判；顾清妍与导师对提示标签是否一致；三个可比任务的难度如何校准。没有真实学员表现前，这些不能由课程文档、导师作答或官方文献关闭。

## 10. Skill、工具地图与检查清单建议

暂不创建或修改 Skill。现有 `real-project-backend-teaching` 候选方向正确，但在真实验证前只建议增加研究级检查清单：`intended_use`、`task_family`、`allowed_tools`、`frozen_initial_answer`、`help_level_by_stage`、`artifact_owner`、`runtime_evidence`、`withheld_transfer`、`future_task_outcome`。它应输出能力向量和证据缺口，不输出自动总分或职级。

工具地图只登记当前已有能力：Git diff/提交用于追踪产物而非证明作者能力；Maven 与真实 MySQL/Redis/XXL-JOB 用于行为证据；AI/导师对话用于提示归属；数据库查询与精确清理用于最终状态。无需安装新插件，也不应开发自动评分器；在样本不足时自动化只会精确地产生未经验证的标签。

## 11. 停止理由与下一触发条件

**停止理由：**第一轮刷新了当前课程、Git、代码和测试，新增决定性项目事实：历史结果混合了独立、提示和完整示例；当前首次领取有真实并发证据，但终态写入未校验 token，且无对应 Job/旧 owner 测试。第二轮核对官方评测、迁移与计算机能力框架，确认“教学内容合理”和“能预测未来交付”是两项不同主张，预测必须按特定用途做前瞻验证。研究问题已转化为可执行协议；下一步所需证据只能由真实学员完成，继续扩读或增加模拟题不会改变能力结论，因此按执行书以 `partial` 停止。
