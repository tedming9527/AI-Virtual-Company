## 核心能力：脱离 JEV 的判断循环

（训练记录）各岗位在多项复杂同状态判断时进入下面的循环；确定性事实与单项低风险判断不进入完整循环。

1. **先分流任务性质**：这是判断、生成还是取证？判断继续；生成由主模型/负责人完成；缺事实先取证。
2. **压缩最小状态**：只保留目标、已证实事实、约束、未知项、候选动作和停止条件。
3. **类型化问题**：真假/概率、互斥动作、有序质量分别处理；无法类型化时不强行套用。
4. **冻结选项与标准**：先写清互斥选项、等级定义和通过门槛，再看结果，避免事后改尺子。
5. **同状态批量判断**：一次处理同一事实包上的全部问题，避免反复加载背景和逐题漂移。
6. **显式不确定性**：没有 JEV 时也使用 `high / medium / low / unknown` 或明确证据等级；低把握不伪造精确小数。
7. **升级改变控制流**：事实冲突、选项不全、开放式问题、高风险、低把握或工具不可达时暂停自动采纳，交回具名责任人。
8. **只执行未升级项**：结论按稳定 ID 输出，保留来源、责任人和下一步；机器先验、人工判断、最终裁决不混写。
9. **事后校准**：用真实结果检查哪些判断稳定、哪些门槛过严或过松；没有可比样本就不宣称提效。

最小无 JEV 模板：

```text
STATE: 目标 / 已证实事实 / 未知项 / 约束 / 停止条件
QUESTIONS: id / type / options-or-levels / acceptance-rule
RESULTS: answer / confidence-or-unknown / escalate / reason / owner / next-action
```

这套循环的目的不是让所有问题都变成选择题，而是快速识别：哪些判断可以机械化，哪些需要补证据，哪些必须由专业负责人承担。

## 有 JEV 与没有 JEV

### 真实观察

- JEV 的稳定价值是结构化输出：`answer / confidence / confidenceFrom / escalate` 让低置信项改变控制流，而不是隐藏在长推理中。
- 对事实已知、问题可枚举、同一状态有多项判断的案例，未升级 verdict 与冻结人工基线普遍同方向。
- 有效 MCP 后端延迟在本轮样本中约为 0.7–3.7 秒；客户端端到端时间明显更长，不能用服务端延迟替代真实体验。
- JEV 是费率与判断分流工具，不天然节省 tokens。本轮每岗记录了 JEV 用量，但没有同口径人工 token/墙钟基线，不能宣称总体更快或更省。
- `unsure` 很有价值：它把含混的等级、混杂的职责或证据不足显式交回主模型。重复调用直到“通过”不是正确做法。
- MCP 与 CLI 是独立路径；MCP 成功不能推导 CLI 同时可用。

### 无 JEV 替代协议

1. 压缩状态：只保留目标、已证实事实、未知项、约束、候选动作和停止条件。
2. 类型化问题：是非概率用 `noul`，互斥动作用 `choice`，有序质量用 `score`。
3. 冻结枚举：选项互斥、尽量穷尽；等级从差到好写清楚。
4. 同状态批处理：一次处理全部判断；状态变化后再开新批次。
5. 明确阈值：低置信、事实冲突、选项不全、状态过大、开放式生成或工具不可达统一进入升级队列。
6. 分离来源：机器先验、人工基线和责任人最终结论分别记录。
7. 收缩输出：保留 `id / type / answer / confidence-or-unknown / escalate / reason / owner / next_action`。

本节不是降级备用方案，而是日常默认思维方式；JEV 可用时负责加速其中的类型化判断，不可用时流程仍完整运行。

## 对“何时适合 JEV”的评价

用户给出的十条条件总体方向正确，但“满足多数项才考虑”不合理，因为条件的重要性不同。JEV 对该规则给出 `1.84/3`，即“基本合理、需要定点修订”；最终人工复核采用三层模型。

| 原条件 | 评价 |
| --- | --- |
| 答案可列为有限选项 | 核心门槛；也可使用有序等级或真假概率 |
| 每个选项定义清晰稳定 | 核心门槛；还应尽量互斥、穷尽 |
| 输入在模型限制内 | 必要但表述过弱；应要求状态最小充分，文件型大批量改走 CLI/脚本 |
| 任务高频重复 | 价值增强项，不是必要条件；一次状态上有多个判断也可能值得批处理 |
| 需要低延迟或本地处理 | 应拆开；低延迟是条件性价值，本轮远端 TypeSafe 并非本地推理，且客户端 wall time 明显高于后端延迟 |
| 有足够真实标注样本 | 不是首次使用的硬门槛；是宣称准确率、校准阈值或生产自动化的重要证据 |
| 错误可撤销或有后续保护 | 自动执行时接近硬门槛；只做建议时是强烈加分项 |
| 可建立独立测试集 | 生产化与长期评估的重要条件，不是每次临时判断的前置门槛 |
| 不要求模型生成解释 | 基本正确；JEV 负责类型化判断，不负责开放式写作。若决策必须有审计解释，应由证据层或主模型补充 |
| 不涉及不可逆高风险决定 | 应改为“JEV 不得成为不可逆高风险决定的唯一决策者”；`jev_gate` 可辅助风险检查，升级后仍由责任人裁决 |

推荐判断法不是计数，而是：

- **硬门槛**：事实可获得；问题可类型化；选项/等级定义清楚；状态可压缩；升级项有明确接手人。
- **价值增强**：高频重复、同状态多判断、需要结构化低成本分流、结果可撤销或有保护。
- **生产化条件**：真实标注样本、独立测试集、阈值校准、不可达回退、漂移监控和专业责任人。
