## 训练目标与路由

本次训练验证两件事：一是把“同一状态上的多个可枚举质量判断”合并为一次 `jev_judge`；二是在 JEV 不可用或脱离 JEV 时，仍用压缩状态、类型化问题、有限选项、批处理、阈值和升级规则保持判断效率与证据边界。

路由规则：上下文中已有事实走一次批量 `jev_judge`；只存在于文件或工具输出的批量条目应由脚本送入 `jev-use judge` CLI；单次高风险阻塞动作才用 `jev_gate`；每个工具调用重复受同类门禁时使用 PreToolUse Hook；新文字、测试代码和不可穷举方案仍由主模型生成。

## 真实批量 `jev_judge` 调用与升级处置

一次 MCP 调用提交了上述 9 个问题：A–F 六个分诊题、一个整体证据 `score`、G 的下一动作 `choice` 和 G 的终态 `noul`。参数为 `model=jev-latest`、`confidence_threshold=0.85`，同一合成状态只传一次。

真实返回摘要：

```json
{
  "backend": "unconfigured",
  "model": "jev-latest",
  "escalated": true,
  "verdict_count": 9,
  "common_result": {
    "answer": null,
    "confidence": 0,
    "escalate": true,
    "reason": "unreachable"
  },
  "failure": "No Jev credentials found"
}
```

处置：九题全部因为 `unreachable` 升级。`answer: null` 没有被解释为任何业务答案，`confidence: 0` 没有被用于放行；没有重试同一请求，也没有启用工具提示的 `JEV_BACKEND=mock`。因此，首轮证据只证明真实 MCP 请求已发出、批处理和失败控制流可观察，不证明 JEV 后端完成了任何质量判断。

## 恢复后的有效批量 `jev_judge`

JEV 后端恢复后，用同一 A–G 合成状态复跑，并在同一批次加入尚未预写答案的 H 迁移题，共 11 题。没有把首轮人工基线作为 JEV 的提示答案；状态只包含发布规则、合成事实和互斥选项。

```json
{
  "backend": "typesafe",
  "model": "jev-1.13.0",
  "latencyMs": 1054,
  "toolWallTimeSeconds": 11.7,
  "usage": {
    "inputTokens": 1994,
    "outputTokens": 607
  },
  "verdictCount": 11,
  "escalated": true
}
```

`latencyMs` 是 JEV 返回的模型延迟；11.7 秒是外层工具调用 wall time，两者口径不同，不相减或混用。有效 verdict 如下：

| --- | --- | --- | --- | --- |
| A | `BLOCK_RELEASE` | 0.98 / reported | false | 采纳 |
| B | `NON_BLOCKING_FIX` | 0.98 / reported | false | 采纳 |
| C | `HOLD_FOR_EVIDENCE` | 1.00 / reported | false | 采纳 |
| D | `HOLD_FOR_EVIDENCE` | 1.00 / reported | false | 采纳 |
| E | `BLOCK_RELEASE` | 0.97 / reported | false | 采纳 |
| F | `OUT_OF_SCOPE` | 0.98 / reported | false | 采纳 |

## 质疑、修订与 `unsure` 升级

顾清妍没有以高置信分数代替质量责任，逐项提出反证问题：低风险 B 是否有功能失败证据；C 的争议标签是否足以越过阈值；E 是否可以证明纯测试抖动；G 的回滚成功是否能补足终态；H 的开关是否能修复已覆盖数据。复核结果为：

- B 只有容差内视觉差异，关键行为已通过，维持 `NON_BLOCKING_FIX`。
- C 的 8 个争议标签可能改变 6%/5% 比较，不能升级成“已证实回归”，维持 `HOLD_FOR_EVIDENCE`。
- E 有同时间产品 trace 佐证，不能隔离测试，维持 `BLOCK_RELEASE`。
- A–F 的原始 `score=0.04` 不是离散索引 0 的字面值；报告保留 0.04，并仅在与人工等级对照时按分布主峰归入 0 级，避免把连续输出改写成整数 verdict。
- G 终态的 `answer=0.10` 只是“成功概率低”的先验，且 `confidence=0.80 < 0.85`、`reason=unsure`。人工升级后，根据“进程崩溃 + 未写终态审计标记”，最终判定仍为 `false`；该结论来源是人工复核，不是对 JEV unsure 的强行采纳。回滚成功只能证明恢复动作，不能证明业务终态成功。
- H 在调用前没有预设答案。人工反向质疑“40 次仅一次是否应隔离 chaos 测试”以及“开关是否足以带保护发布”；由于失败表现是可观测的破坏性覆盖、审计缺失且开关不能恢复已损数据，确认 `BLOCK_AND_INVESTIGATE`，数据完整性为 `false`。这完成了迁移题的作答—质疑—修订闭环；结论仅适用于合成案例。

本轮没有其他 `unsure`。若后续复跑出现 `unsure`，继续执行同样控制流：保留先验、禁止直接执行、交专业负责人复核并标注最终结论来源。

## 无 JEV 同题基线与迁移题

在与 JEV 结果严格分栏后，顾清妍按预先写入合成状态的发布规则完成无 JEV 基线；它只用于用户要求的同题对照，不回填、替代或冒充 JEV verdict。

| ID | 无 JEV 结论 | 证据边界 / 升级 |
| --- | --- | --- |
| A | `BLOCK_RELEASE` | 重复财务效果已在真实测试数据库链路复现；阻断并升级关键缺陷，回滚仍需演练 |
| B | `NON_BLOCKING_FIX` | 偏差在明确容差内且关键行为证据通过；记录为界面瑕疵，不外推为所有视觉均通过 |
| C | `HOLD_FOR_EVIDENCE` | disputed labels 会直接改变 6%/5% 比较；先裁决标签并重算，不能宣称已证实回归 |
| D | `HOLD_FOR_EVIDENCE` | 单元和 Mock 不能支撑真实消息代理、数据库或端到端生产就绪主张 |
| E | `BLOCK_RELEASE` | 失败与产品 trace 同时间相关，不能先隔离为测试抖动；阻断并做可靠性根因分析 |
| F | `OUT_OF_SCOPE` | 不影响可执行发布契约；可顺手修正，但不是发布门槛 |
| A–F 整体 | `score=0`：证据反对整体批准 | A 与 E 已构成阻断；单个低风险项不能平均掉关键路径风险 |
| G 迁移题 | `SECURITY_BLOCK` | 跨租户泄漏触发安全阻断与事件升级；保留已验证回滚，完成隔离根因和重测前不放行 |
| G 终态 | `false` | 审计终态缺失且进程崩溃；回滚成功不等于业务终态成功 |

手工基线不输出伪造的数值置信度；置信度记为 `unknown / 未计量`。A、E、G 依据预设关键风险规则强制升级，C、D 依据证据层级缺口进入等证据状态。迁移题证明规则能迁移到“租户隔离 + 终态证据”组合场景，但只属于合成案例推理，不证明生产提效。

## 脱离 JEV 的高效输入输出协议

1. **压缩状态**：只保留目标、已证实事实、环境/证据层级、风险门槛、候选动作和 unknown；长文件保留引用，由本地脚本先结构化，避免把全文搬进对话。
2. **类型化**：真假判断写成 `noul`，下一动作写成 `choice`，质量等级写成 `score`；需要生成文本、代码或无法穷举选项的任务另开生成阶段。
3. **枚举互斥选项**：每个 `choice` 预先定义互斥且可执行的标签；每个 `score` 从低到高写明等级；`noul` 同时定义 true/false 的验收含义。
4. **同状态一次批处理**：同一证据包上的全部问题一次作答，结果按稳定 ID 返回，禁止逐题重复加载背景。
5. **阈值前置**：低风险题可设置普通复核阈值；数据损失、财务重复、租户隔离、安全与未知终态采用硬门槛，不被平均分或多数票抵消。没有可校准置信接口时写 `unknown`，不编造小数。
6. **升级矩阵**：证据冲突 → 人工复核；证据层级不足 → `HOLD_FOR_EVIDENCE`；状态过大 → 重新压缩或按文件脚本处理；开放式问题 → 主模型；工具不可达 → 按任务规则停止或明确切换无 JEV 流程；高风险命中 → 专业负责人升级。
7. **只执行未升级项**：输出固定为 `id / type / answer / confidence-or-unknown / escalate / reason / next_action`；升级项不得沿用低置信先验，也不得被未升级项的数量覆盖。
8. **保留来源边界**：把 JEV verdict、主模型回退结论、测试原始证据和最终质量裁决分栏记录；构建、Mock、截图或回滚成功不得互相替代。

可复用批次模板：

```text
STATE: <最小充分事实 + 证据层级 + 风险硬门槛>
QUESTIONS:
- id=<id>; type=noul; true=<验收含义>; false=<验收含义>
- id=<id>; type=choice; options=<互斥动作>
- id=<id>; type=score; levels=<从低到高>
THRESHOLD: <普通阈值>; HARD_GATES: <数据/财务/隔离/安全/终态>
RESULTS: id / answer / confidence-or-unknown / escalate / reason
ACTION: 只执行未升级项；升级项交专业负责人或停止。
```
