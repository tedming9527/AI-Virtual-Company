## 一、路由理解

| 判断来源与阻塞方式 | 应用通道 | 产品岗位示例 | 边界 |
| --- | --- | --- | --- |
| 事实已在当前上下文，且有多个可枚举判断 | `jev_judge`，同一状态一次批量 | 是否满足试点门槛、下一动作、证据等级 | 只交付判断，不让 JEV 写 PRD、研究提纲或新方案 |
| 条目只在文件或工具输出中 | 脚本把文件直接交给 `jev-use judge` CLI | 大批反馈标签、实验日志逐条分级 | 不为了调用 JEV 把整份文件读入主对话 |
| 单个高风险或不可逆动作阻塞后续执行 | `jev_gate` | 是否允许按现有证据启动一次全量发布 | 只门禁一个拟执行动作；最终责任仍由主模型与负责人承担 |
| 每个工具调用都要经过同类安全判断 | `jev-use hook gate` PreToolUse Hook | 连续执行一组发布命令的重复门禁 | 一次接入重复使用，不逐命令手调 `jev_gate` |
| 需要生成新文字、开放式探索或选项无法穷举 | 主模型 | 定义用户问题、提出候选策略、撰写 PRD | 不把生成任务伪装成 `choice` |

产品岗位最适合交给 JEV 的不是“决定产品战略”，而是已经完成问题定义后，对同一事实状态执行快速、类型化的门槛判断。问题定义、选项生成、权衡解释和最终签字仍属于负责人。

## 二、首次真实批量调用：BriefPilot 试点（恢复前）

### 2.1 合成状态

BriefPilot 把会议纪要转为可确认行动项。决策动作固定为 `scale / continue_pilot / pause_fix / stop`，规则如下：

- `scale`：7 日已验证行动完成率相对基线提升至少 5 个百分点；人群可比；数据完整率至少 98%；严重错误率不高于 2%；隐私事件为 0；单任务成本不高于 0.20 元。
- `pause_fix`：隐私事件大于 0，或主指标数据完整率低于 95%。
- `stop`：未触发暂停条件，且提升低于 2 个百分点或成本高于 0.25 元。
- 其余情况：`continue_pilot`。

事实为：基线组与实验组各 120 人；完成率 34%→42%；实验组高频用户占 60%，基线组占 30%，未校正；完整率 99%；严重错误率 1.8%；隐私事件 0；单任务成本 0.18 元。反馈项包括撤销可发现性、标题截断、PII 扫描覆盖不足和深色模式图标错位。

### 2.2 调用形态

一次 `jev_judge` 调用提交 6 个问题，而不是逐题调用：

- 2 个 `noul`：是否满足放量条件、能否支持因果归因；
- 2 个 `choice`：下一动作、反馈优先级；
- 2 个 `score`：证据等级、放量准备度。

参数：`model=jev-latest`，`confidence_threshold=0.92`。工具记录的 wall time 为 **10.5 秒**。

### 2.3 真实返回与升级处理

6 个问题共同返回：

```json
{
  "answer": null,
  "confidence": 0,
  "escalate": true,
  "reason": "unreachable",
  "backend": "unconfigured",
  "model": "jev-latest"
}
```

后端错误明确为未发现可用 JEV 凭据。处置如下：

1. 没有把 `null` 解释成否定答案，也没有沿用零置信度答案。
2. `escalate: true` 改变了控制流：JEV 判断步骤停止，结果不得进入产品动作。
3. 未启用返回提示中的 `JEV_BACKEND=mock`，因为 dry run 不能替代真实 JEV verdict。
4. 未切换到其他模型冒充 JEV，也未修改凭据或扩大权限。
5. 主模型只做明确标注的“无 JEV 对照”，不回填为 JEV 成果。

## 三、无 JEV 对照、质疑与修订

相同状态由主模型按显式规则独立判断；这部分仅用于比较，不是 JEV verdict。

| 问题 | 无 JEV 答案 | 依据 / 边界 |
| --- | --- | --- |
| 是否满足全部 `scale` 条件 | `false` | 高频用户比例 60% vs 30%，人群可比性不成立 |
| 下一动作 | `continue_pilot` | 未触发暂停或停止，且放量条件不全；落入兜底规则 |
| 提升能否归因为功能 | `false` | 明显人群混杂未校正 |
| 证据等级 | 1：方向性 | 指标与护栏较完整，但归因有关键混杂 |
| 最优先反馈 | `F3` 仅作风险假设，`escalate=true` | 可能影响隐私护栏，但题目没有严重度、发生概率、暴露面和可检测性，不能稳定定优先级 |
| 放量准备度 | 1：仅可继续小试点 | 可继续收集证据，不支持放量 |

### 3.1 对答案的质疑

反馈优先级题虽然列出了有限选项，但状态没有提供统一决策准则。直接选择 F3 容易把“隐私相关”机械等同于“最高优先级”，这不等于证据充分。JEV 即使返回高置信度，也不能补足缺失事实。

### 3.2 修订

后续批次应先补充四项字段再做 `choice`：

- 用户/业务影响等级；
- 发生概率或样本频次；
- 影响范围与可逆性；
- 是否触发既定硬护栏。

若任一候选项可能触发硬护栏但事实未知，应把该题升级为“先核实哪项事实”，而不是强选修复顺序。修订改变的是状态质量和问题结构，不是要求 JEV 生成新的优先级方法。

该答案没有写回 JEV 结果，也不证明 JEV 会给出相同结论。迁移题只验证了问题结构可复用和失败控制流；没有验证正常 JEV 判断质量。

## 五、首次有 JEV / 无 JEV 对照（恢复前）

| 维度 | 使用 JEV（本次实测） | 不使用 JEV（本次对照） | 结论 |
| --- | --- | --- | --- |
| 可测耗时 | 两次 MCP wall time：10.5 秒、9.4 秒；均为失败路径 | 当前平台没有提供单段主模型判断的独立 wall-time | 无 JEV 耗时为 `unknown`；不能用失败耗时代表正常 JEV 延迟 |
| 主对话上下文 | 调用参数和重复错误返回进入上下文；token 数不可测 | 状态与判断均留在主模型上下文；token 数不可测 | 本次失败路径没有上下文优势；文件批量数据仍应走 CLI |
| 输出一致性 | 没有有效答案 | 两个案例均有人工规则答案 | `unknown`，没有可比的 JEV verdict |
| 升级处理 | 10/10 题均 `unreachable`，必须停止或明确回退 | 主模型可接手，但必须标注来源 | `escalate` 是控制流信号，不是附注 |
| 输出结构 | 请求已统一为 `noul / choice / score`，但无有效返回 | 通过同一结构可稳定产出可审查答案 | 类型化结构即使脱离 JEV 仍有价值 |
| 适用边界 | 可枚举、状态充分、低延迟判断；实际效率待真实后端复测 | 负责状态建模、开放式生成、缺事实补问与最终责任判断 | JEV 不替代产品判断与授权 |

理论上，有效 JEV 模式的优势应来自：把同一状态的多个类型化判断一次批处理、让判断离开主模型推理链、用统一 confidence / escalate 处理不确定性。本次仅验证了调用接口和失败语义，未验证这些优势在当前环境成立。

## 六、脱离 JEV 后的高效替代协议（2026-09-24 审计修复：引用阈值以 batch_id 定位——首次 0.92 / 恢复 0.70，不沿用全文最后出现值）

当任务允许回退而 JEV 不可用时，按下面的 `JEV-like` 协议运行；若任务规定“JEV 不可用即停止”，则只记录升级，不执行第 7 步。

1. **压缩状态**：只保留目标、已证实事实、硬护栏、未知项、候选动作和停止条件；叙事背景移除。文件型大数据只保留引用或先在脚本侧摘要。
2. **类型化**：判断只能进入三类：`noul`（真假）、`choice`（互斥有限选项）、`score`（有序等级）。需要新文字或选项不可枚举时直接交给主模型生成。
3. **写清语义**：`noul` 同时定义 true/false；`choice` 的标签必须互斥且可执行；`score` 从低到高写明每一级的观察条件。
4. **一次批处理**：同一状态上的问题组装成一个批次，禁止为每个问题重复加载背景。
5. **固定阈值**：批次开始前设置阈值。本训练使用 0.92，是为了让不确定题主动升级，不代表公司统一阈值。主模型无校准置信接口时写 `confidence=unknown`，不得编造小数。
6. **升级条件**：证据冲突、关键事实未知、问题开放、状态过大、选项不完备、工具不可达或高风险不可逆时，标记 `escalate=true` 和原因。
7. **只执行未升级项**：升级项回到主模型复核、补证据或停止；不得沿用低置信答案。最终动作仍核对授权和产品护栏。
8. **保留最小回执**：只记录 `id / type / answer / confidence或unknown / escalate / reason / action`，避免把整段推理复制到每题。

可复用模板：

```text
STATE: <最小充分事实、规则、unknown>
THRESHOLD: <预设阈值或 unknown>
QUESTIONS:
- id=<id>; type=noul; true=<含义>; false=<含义>
- id=<id>; type=choice; options=<互斥可执行选项>
- id=<id>; type=score; levels=<从低到高等级>
RESULTS:
- id=<id>; answer=<答案或null>; confidence=<值或unknown>;
  escalate=<true|false>; reason=<原因>; action=<采纳|补证据|停止>
```

## 十、质疑与修订结果

首次版本要求在 F1–F4 中选择最高优先级，却没有影响、概率、范围、可逆性或硬护栏规则。无 JEV 基线虽然把 F3 当作风险假设，但必须升级，否则只是把“隐私相关”机械等同于最高优先级。

恢复批次补充可审计选择规则和影响范围后，JEV 返回 `F3`，置信度 0.95、无升级；与按同一规则的无 JEV 基线一致。由此确认：

- 有限选项不等于状态充分，`choice` 还需要统一的选择规则；
- JEV 不能补足缺失事实，硬护栏未知时应升级或先补事实；
- 状态修订减少了优先级题的不确定性，但没有把答案预写进状态。

证据等级题仍为 `unsure`，说明“方向性”和“可继续试点”在语义上可能重叠。下次应把等级改成互斥硬条件：等级 1 明确为“存在未校正关键混杂”；等级 2 明确为“无关键混杂但尚缺放量证据”。

`m3_evidence` 同样按 `unsure` 升级。未校正的紧急工单占比差异是明确关键混杂，因此最终等级为 1。迁移题的三个未升级 verdict 与无 JEV 基线一致，升级题经复核后也与基线一致；这验证了判断结构的可迁移性，但不证明生产效果。
