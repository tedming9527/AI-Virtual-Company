## 经验单元 1：异步交互先做“请求归属”，再谈结果

- 触发信号：
  - 搜索/筛选、分页、重复提交、接口返回乱序或页面快速切状态。
  - 看到“加载中”“失败”“重试”频繁出现，且用户反馈出现内容闪烁或旧数据回写。
- 状态/责任边界：
  - 前端侧负责客户端可见数据一致性（行级/视图状态与 loading/error）与用户可恢复性。
  - 后端幂等、权限、最终一致性责任在后端工程师；前端“取消请求”不等于服务端幂等已满足。
- 决策规则：
  - 每次请求记录归属标识（如序号/关键词快照），新请求到来时先更新“当前生效版本”。
  - 回包到达后仅在归属匹配时更新视图，不匹配则丢弃，避免旧响应覆盖新视图。
  - 重试仅在保持当前上下文（如关键词、过滤条件）时执行。
- 证据：
  - `employees/frontend-expert/MEMORY.md`：`frontend-expert-core` 条目提到“搜索/筛选/重复提交场景的请求归属与旧响应防污染”。
  - `employees/frontend-expert/KNOWLEDGE.md`：异步竞态条目明确注明“取消请求不独自保证正确”。
  - `learning/2026-09-13-vanke-frontend-code-distillation.md`：选择性蒸馏中强调“旧请求失败不污染 rows/loading/error”。
- 反例/失效条件：
  - 反例：仅用按钮禁用替代归属校验，导致用户改条件后旧响应覆写新列表。
  - 失效条件：请求被取消后直接提示“成功”，或未检验关键词快照即复用旧数据。

## 经验单元 2：复杂页面状态采用三层验收，而不是全量 jsdom 覆盖

- 触发信号：
  - 页面包含 loading/empty/error/权限/活动态/异常态组合多，且视觉在快速迭代中变化频繁。
  - 团队发现单纯加 DOM 或 class 断言测试维护成本上升但收益下降。
- 状态/责任边界：
  - 体验侧负责状态覆盖的人工可视化探索（Debug 浮板）与关键视觉契约。
  - 逻辑稳定性（字段映射、入口决策、请求参数）由单测验证；关键链路（授权、支付、订单、防重复提交）才保留端到端覆盖。
  - 生产默认关闭 debug，仅受控环境展示状态工装。
- 决策规则：
  - 默认开启“Debug 浮板 + 稳定逻辑单测 + 关键路径端到端”三层。
  - 对频繁变更、纯视觉断言或可变 DOM 结构采用人工状态切换复核，不作为主回归。
- 证据：
  - `employees/frontend-expert/PAGE_STATE_VALIDATION.md`：明确三层策略与“debug=1”状态浮板入口实践。
  - `employees/frontend-expert/MEMORY.md`：同条目将该规则定义为 `reviewed_case` 并记录生产提效待验证。
  - `employees/frontend-expert/PAGE_STATE_VALIDATION.md`：列出浮板与关键旅程测试边界，尤其说明支付/领取等副作用必须禁用真实提交。
- 反例/失效条件：
  - 反例：以“有测试文件即可”替代真实视口和状态组合复核，结果在小屏/动态布局下漏检。
  - 失效条件：将测试断言下沉到可变 class 名称或迁移性差的结构级别。
