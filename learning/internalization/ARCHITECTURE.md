# 学习经验内化架构 v1

## 目标

把岗位已有经验从“记住一个答案”转成可迁移的决策单元。每个单元必须说明何时触发、看什么信号、为何这样决定、如何行动、用什么证据验收、何时不能套用，并通过一个未预先给答案的新场景。

本目录是训练运行层，不替代 `employees/<role>/KNOWLEDGE.md`、公司政策或项目事实源。只有经过岗位复核、反例检查和迁移验收的结论，才可按知识维护政策另行发布。

## 四方对话单元

每名员工使用三个同岗位分身，避免单一路径自我确认：

1. `experience_miner`：从现有证据还原触发、信号、隐性判断和有效动作。
2. `boundary_challenger`：寻找反例、失效条件、权限边界和证据缺口。
3. `transfer_architect`：抽象不变量与变化轴，设计未见迁移题。
4. `business_stakeholder`：由相关业务岗位提出目标、成本、数据或交付约束，不能由三个分身替业务事实作答。

主责只做冲突整合：保留不同意见，证据不足写 `unknown`，不以多数表决代替事实或用户授权。

## 经验单元

每岗最终形成一个 `experience_unit`：

`trigger → signals → decision → action → evidence → limits → counterexample → transfer_test`

- `trigger`：什么情境应召回该经验。
- `signals`：决定前必须取得的事实；缺失项不能用猜测补零。
- `decision`：可复用的不变量，不绑定某个单一案例名。
- `action`：最小可执行步骤。
- `evidence`：来源路径和证据级别；`reviewed_case`、`verified_context`、`unknown` 分开。
- `limits`：环境、权限、版本和外推边界。
- `counterexample`：至少一个看似相似但不应套用的场景。
- `transfer_test`：改变至少两个变化轴的新题，并记录作答、质疑、修订与结果。

## 状态机与发布门禁

```text
registered
  -> elicited
  -> challenged
  -> abstracted
  -> transfer_tested
  -> cross_checked
  -> candidate
  -> published
```

- 任一阶段发现证据冲突，可回到 `elicited`；连续两轮没有新增证据则停止为 `held`。
- `transfer_tested` 只表示本轮迁移题已完成；桌面案例最多支持 `reviewed_case`。
- `published` 必须另按 `KNOWLEDGE_MAINTENANCE.md` 同步详情、摘要、catalog 与 hash；本架构不会自动发布。
- 外部操作、生产验证、权限提升与长期政策修改不由会议状态授权。

## 异步并行拓扑

调度器按环境并发上限建立批次：一个监督者持续跟踪共享 Spark 窗口、员工任务状态与停止门禁，其余槽由显式指定 `gpt-5.3-codex-spark` 的员工分身异步并行。某一批完成或需要关注时，监督者为下一名员工补位。同一批中分身只读最小充分上下文，独立产出后进入交换阶段；不同岗位保持并行，涉及同一共享文件的写入才由监督者串行集成。

用户未写“最多、上限、不超过”时，每岗 10% 解释为等额任务目标，八岗由监督者按共享窗口聚合监督到 80%；用户明确写上限词时才解释为上限。建议任务设计为：资料定位 1%、三分身独立提取 5%、交叉对话与迁移题 3%、压缩与候选登记 1%。共享窗口不能精确归属个人，不能伪造八份个人用量；但实际 Spark 模型、前后快照和正增量缺一项时，整轮不得标记完成。问题解决、连续两次无新增证据或达到停止缓冲时可提前结束，并将未达目标记为 `partial`，不为追求显示值精确相等制造无效输出。

## 数据与文件

- `runs/<date>-<name>.json`：机器可检验的本轮结构化结论。
- `runs/<date>-<name>.md`：给人审阅的整合记录、分歧和边界。
- `scripts/check-internalization-run.mjs`：检查花名册覆盖、分身角色、对话、迁移题、证据级别和预算声明。
- 岗位 `MEMORY.md` / `KNOWLEDGE.md`：只有完成发布门禁后才更新，不从运行文件自动覆盖。

## 验收与举一反三

结构检查只能证明字段和覆盖完整。真正的“举一反三”至少要求：

1. 迁移题没有出现在原经验证据中，并改变两个以上变化轴；
2. 员工先独立作答，相关岗位再质疑，最后保留修订痕迹；
3. 答案能指出何处沿用不变量、何处因新信号改变决策；
4. 一个反例明确判定为“不应套用”；
5. 后续真实任务另记录采用/拒绝、返工和遗漏，不能由一次会议宣称长期能力提升。
