## 一、审计口径与独立性

本次只审计“经验是否形成、证据是否支持、边界是否准确、是否正确落盘”，不把研究报告数量、回答流畅度、结构评分、模型消耗或自报点数当成能力提升证据。研究/判断成熟度、真实项目独立交付、生产效果三层分别裁决。

三组只读审查使用不继承原作者讨论的新上下文（`fork_turns=none`）：`/root/audit_roles_a`、`/root/audit_roles_b`、`/root/audit_roles_c`。任务请求为 `gpt-5.6-sol / high / deep`，但当前协作通道未返回可独立核验的实际模型身份，因此实际模型记为 `unknown`；不以请求参数冒充模型回执。

主要证据：

- [第一轮综合报告](../professional-capability-research-2026-09-18/REPORT.md)及八份岗位报告；
- [第二轮综合报告](../professional-capability-deep-research-2026-09-18/REPORT.md)、[质量复核](../professional-capability-deep-research-2026-09-18/quality-review.md)与[测试岗独立复核](../professional-capability-deep-research-2026-09-18/test-expert-review.md)；
- 八岗 MEMORY、第一轮新知识详情及[公司共用证据账本](../../knowledge/verifiable-work-evidence-ledger.md)。

## 二、总体裁决

1. **八人均形成了可定位的研究/专业判断增量。** 增量表现为更精确的状态边界、反例、竞争假设、迁移题和真实验证协议，可按 `reviewed_case` 或候选研究成果使用。
2. **八人均没有证据证明真实项目独立交付能力已经提升。** 缺少可比前后基线、用户/业务真实任务中的独立执行轨迹、相称环境终态和连续效果数据。
3. **此前任何数值化“提升了多少分”都不能作为审计结论。** 当前没有统一量表、盲测基线、重复测量和评分者一致性；本报告只接受方向性、证据分层后的结论。
4. **第一轮八份经验允许保持 `reviewed_case`；第二轮结论继续留在 `learning/` 候选层。** 本次重复审阅不构成状态升级证据。
5. **生产能力、发布准确率、长期返工下降和市场薪资上调均未验证。** 后续须由真实任务产生新证据，不能从本次审计通过反推。

## 四、审计发现与本轮修正

### A-01 · 新知识缺少显式置信度

- 影响：六份详情及相关发现条目虽有状态和边界，但不完全满足记忆政策对置信度元数据的要求。
- 处置：为陈知行、陆行远、苏映雪、顾清妍、辛澈、沈砚舟的详情补充 `medium` 及其证据上限；八岗新 MEMORY 条目均补充置信度说明。
- 边界：只补元数据，没有把任何条目升级为生产能力。

### A-02 · 前端旧候选的“真实迁移”措辞与任务状态冲突

- 影响：`actual_executor: not_started` 与 `status: verified` 冲突时，原条目仍称“一次真实页面迁移”，可能导致后续错误复用。
- 处置：将该条置信度降为 `low`，明确它只能支持候选检查清单；未补原始提交、执行回执、测试与浏览器证据前不得称迁移完成。同步更新 MEMORY、catalog 摘要边界和正文 hash。
- 边界：未否定其架构检查清单的候选价值，也未补造缺失的运行证据。

修正后 `scripts/check-company-bootstrap.sh`、全量 `scripts/check-knowledge.mjs` 与 `git diff --check` 均通过；结构通过不替代上述语义结论。

## 五、后续真实任务门槛

未来每岗至少记录三个满足同一准入条件的可比真实任务，分开保留：独立完成与提示程度、首次验收缺口、返工原因、真实环境终态、escaped defects、人工介入和知识复用结果。只有新增证据方向一致，才讨论稳定能力或返工改善；市场价值变化另按用户能力评估协议，在岗位、地区、时间和薪酬口径明确时评估。
